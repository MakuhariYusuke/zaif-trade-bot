# v459 追加レビューと考察 (01)

## 1. 大義と成功基準のズレ
- 「短期間で高収益」を掲げる一方で、成功基準が `PF > 1.05` / `Sharpe > 0.5` / `ROI > 0%` と緩く、短期の高収益と整合しない。現状の基準は「動作確認」レベルであり、Go/No-Goの判断軸として弱い。
- 収益性の定義が曖昧。年率換算、最大DD、回転率、取引コスト込みの期待値などの明文化が必要。
- v451の成功条件を引用しているが、市場環境や実行モデルが違えば再現性は低い。成功条件を「再利用」ではなく「再検証」扱いにすべき。

## 2. 評価設計の穴（統計と漏洩の観点）
- Walk-Forwardは「動作完了」だけでなく、分割・スケーリング・特徴生成の時系列因果性を保証する明確な手順が不足。特にスケーラのfit範囲とリーク検査基準が記載されていない。
- Multi-Seed比較は必要条件だが十分条件ではない。複数seed + 複数分割（期間違い）の組み合わせがないと、局所的な運の良さを見抜けない。
- AB Testingが「Entry Gate ON/OFF」だけだと因果の切り分けが弱い。少なくとも「報酬設計」「コストモデル」「実行モデル」まで含めた分解検証が必要。
- Buy-and-Hold/SMAはベースラインとして弱い。手数料込みでの単純モメンタム/リバージョン、ボラティリティターゲット、ランダムアクションなど最低限の比較軸を追加すべき。

## 3. 実装計画の現実性
- Phase 1-2が合計3-5日でバグ修正・統合・AB有効化・Reporter統合まで完了する想定は楽観的。バグ修正の影響範囲が広く、テストと再学習の工数が見積もられていない。
- 「No New Features」を掲げる一方で、Paper Trading統合やVPM統合などは実質的に新規結合作業に近い。凍結対象と改善対象の境界が曖昧。
- Entry GateやReporterの統合は複数ファイルに影響するため、事前に仕様（I/O・指標定義・ログ粒度）を固定しないと再修正が連鎖する。

## 4. 収益性とリスク管理のギャップ
- Circuit Breaker / VPMがある一方で、トレード頻度・保有時間・スリッページ耐性の制約が明示されていない。高回転型なら実行コストが勝敗を決める。
- 「高収益」を狙うほどリスクが尖るが、最大DD、日次損失上限、連敗時の縮退規則などの具体値が未定。
- Profit Factorが低い状態で「勝率30%」を許容すると、実行コストで逆転される危険が高い。

## 5. 報酬設計の不確実性
- 「PnL-Centered + Trend Guidance (Decay)」としつつ、v451の「シンプル報酬回帰」と両立していない。報酬の主従関係とスケーリングを先に固定すべき。
- これまでの問題（コスト二重計上、統計の混在）から見て、まずは「純粋PnLのみ」の固定版でベンチマークを取り、ガイダンスは段階導入にした方が安全。

## 6. データ品質・実行モデルの不足
- タイムゾーン、欠損補間、スプレッド、約定遅延などの条件が未定義。ここが曖昧なままだとバックテスト優位に寄る。
- Paper Tradingの評価基準が「安定動作」だけだと、戦略品質の判断材料にならない。スリッページ/約定率/遅延の実測ログが必要。

## 7. 結論としての懸念点
- 現状の計画は「安定化の最終章」と位置づけるには評価設計・運用条件の詰めが甘い。
- 目標が高い割に検証基準が低く、Go/No-Goが形式的になりやすい。
- 既存資産の統合に対して仕様固定・再現性・計測設計が追いついていない。

## 8. 推奨アクション（優先順）
1. 成功基準を「収益性・リスク・実行コスト」込みで再定義（PF/Sharpe/MaxDD/Turnover/Cost）。
2. Walk-Forwardの因果性検証（スケーラfit範囲、特徴生成のリーク検査手順）を明文化。
3. 報酬設計を段階化（純PnL → Trend Guidance追加）し、A/B比較の軸を増やす。
4. Paper Tradingの実行モデル定義（スリッページ、遅延、約定率）を先に確定。
5. フェーズごとの「完了条件」と「実測ログ」をセットで定義。

## 9. 率直な所感
- 「実運用可能な高収益」へ向かう意思は明確だが、成功定義と検証の精度が足りない。このまま進むと「動いたが勝てない」状態で収束する可能性が高い。
- 本当に勝ちに行くなら、評価設計と実行コストの定量化を最初に固定し、その枠内での改善に集中するのが最短。
