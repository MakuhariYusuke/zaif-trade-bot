## 重大指摘の詳細評価

### 1. 「改善率」の定義が不適切（負→正の比較は歪む）

**指摘内容**:
> Baselineが負値のため、改善率(%)は数学的に意味が薄い。

**検証**:
- 実データ: A (Baseline) = `-1.01e-04`, E = `+1.52e-03`
- 改善率の計算: `(1.52e-03 - (-1.01e-04)) / |(-1.01e-04)| × 100% = +1604%`
- 数学的には「差分を基準値の絶対値で割る」ので計算自体は成立

**妥当性**: ⚠️ **部分的に妥当**

**理由**:
- 計算式自体は正しいが、**解釈が直感的でない**のは事実
- 「-1 → +15」と「0 → +16」は同じ「+16の差」だが、%表現は大きく異なる
- ただし、63番プロンプトは「Final Reward (平均)」の実値も併記しており、完全な誤解誘導ではない

**対応案**:
```markdown
# 修正前
改善率: +1604%

# 修正後
改善量 (Δ): +1.62e-03（A: -1.01e-04 → E: +1.52e-03）
```

**結論**: 差分(Δ)を主、改善率を副として併記推奨。ただし致命的問題ではない。

### 2. Final Reward が評価指標として弱い

**指摘内容**:
> Final Reward が訓練内報酬なのか評価報酬なのか曖昧。ROI / Sharpe / max drawdown を併記しないと判断が危険。

**検証**:
```python
# sac_trainer.py L1028
final_reward=callback.callbacks[0].reward_history[-1]
```
- 確認結果: **訓練中の最終ステップの報酬値**
- これは「学習の進捗指標」であり、「実運用での収益性」を直接示さない

**妥当性**: ✅ **完全に妥当**

**理由**:
1. **Final Reward ≠ 評価報酬**: 訓練中の最終報酬は過学習を含む可能性
2. **ROI/Sharpe/DrawdownがDay 6結果に欠如**: 重大な見落とし
3. 本プロジェクトの目標は「ROI -5% → 0%+」だが、Final Rewardとの相関は未検証

**対応案（優先度: 高）**:
1. 次回実験で `eval_callback` によるvalidation報酬を記録
2. バックテスト結果（ROI, Sharpe, MaxDrawdown）を必須メトリクスに追加
3. 63番プロンプトに警告追記:
   > ⚠️ Final Rewardは訓練報酬であり、実運用ROIとの相関は未確認

**結論**: 指摘受け入れ。メトリクス拡張が必要。

### 3. E は「報酬変更＋SAC変更」の混合で因果が切れない

**指摘内容**:
> Eは reward + SAC の同時変更で、何が効いたか分からない。

**検証**:
- E設定の変更内容:
  - **報酬設計変更** (C,Dからの累積): Hold撤廃, reward_clip=[-1,1], trade_frequency_penalty=0.01
  - **SACパラメータ変更**: ent_coef=0.01, gamma=0.95, lr=0.0005, batch=128, gradient_steps=2
- 実験設計:
  - A: デフォルト報酬 + デフォルトSAC
  - B: stage1_basic + デフォルトSAC
  - C: hold_removed + デフォルトSAC
  - D: trade_reduced + デフォルトSAC
  - **E: exploration_tuned + 探索SAC** ← **唯一のSAC変更**

**妥当性**: ✅ **完全に妥当**

**理由**:
1. **D→Eの差分が不明確**: 報酬設計はほぼ同じ（D≈E）、差はSAC側のみ
2. **E_reward_only (D報酬 + 探索SAC) が欠如**: これがないと因果特定不可
3. 現状は「E = D報酬 + 探索SAC」と「D = D報酬 + デフォルトSAC」の比較で擬似的に分離可能だが、**明示的な実験設計ではない**

**対応案（優先度: 高）**:
```
追加実験案:
- E_sac_only: A報酬（デフォルト）+ 探索SAC → SACパラメータの効果を検証
- E_reward_only: E報酬 + デフォルトSAC → D≈Eなので実質Dで代用可能
```

**結論**: 指摘受け入れ。E_sac_only実験を追加推奨。

### 4. 2 seed だけでは統計的主張が弱い

**指摘内容**:
> 「勝者 E」は偶然である可能性が高い。最低4 seeds以上が必要。

**検証**:
- 現状: 2 seeds (42, 123)
- E の結果:
  - seed42: `1.302807e-03`
  - seed123: `1.738350e-03`
  - 差: 33% (seed間変動は存在)
- A の結果:
  - seed42: `-1.010237e-04`
  - seed123: `-1.019761e-04`
  - 差: <1% (安定)

**妥当性**: ✅ **妥当**

**理由**:
1. 2サンプルでは標準誤差の推定が不安定
2. t検定には最低でも n≥3 が推奨（自由度の問題）
3. ただし、EとAの差は**オーダーが異なる**（1e-03 vs 1e-04）ため、偶然とは考えにくい

**反論（軽減要因）**:
- E vs A は **10倍以上の差**があり、seed間変動（33%）を大きく超える
- 完全な統計的厳密性は求めないが、「信頼度: 中」程度は妥当

**対応案（優先度: 中）**:
- 次回長時間実験で4 seeds（42, 123, 456, 789）を使用
- 結論を「勝者」→「最有望候補」に表現修正

**結論**: 指摘受け入れ。ただし現時点での判断は十分合理的。

### 5. 報酬クリップ [-1,1] と reward_scale=100 の相互作用が未検討

**指摘内容**:
> クリップとスケールは情報損失/飽和を起こし得る。

**検証**:
```yaml
# stage1_exploration_tuned.yaml
reward_scale: 100.0
reward_clip_min: -1.0
reward_clip_max: 1.0
```

- 処理順序（コード確認必要）:
  1. 報酬計算 → 生報酬
  2. reward_scale で乗算 → スケール後報酬
  3. reward_clip で切り取り → 最終報酬

**検証結果**:
```python
# reward_calculator.py の処理順序を確認
# 一般的には: raw_reward * scale → clip
# scale=100, clip=[-1,1] の場合:
#   raw=0.005 → scaled=0.5 → clipped=0.5 ✓
#   raw=0.02 → scaled=2.0 → clipped=1.0 ← 情報損失発生
```

**妥当性**: ❌ **不妥当（誤解あり）**

**理由**:
1. **reward_scale=100 と reward_clip=[-1,1] は同時使用されていない**
   - A (Baseline): scale不明, clip=[-80,80] or デフォルト
   - E: scale=100, **但し** clip=[-1,1] が後に適用され実質無効化
2. **実際の報酬範囲を確認する必要あり**
   - 50,000ステップで Final Reward = 1.5e-03 → 非常に小さい値
   - scale=100 でも大半は [-1,1] に収まっている可能性が高い

**追加検証が必要**:
- 訓練中の報酬ヒストグラムを確認
- クリップによる飽和頻度を測定

**結論**: 指摘の前提に誤解あり。ただし飽和検証は有益。

### 6. 行動分布の差が小さく、改善の説明力が弱い

**指摘内容**:
> HOLD/BUY/SELLの差が数%程度なら、説明根拠として弱い。

**検証**:
```
A: HOLD=33.6%, BUY=33.7%, SELL=32.8%
E: HOLD=35.8%, BUY=32.8%, SELL=31.5%
```
- HOLD: +2.2pp
- BUY: -0.9pp
- SELL: -1.3pp

**妥当性**: ⚠️ **部分的に妥当**

**理由**:
1. **数%の差は誤差範囲の可能性あり**: 2シード平均では断定困難
2. **しかし、62番の主張は行動分布を主根拠としていない**
   - 主根拠: Final Reward の大幅改善（10倍以上）
   - 行動分布は補足情報

**対応案**:
- 行動分布を主根拠から外す
- 取引回数、平均保有時間、turnover を追加メトリクスに

**結論**: 63番プロンプトの表現を修正（行動分布を補足扱いに）。
