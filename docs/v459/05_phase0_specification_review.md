# v459 Phase 0 仕様固定レビュー (05)

対象: `04_phase0_specification.md`

## Verdict
Phase 0の仕様は「PnL規約」「Entry Gate」「スケーラ因果性」「実行モデル」を具体化できており、方向性は正しい。一方で、**ゲート仕様の安全性、統計・指標の定義精度、リーク検査方法**に重大な不足が残っている。現状のままだと「仕様通り実装したのに判定が不安定」になる可能性が高い。

## 良くなった点
- **PnL規約の統一（env=net / reporter=検証のみ）**が明確化され、二重計上の再発防止に繋がる。
- **Entry Gateの型定義**とConfig配線位置が固定され、過去の接続ミスが回避できる。
- **CausalOnlineScalerのfit範囲指定**が明文化され、因果性の線引きが明確になった。
- **実行モデルのパラメータ化**により、バックテストとPaper Tradingの差異管理がしやすくなった。

## 重大な欠陥（要修正）
1. **Entry Gateが「exit/close」までブロックする仕様になっている**
   - 仕様例では gate が `should_enter=false` の場合に action を強制HOLDへ変換。  
     これだと**損切り/クローズが拒否される可能性**がある。  
     ⇒ 「エントリーのみを制限、クローズ/リスク縮小は常に許可」を仕様として明文化すべき。
2. **Trade Type分類が不足**
   - `hold`が「無変化」と「同方向の増減」を区別できず、統計（Win Rate/Profit Factor）の歪みを招く。  
     ⇒ `long_add / long_reduce / short_add / short_reduce` を定義するか、`reverse`を「close + open」に分解する規約が必要。
3. **MTF因果性検査の方法が不適切**
   - `current_5m == future_5m` を違反判定に使う検査は、**リーク検出として無意味**で誤判定が多い。  
     ⇒ 「t時点までのデータで再計算した特徴」との一致検証に置き換える必要がある。

## 重要な未確定事項（精度リスク）
- **Sharpe/ROIの定義粒度**  
  日次リターン換算の方法（分足→日次の集計）と、risk-freeの扱いが未定義。
- **Profit Factorの0除算対策**  
  損失がゼロの場合の扱い（`inf` or `None`）を仕様で固定していない。
- **Gross ROIの定義精度**  
  `Net ROI + total_costs/initial` は正しいが、`total_costs`の算定対象（fee/slippage/price impact）を定義していない。
- **CausalOnlineScalerのゼロ分散対応**  
  `std=0` のときの除算ルールが未定義（NaN発生リスク）。
- **Configと実装の不整合**
  - `execution_model.slippage_model` が仕様にあるが、CostModel例では利用されていない。
  - `assert`での設定検証は最適化で無効化されるため、例外型での検証に統一する方が安全。

## ドキュメント内の整合性
- チェックリストで「Entry Gate I/F仕様書」や「スケーラfit規則書」が未チェックだが、本文では既に定義済み。  
  ⇒ **仕様書の完了基準（文書化完了 vs 実装完了）を分離**して明示した方が良い。

## 推奨アクション（優先順）
1. Entry Gateは**新規エントリーのみ制限**と明記し、exit/closeは必ず許可する。
2. Trade Typeの分類仕様を再定義し、**増減/反転の扱い**を明文化する。
3. MTF因果性検査は**再計算一致テスト**に置き換える。
4. Sharpe/ROI/Profit Factorの計算粒度と例外処理を固定する。
5. チェックリストの「仕様完成」と「コード完成」を分離して管理する。

## 所感
Phase 0は「仕様固定」という目的にかなり近づいたが、**Exit制限の安全性と指標の厳密性**が未完成。ここを詰めない限り、後工程で統計の再修正が起きやすい。ここでの確定が最終品質を左右する局面。
