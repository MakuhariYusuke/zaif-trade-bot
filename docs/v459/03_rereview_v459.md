# v459 再レビュー結果 (03)

対象: `00_project_proposal_v459.md`, `02_evaluation_design_and_causality.md`

## Verdict
Doc01の指摘に対する反映は大幅に前進しています。特に成功基準の厳格化と評価設計の明文化は効果的。ただし、**評価基準の整合性・統計検定の妥当性・ベースライン比較条件の公平性**にまだズレがあり、現状のままだと「判定は通るが説得力が弱い」状態になり得ます。

## 良くなった点（強化ポイント）
- **成功基準の厳格化**とGo/No-GoのGate分離は適切。数値基準と運用条件が明文化された。
- **Phase 0の仕様固定**が追加され、実装前に仕様を固める流れができた。
- **報酬設計の段階化**により、PnLベースライン→ガイダンス追加の因果が検証可能になった。
- **評価設計ドキュメント(02)**で因果性・リーク検査・実行モデルが体系化された。

## 重大な不整合（要修正）
1. **成功基準の不一致**
   - Doc00では「Momentumは参考」、Doc02では「Momentumも必須合格」となっており判定基準が矛盾。
   - Doc00のGate 2基準とDoc02の「中央値ROI/最悪ケース/成功率」の基準が二重で、**どちらが最終判定か不明**。
2. **統計検定の不備**
   - Doc00で「統計的有意差検定」を要求しているが、**方法・有意水準・多重比較補正の規定がない**。
3. **運の良さ検出ロジックの妥当性**
   - Doc02の`detect_luck`で「対角線のみ高性能＝過学習」はseed×split行列の構造上意味が薄い。
   - `std/mean` は平均がゼロ近傍の場合に不安定で、**誤判定が起きやすい**。

## 重要だが未確定な点（リスク）
- **ベースライン比較の公平性**  
  Doc02の`position_size`固定と、RL側のサイズ調整（VPM/Allocator）をどう整合させるかが曖昧。比較条件が揃わないと優位性の証拠力が落ちる。
- **因果性のウォームアップ定義**  
  「期間開始前データのみ使用」とあるが、ローリング指標やMTFは**どこまで遡って許容するか**の明文化がない。境界条件が曖昧だとリーク判定が揺れる。
- **サンプル数要件**  
  「1000取引で計測」などの条件があるが、低頻度戦略では達成に時間がかかる。**期間依存の基準**に調整が必要。

## 推奨アクション（優先順）
1. **成功基準の整合統一**  
   - Doc00とDoc02で「必須/参考」の扱いを統一し、最終判定基準を1つに絞る。
2. **統計検定の仕様確定**  
   - 例: Mann-Whitney U検定 + Holm補正、α=0.05 を明記。
3. **運の良さ検出ロジックの修正**  
   - `std/mean`はIQRやMADに置換。対角線判定は削除か、意味のある構造に変更。
4. **ベースライン公平条件の規定**  
   - RL/ベースラインで「同一ポジションサイズ or 同一リスク制約」を明文化。
5. **ウォームアップ規定の明文化**  
   - 例: `max_lookback` までの過去データは許容、Val/Test開始時は直前データまで使用可能、等。

## 所感
この更新で「運用可能性を判定する設計」まで踏み込めています。残る課題は**基準の整合性と検定設計の堅牢化**。ここを詰めれば、Go/No-Go判定の説得力が一段上がります。
