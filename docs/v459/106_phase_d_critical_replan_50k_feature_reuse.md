# 106# Phase D 再設計案（50K固定・既存特徴量資産活用）

**Date**: 2026-02-10  
**対象**: `105_phase_d_plan_for_codex_review.md`  
**方針**: 「学習ステップ拡大は最後に実施」「まず50Kで取れる情報を取り切る」  
**目的**: 時間ロスを抑えつつ、Gate 2 突破に直結する改善順序へ計画を修正する

---

## 0. 結論（先に要点）

1. `105#` の最大課題は、**D0で200K/500Kを先行させたこと**。現段階では時期尚早。  
2. `104#` は同じ50Kでも改善余地が大きいことを示している（`ROI -15% → -4.38%`）。まず50Kで因果分離を完了すべき。  
3. 次フェーズは「**既存特徴量資産の再利用**」を主軸に据える。新規特徴量開発は後回し。  
4. 改訂Phase Dは **50K固定**で D0→D1→D2→D3→D4 を実施し、**最後の仕上げでのみ** step拡大を許可する。

---

## 1. 105#への批判的レビュー（主要修正点）

## 1.1 D0=学習量拡大は順序が逆

- `105#` は D0 を `50K→200K→500K` としているが、`66#`, `98#`, `99#`, `101#` の教訓（計測/因果分離先行）に反する。  
- 高コスト実験を先に回すと、評価誤差や設計ミスを抱えたまま計算時間だけ消費する。  
- **修正**: Step拡大は「有望条件の最終確認フェーズ」に限定する。

## 1.2 特徴量戦略が弱い

- `105# D1` は「特徴量強化」と書かれているが、既存資産の再利用順序が具体化されていない。  
- v459には既に特徴量関連資産が存在する（後述）。ここを使わずにtimesteps増加へ逃げるのは非効率。  
- **修正**: 50Kで「既存セット比較→アブレーション→採用判定」の順に実施。

## 1.3 C2（約定/コスト現実化）を後回しにしすぎ

- `101#` は C2（約定モデル現実化）を重要段階として定義。  
- `104#` でも主要ボトルネックは手数料支配。実行コスト感度の検証を飛ばすと、PF改善の議論が空回りする。  
- **修正**: 特徴量評価と並行で、50Kのままコスト/約定感度を早期に確認する。

## 1.4 D0のGate基準（2x改善）は恣意的

- `avg_gross_pnl_per_trade 2x` は分かりやすいが、分散や再現性を無視しやすい。  
- **修正**: `PF`, `Net ROI`, `gross/fee per trade`, `seed/window再現`を組み合わせた複合Gateに変更。

## 3. Phase D 改訂ロードマップ（50K固定）

## 3.1 D0: 実験基盤ロック（半日〜1日）

目的:
- 「50K比較」を厳密に成立させる。

実施:
1. `run_phase_c.py` を「特徴量プロファイル/データパス切替」に対応させる（timestepsは50K固定）。  
2. KPIログを固定: `PF`, `ROI`, `Sharpe`, `gross_pnl`, `total_fees`, `avg_gross_per_trade`, `avg_fee_per_trade`。  
3. 既存C3最良条件（`ent001 + thr70 + nodd`）を共通ベースとして使用。

## 3.2 D1: 既存特徴量セット比較（50Kスクリーニング）

目的:
- 「今ある特徴量資産だけ」で予測優位を引き上げられるか判定。

候補（新規開発なし）:
1. `v451_optimized`（現行8特徴）  
2. `minimal`（既存セット）  
3. `curated`（既存セット）  
4. `full`（既存セット）  
5. `v459_expanded_features.parquet`（既存生成済み資産、品質確認後）

進め方:
- Step 1: seed=42で粗選別（50K）  
- Step 2: 上位2条件を2seedへ拡張  
- Step 3: 上位1条件を4seedへ拡張

## 3.3 D2: 特徴量アブレーション（50K、上位条件のみ）

目的:
- 「効いている特徴量群」を特定し、無駄特徴を削る。

実施:
1. `run_ab_feature_test.py` ロジックを流用して、上位条件でLOOまたはグループ除去。  
2. 指標は `PF` と `gross/fee per trade` を主軸に採否判定。  

## 3.4 D3: コスト/約定現実化（50Kのまま）

目的:
- 手数料支配の改善可能性を先に判定する。

実施:
1. 取引コスト感度（例: 0.0005 / 0.001 / 0.0015）を同条件で比較。  
2. `101#` で推奨された約定系資産（`ztb/trading/execution/*`）を限定導入し、実行コストの劣化幅を計測。  
3. 「モデル改善がコストで消える条件」を明確化。

## 3.5 D4: 再現性検証（50K）

目的:
- 「たまたま勝ち」を排除する。

実施:
1. 最終候補1条件に対して 4seed × 複数window。  
2. `Mann-Whitney + Holm + Cliff’s delta` で Random超過を検証。  
3. Gate 2の未達KPI（ROI/PF/Sharpe）に絞って改善幅を確認。

---

## 4. Step拡大を許可する条件（最後の仕上げのみ）

以下を満たした場合のみ、`100K〜200K` を最終確認として許可:

1. 50Kで `PF >= 1.05` かつ `Net ROI >= 0%` を複数seedで再現  
2. `avg_gross_per_trade` が `avg_fee_per_trade` に実質接近  
3. Random比較で優位性が統計的に示唆される

満たさない場合は、step拡大を禁止し、D1〜D3の再設計を優先する。

## 7. 最終コメント

`105#` は問題意識としては正しいが、優先順位が逆だった。  
本段階で最も価値が高いのは「計算量を増やすこと」ではなく、**50Kで因果を切ること**と**既存特徴量資産を最大活用すること**。  
Phase Dは「50K固定で勝ち筋を作る」ことに集中し、step拡大は最後の仕上げに限定する。
