## §3 Q2: 学習曲線 (過学習診断)

### §3.1 チェックポイント別評価 (Run 4)

| Training Steps | Trades | Net ROI (%) | Gross PnL | Fees | IC_h1 | Avg PnL/Trade |

| 50,000 | 47 | **-7.16** | -6,243 | 905 | -0.006 | -231 |

### §3.2 学習曲線の特徴

1. **取引回数の減少**: 10K:201回 → 50K:47回 — 学習が進むと取引を避ける
2. **ROI の改善は見かけ上**: -15.64% → -7.16% だが、改善の主因は取引頻度の低下（手数料削減）
3. **Avg PnL/Trade は悪化**: -143 → -231 — 1取引あたりの収益性は改善せず
4. **IC は全ステップで ≈ 0**: 方向予測力に改善なし

### §3.3 4回の Q2 verdict

| Run | Verdict | Best Checkpoint |
|-----|---------|-----------------|
| 1 | OVERFITTING | 20,000 |
| 2 | OVERFITTING | 10,000 |
| 3 | OVERFITTING | 40,000 |
| 4 | UNDERFITTING | 50,000 |

- 3/4 OVERFITTING だが、best checkpoint がバラバラ → 系統的過学習ではなく**学習信号そのものが不在**
- Run 4 の UNDERFITTING は「後半の ROI が前半よりマシ」だが、全 ROI が深刻な負

### §3.4 Q2 総合判定

> **NO_LEARNING_SIGNAL** — 過学習/未学習の区別が不安定。モデルは方向予測ではなく「取引を減らすこと」（= 手数料回避）を学習している。学習曲線は prediction quality ではなく trading frequency の減少カーブに過ぎない。

## §4 Q3: Threshold 感度分析

### §4.1 Threshold 別の性能 (Run 4)

| Threshold | Trades | Net ROI (%) | Gross PnL | Fees | Active Ratio |
|-----------|--------|-------------|-----------|------|--------------|
| 0.30 | **1,794** | **-21.70** | -941 | 20,759 | 40.2% |
| 0.50 | **1,002** | **-21.49** | -8,863 | 12,625 | 13.9% |
| 0.70 | **181** | **-19.33** | -16,545 | 2,777 | 4.0% |
| 0.80 | **51** | **-7.05** | -6,050 | 985 | 2.1% |
| 0.90 | **9** | **-1.00** | -2,048 | 180 | 0.8% |

### §4.2 コスト構造の支配性

```
Threshold 0.30: 手数料 = 20,759 >>> |Gross PnL| = 941    → 手数料が22倍
Threshold 0.50: 手数料 = 12,625 >   |Gross PnL| = 8,863  → 手数料が1.4倍
Threshold 0.70: 手数料 = 2,777  <   |Gross PnL| = 16,545 → Gross損失が主因
Threshold 0.80: 手数料 = 985   <    |Gross PnL| = 6,050  → Gross損失が主因
Threshold 0.90: 手数料 = 180   <    |Gross PnL| = 2,048  → Gross損失が主因
```

- threshold ≤ 0.50: **手数料支配** (Cost Ratio >> 100%)
- threshold ≥ 0.70: **方向予測の失敗が主因** (Gross PnL 自体が大きな負)
- threshold = 0.90 でも ROI = -1.0% → 取引を極限まで減らしても**まだ負**

### §4.3 IC_h1 の threshold 非依存性

| Threshold | IC_h1 Spearman |
|-----------|---------------|
| 0.30 | -0.006052 |
| 0.50 | -0.006067 |
| 0.70 | -0.006018 |
| 0.80 | -0.005991 |
| 0.90 | -0.005984 |

- IC は threshold によって**全く変化しない** → threshold は方向予測力に影響せず、取引頻度のフィルタに過ぎない

### §4.4 Q3 総合判定

> **COST_DOMINATED** — threshold は取引頻度のフィルタとしてのみ機能し、方向予測力を改善しない。ROI の改善は手数料削減による見かけの効果。threshold=0.90 でも ROI=-1.0% であり、コスト構造を完全に排除しても収益化できない。

## §5 E0 統合診断

### §5.1 三問綜合

| 問 | 結論 | 深刻度 |
|----|------|--------|
| Q1 | 方向予測力なし (IC ≈ 0, 再現不能) | ⭐⭐⭐ CRITICAL |
| Q2 | 学習信号不在 (取引回避のみ学習) | ⭐⭐⭐ CRITICAL |
| Q3 | コスト構造支配 (threshold は手数料フィルタ) | ⭐⭐ HIGH |

### §5.2 根本原因の特定

E0 の結果は単一の根本原因に収束する:

> **SAC は現在の特徴量セットと報酬設計から方向予測信号を抽出できていない。**

裏付け:
1. IC が全ホライズン・全セッション・全 bin でゼロ近傍
2. 確信度が高い行動ほど逆方向 (directional_pnl < 0)
3. 学習は取引回避 (fee reduction) に収斂する
4. threshold を変えても IC は不変

### §5.3 E2 方向性の判断

スクリプトの自動推奨は `REWARD_REDESIGN_OR_FEATURE_EXPANSION` だったが、E0 結果の批判的分析に基づく修正判断:

| E2 候補 | 根拠 | 優先度 | 備考 |
|---------|------|--------|------|
| **P3: Counterfactual 検証** | SAC が学習不能なのか、特徴量/報酬が不適切なのか切り分け | ⭐⭐⭐ | 114# H4=保留 → P3 で決着 |
| P4: 報酬関数再設計 | use_simple_reward=True で PnL 直結だが、取引回避に偏る | ⭐⭐ | P3 結果次第 |
| P5: 特徴量拡張 | 現 14 特徴量では方向信号が不足 | ⭐⭐ | P3 結果次第 |
| P6: アルゴリズム変更 | SAC → PPO/DQN/教師あり回帰 | ⭐ | 最終手段 |

### §5.4 次ステップ: Phase E1 (Counterfactual)

E0 で Q1=NO_USEFUL_EDGE が確定したため、E1 は **P3 Counterfactual** を実施:

> 「SAC にコスト 0・完全情報を与えた場合、方向予測が可能か？」

- **手数料 = 0**: fee=0 で訓練 → cost 除去後にもまだ IC≈0 なら、特徴量/報酬の問題
- **未来情報リーク**: 次の n-step の return を特徴量に追加 → IC が改善すれば特徴量不足が原因
- **Oracle baseline**: ランダムだが常に正解方向の action → 手数料構造下での理論上限

## §8 Phase E1: Counterfactual 結果

### §8.1 実験設計

E0 で「SAC に方向予測力なし」が確定。E1 はその原因を切り分ける:

| 実験 | 手数料 | Threshold | 目的 |
|------|--------|-----------|------|
| CF1 | **0** | 0.80 | 手数料除去のみで方向予測力が現れるか |
| CF3 | **0** | **0.30** | 手数料除去 + 低閾値で全行動を活かした場合 |
| Oracle (normal) | **0.001** | — | 完全予測の理論上限（現行手数料下） |
| Oracle (zero) | **0** | — | 完全予測の理論上限（コストなし） |

### §8.2 結果

| 実験 | Trades | Gross PnL | Fees | Net ROI% | IC (best) |
|------|--------|-----------|------|----------|-----------|
| E0 BL (cost=0.1%, thr=0.80) | 47 | -6,050 | 905 | -7.05 | ≈ 0 |
| **CF1** (cost=0, thr=0.80) | 1,817 | **-2,583** | 0 | **-3.16** | 0.015 |
| **CF3** (cost=0, thr=0.30) | 14,265 | **+2,788** | 0 | **+2.82** | 0.012 |
| **Oracle** (cost=0.1%) | 9,022 | +107,493 | **125,746** | **-18.25** | — |
| Oracle (cost=0) | 49,993 | +27,315,082 | 0 | +27,315 | — |

### §8.3 核心的発見

#### 発見 1: COST_STRUCTURE_FATAL — 完全予測でもコスト負け

```
Oracle (cost=0.1%):
  avg_gross/trade = 11.91 JPY
  avg_fee/trade   = 13.94 JPY
  → 完全予測でも 1取引あたり -2.02 JPY の損失
```

**0.1% 手数料下では、1分足の全ステップで正解方向に賭けても利益にならない。**
これは SAC の問題ではなく、**手数料構造 × 取引頻度 の問題**。

#### 発見 2: SAC_HAS_WEAK_EDGE — 微弱な方向予測力は存在する

CF3 (cost=0, threshold=0.30) で **ROI = +2.82%, Gross PnL = +2,788 JPY**。

action bin 別分析:

| |action| 帯 | 件数 | avg_directional_pnl |
|-------------|------|---------------------|
| 0.0–0.3 (弱) | 22,499 | **-7.30** |
| 0.3–0.6 (中) | 17,637 | **+23.51** |
| 0.6–1.0 (強) | 9,863 | **+182.74** |

- **E0 とは逆パターン**: E0 では高確信度ほど損失 → E1-CF3 では高確信度ほど利益
- コストがない環境で学習すると、SAC は方向予測を学習する
- コストがある環境では、SAC は「方向予測」ではなく「取引回避」を学習してしまう

#### 発見 3: THRESHOLD_COUNTERPRODUCTIVE — 高閾値は逆効果

CF1 (cost=0, threshold=0.80) では **ROI = -3.16%**:
- 手数料なしでも高閾値で負の収益
- threshold=0.80 は中確信度の有益な取引を除外している
- CF3 (threshold=0.30) では **同一モデル種で +2.82%** → 閾値設計が根本的に間違っていた

### §8.4 E0 診断の修正

| E0 の結論 | E1 による修正 |
|-----------|--------------|
| "SAC に方向予測力なし" | ❌ **コスト 0 環境では微弱な方向予測力あり** |
| "特徴量/アルゴリズムが不適切" | ⚠️ **コスト構造が学習を阻害していた可能性** |
| "threshold はフィルタに過ぎない" | ✅ 維持 — ただし**フィルタが有害** |

### §8.5 E1 統合診断

> **根本原因は「手数料構造 × 取引頻度」の不整合。**
>
> - SAC は cost=0 環境で弱い方向予測力を学習できる (CF3: +2.82%)
> - しかし cost=0.1% では完全予測ですら利益不可 (Oracle: -18.25%)
> - SAC の学習はコスト圧力下で「取引回避」に収斂する
> - threshold は方向予測の改善に寄与せず、有益な取引を除外して悪化させる

## §9 Phase E2: 方針決定

### §9.1 E1 から導かれる解決軸

| 軸 | 内容 | 期待効果 | 実現性 |
|----|------|---------|--------|
| **A**: 手数料率の是正 | Zaif maker fee (0% or -0.01%) を使用 | ⭐⭐⭐ | Zaif 実態に依存 |
| **B**: 保有期間の延長 | TTL 固定 or 最小保有期間で 1取引の price swing を大きくする | ⭐⭐⭐ | v457.3 実証済 |
| **C**: エントリー選択性 | 全 step でなく、高シグナル時のみエントリー | ⭐⭐ | メタラベル化 |
| **D**: 報酬関数からコスト分離 | cost=0 で方向予測を学習 → 推論時のみコスト考慮 | ⭐⭐ | CF3 が実証 |

### §9.2 推奨: 軸 B+D の組み合わせ

**根拠**:

1. **軸 D (コスト分離訓練)** は CF3 で実証済み — cost=0 で訓練した SAC は微弱ながら正のリターンを生成する
2. **軸 B (保有期間延長)** は v457.3 (+36M JPY) で実績あり — 1取引の price swing を手数料以上にする
3. A は外部依存（取引所の手数料体系）、C は追加モデルが必要で工数大

**Phase E2α 設計**:
- cost=0 で訓練 + 最小保有期間 (TTL) + 推論時 cost 適用
- 10K スクリーニング → PF > 1.05 なら 50K 昇格

### §9.3 Phase E No-Go の更新条件

E1 の Oracle 結果により、Phase D の No-Go 条件を更新:

| 条件 | 状態 | 判定 |
|------|------|------|
| 10K 有望→50K で3回失速 | 1/3 (d2_thr80) | ⚠️ |
| avg_gross ≤ 0 @50K | ✅ 全実験 | ⭐ |

| **Oracle が cost 下で利益不可** | ✅ **新規追加** | ⭐⭐⭐ |

**Oracle の結果が最も重要**: 手数料構造を変えない限り、いかなるモデルも利益を出せない。

### §10.6 E2α の注意点・限界

1. **単一 seed (42)**: 再現性未検証。base ROI は E1-CF3 (+2.82%) と大きく乖離 → 高分散

## §14 停滞打破のための実行提案（レビュー意見）

「グダり」を断つには、改善案を増やすのではなく **実験の自由度を意図的に減らす** 必要がある。  
本稿の結果を踏まえ、次の 48 時間は以下の順で固定する。

### §14.1 まず止めること（即時）

1. 50K 以上の学習ステップ拡大（100K/200K）

### §14.2 先に潰すべき測定バグ（D0）

1. **eval_cost 切替の不整合を修正**  
   - `e2a_realcost` で `eval_cost=0.001` なのに `total_fees=0` が出ており、実コスト結論が歪む。  
   - `transaction_cost` だけでなく `exchange_profile.fee_model`（buy/sell fee）まで評価時に上書きするテストを追加。

2. **再現性の実験単位を固定**  
   - run ごとに `run_id` を発行し、`config / stdout / stderr / json` を同一IDで保存。  
   - checkpoint の共有ディレクトリ運用を禁止（run 単位ディレクトリに分離）。

3. **Gate 判定の統一**  
   - 以後の昇格条件を `4 seed 中 3 以上で gross>0` に固定し、単発勝利は採用しない。

### §14.3 次にやる 2 本だけの Killer 実験（E2β.5）

1. **K1: 費用現実性テスト（執行モデル差分）**  
   - 同一シグナル列で `fixed` / `realistic` / `pseudo_hft` を再評価し、  
     `avg_gross_per_trade - avg_fee_per_trade` の符号を比較。  
   - ここで全モデル負なら、RL改善ではなく市場×手数料前提の不適合と確定。

2. **K2: 非RLの上限テスト（同特徴量）**  
   - 同じ特徴量で、単純分類器（例: logistic / xgboost）の符号予測を walk-forward 評価。  
   - 非RLでも優位が出ないなら、問題は SAC ではなく特徴量情報量不足。

### §14.4 48時間後の分岐（強制）

| 条件 | 判定 | 次アクション |

| K1, K2 とも正 | 継続 | 4 seed + OOS で再検証し Phase F 判定 |

### §14.5 最後に

現状は「改善不足」より **判定系の不整合と探索自由度過多** が詰まりの主因。  
先に計測を硬化し、Killer 実験 2 本で分岐を強制すると、停滞は解消できる。
