### 「悪いかそうでないか」の判定（10Kステップ）

ユーザー指摘の通り、10Kステップでは「良いか」は判断できないが「悪いか」は判断可能：

| 判定 | 基準 | 現状 | 結果 |
|------|------|------|------|
| **壊滅的に悪い** | ROI < -20% | ROI = -5% | ❌ 該当しない |
| **明らかに悪い** | ROI < -10% | ROI = -5% | ❌ 該当しない |
| **やや悪い** | -10% < ROI < -3% | ROI = -5% | ✅ **該当** |
| **許容範囲** | -3% < ROI < 0% | ROI = -5% | ❌ 該当しない |
| **良い** | ROI > 0% | ROI = -5% | ❌ 該当しない |

**解釈**: 現在のモデルは「やや悪い」カテゴリ。壊滅的ではないが、改善の余地がある。

### 1. v451 "Golden Era" - 最も収益性が高かった時代

**出典**: [docs/v457/01_legacy_asset_analysis.md](../v457/01_legacy_asset_analysis.md)

| 設定 | v451 (成功) | v459現行 | 差異 |

| **Hold Penalty** | **0.0** | 適用あり | **待機に罰がない** |

**目的**: v451の成功設定が現環境で再現するか検証

```python
    # ROI, Trades, Action分布を記録
```

### Phase B: コスト影響分析（v457.2知見の適用）

**目的**: Gross PnL vs Net PnLの差分を可視化

**必要なメトリクス**:
1. `gross_pnl`: 手数料・スリッページ前の純利益
2. `total_fees`: 全取引の手数料合計
3. `total_slippage`: 全取引のスリッページ合計
4. `net_pnl`: gross_pnl - total_fees - total_slippage

**分析スクリプト案**:
```python
def analyze_cost_impact(env_metrics: dict) -> dict:
    gross_pnl = env_metrics.get('gross_pnl', 0)
    total_costs = env_metrics.get('total_fees', 0) + env_metrics.get('total_slippage', 0)
    net_pnl = gross_pnl - total_costs
    
    return {
        "gross_roi": gross_pnl / initial_balance * 100,
        "cost_roi": total_costs / initial_balance * 100,
        "net_roi": net_pnl / initial_balance * 100,
        "cost_ratio": total_costs / abs(gross_pnl) if gross_pnl != 0 else float('inf'),
        "interpretation": (
            "取引自体は利益" if gross_pnl > 0 else "取引自体が損失"
        )
    }
```

### Phase C: 非対称報酬（v451知見の適用）

**目的**: 損失を1.2倍重く評価する効果を検証

```python
# v451スタイルの非対称報酬
if pnl < 0:
    reward = pnl * 1.2  # 損失を強調
else:
    reward = pnl * 1.0  # 利益はそのまま
```
