**実行日時**: 2026-01-18

## 1. 結果概要：Freeze完全解消

- **改善点**: 以前の「Short Freeze」「Buy Freeze」が解消され、**活発な取引行動（1228トレード/10000ステップ）** が観測されました。
- **行動分布**:
  - Buy: 38.5%
  - Sell: 51.9%
  - Hold: 9.7%
  → 「持ちっぱなしは損」という学習が浸透し、積極的にポジションを回転させる（スキャルピング的な）動きになっています。

## 2. パフォーマンス評価

- **勝率**: **56.8%**（ランダム50%を有意に超えている）
- **純利益**: **¥-13,338**（マイナス）
- **考察**:
  - 勝率は良化したが、手数料とスリッページ負けしている。
  - トレード回数が多すぎる（10ステップに1回以上取引）。
  - これはペナルティが強すぎて「早く逃げないと！」という焦燥感（Over-Trading）を生んでいる可能性があります。
  - しかし、「動かないエージェント」よりは「動いて損するエージェント」の方が、報酬調整による改善余地が遥かに大きいです。

## 3. 次の課題：Over-Tradingの抑制

「保有コスト」がエージェントに強く認識された今、次は「エントリーコスト（手数料）」の認識を強化する必要があります。

- 現状：保有ペナルティ > エントリーコスト意識
- 目標：エントリーコスト > 期待利益 < 保有ペナルティ の均衡点
- 対策案：
  1. `hold_ramp` を少し緩める（現在200円 → 50〜100円へ）。
  2. `min_edge_mult` を強化し、小幅な値動きでの参入を禁止する。

## 4. 追加計画：過去バージョン（v437/v450）からの知見

### V437: Trading Frequency Controls
v437では「取引頻度制御」として以下のメカニズムが導入されていました：
- **Minimum Steps Between Trades (Cooldown)**: 取引後一定期間（例: 5 steps）は取引不可。
- **Max Trades Per Episode**: エピソードあたりの取引回数制限。
- **Action Thresholds (Symmetric)**: `0.33` などの閾値を設け、それ以下のアクション変化は無視する（Holdとみなす）。現在の `min_delta` に相当するが、より明示的な閾値設定が有効かもしれません。

### V450: Dynamic Thresholds
ボラティリティに応じてアクションの閾値を動的に調整する `DynamicThresholdManager` の概念。
- 低ボラティリティ時は閾値を上げ、不用意なエントリーを防ぐ。
- 高ボラティリティ時は閾値を下げ、チャンスを逃さない。

## 5. Over-Trading 対策の適用検証 (2026-01-18 追記)

Doc 14 の指摘に基づき、以下の修正を適用して検証を行いました。

### 修正内容
1. **Config注入経路の修復**: 
   - `ztb/trading/environment/utils/fast_intraday_env_v456_utils.py` を修正し、configから `min_delta` や `cooldown_steps` が正しく環境に渡るようにしました（Doc 14 Point #7 への対応）。
2. **パラメータ調整**:
   - `min_delta`: 0.01 → **0.05** (変更に必要な変化率を5倍に強化、ノイズによる反転を抑制)
   - `hold_ramp`: 200.0 → **50.0** (保有コストを緩和、早逃げ圧力を低減)

### 検証結果 (Backtest)
- **取引回数**: 1228回/10k steps (修正前) → **233回/141k steps** (修正後)
- **頻度**: 12.2% → **0.16%**
- **挙動変化**: 
  - 過剰なスキャルピング（Over-Trading）が完全に沈静化しました。
  - Config注入（`min_delta`）が正常に機能していることが確認できました。
- **次ステップ**: 
  - 取引頻度が極端に低下したため（約2.3回/日）、今度は「Under-Trading」領域に入っています。
  - `min_delta` を `0.02`〜`0.03` に緩和するか、`max_delta_per_step` を調整して機会を増やすチューニングへと移行します。
   - 手数料を現在のように損益の一部として引くだけでなく、**アクションそのものへのペナルティ** として報酬関数に追加する。
   - `reward -= abs(delta) * penalty_coeff`
   - これにより、期待リターンが薄い場面でのエントリーを抑制する。

2. **閾値 (Threshold) の調整**:
   - 現在の環境 (`FastIntradayEnvV456`) の `min_delta` (0.01) は、0.01 BTC以上の変化があれば即取引となる。これがノイズに反応しすぎている可能性がある。
   - `min_delta` を **0.02 - 0.05** に一度引き上げてみる。

3. **利益確定基準の導入**:
   - 強制決済に近いロジックで、「一定の利益（手数料以上）が出るまではHoldを推奨」するような報酬バイアスは危険（Hold Freezeに戻る）だが、`min_edge_mult` の強化で代用可能。
