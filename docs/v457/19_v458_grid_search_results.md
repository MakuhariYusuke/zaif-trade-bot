# 19. v458 Parameter Grid Search Results

**実施日**: 2026-01-18
**モデル**: `v457_base_legacy_assets` (SAC)
**データ**: `btc_jpy_training_data.csv` (10,000 steps)

## 1. 実験概要

「短期間での高収益」を目指し、`min_delta` を緩和した場合の挙動を検証しました。
バックテストには改修版 `backtest_v456.py`（Config注入・詳細ログ対応）を使用し、手数料（0.1% 往復）を含めた実質損益(Net PnL)を算出しました。

### 検証ケース

| Case | min_delta | hold_ramp | max_ttl | 狙い |
| :--- | :--- | :--- | :--- | :--- |
| **Case A** | **0.03** | 50.0 | 60 | 標準的な緩和 |
| **Case B** | **0.02** | 50.0 | 60 | さらなる緩和 (高頻度) |
| **Case C** | 0.03 | **20.0** | **30** | 保有コスト低減 + 時間切れ強制 (Sniper) |
| **Ref** | 0.05 | 50.0 | 60 | v457 Default (Under-Trading, ~16 trades/10k) |

## 2. 実験結果

| Metric | Case A | Case B | Case C |
| :--- | :--- | :--- | :--- |
| **min_delta** | 0.03 | 0.02 | 0.03 |

| **Trades (/10k)** | **1,759** | 1,234 | **1,057** |

| **Avg Win** | 221 | 268 | 280 |
| **Avg Cost** | ~280 | ~306 | ~339 |

## 3. 分析と考察

### A. Over-Trading の再燃
- `min_delta` を 0.05 から 0.03/0.02 に下げた瞬間、取引回数が **激増** しました（16回 → 1000回超）。
- **手数料負け (Death by Fees)**: すべてのケースで、純利益が **壊滅的な赤字** (-30万円超) となりました。
- 平均利益 (Avg Win ~250円) が 取引コスト (Avg Cost ~300円) を下回っており、**「取引すればするほど損をする」** 構造的欠陥が露呈しました。

### B. hold_ramp の影響 (Case A vs Case C)
- `hold_ramp` を 50 → 20 に下げた（保有ペナルティ緩和）結果、**取引回数が減少** (1759 → 1057) し、**Raw PnL が改善** (-21k → +34k) しました。
- **解釈**: 強い保有ペナルティは、エージェントに「微益撤退」や「損切り」を強要し、結果として無駄な回転売買（Churning）を引き起こしていた可能性があります。

### C. 謎の逆転現象 (Case A vs Case B)
- 通常 `min_delta` が低い (0.02) 方が高頻度になるはずですが、今回は 0.02 の方が頻度が低くなりました。
- **仮説**: ノイズレベル(0.02付近)のアクションがあまりに頻繁に入れ替わるため、逆にポジションが相殺されたり、環境内部の他の制約に引っかかっている可能性があります。

## 4. 結論と次の方針

**「パラメータ調整だけでは解決しない」** ことが明白になりました。
`min_delta` 0.05 では動かず、0.03 では動きすぎて死にます。この中間のスイートスポット（0.04?）を探るのも手ですが、より本質的な対策が必要です。

### 提言: Frequency Control の導入
取引回数を 1/10 (100〜150回/10k steps) に抑え込む必要があります。

1.  **Cooldown の強化**: 現在の `5` steps を `30`〜`60` (30分〜1時間) に増やす。一度取引したら連投不可にする。
2.  **Trade Limit**: 1日の最大取引回数を制限するラッパーを導入する。
3.  **Adaptive Threshold (再考)**: 今の相場なら動く、今は休む、を判断させる（v450 Dynamic Threshold）。

### 次の実験案 (Case D)
- **Base**: Case C (Raw PnLが良い)
- **Mod**: `cooldown_steps: 60` (1時間取引禁止)
- **Target**: 取引回数を ~150回/10k steps まで落とし、Net PnL の黒字化を狙う。
