## 1. 結果サマリー
**状態: 未解決（Freeze継続 / 方向転換）**

- **現象**: 以前の「100% Short Freeze」から「**100% Buy Freeze** (0.01 BTC)」へ変化。
- **挙動**: エピソード開始直後に最小単位（または小規模）のBuyを行い、10,000ステップ（約1週間）持ち続けた。

- **バックテスト結果**: 
  - 勝率: 100% (1トレード中1勝...実際は強制決済で微プラスの場合もあればマイナスも)
  - アクション分布: Buy 100%

## 2. 分析：なぜまだ張り付くのか？

### A. ペナルティの「希釈」問題
今回導入した `Time-Decay Penalty` は以下の式で計算されます：
```python
penalty = hold_ramp * extra_steps * (|position| / max_position)
```
- **設定値**: `hold_ramp = 200 JPY`, `max_position = 1.0 BTC`
- **実動作**: エージェントは `0.01 BTC` （最小に近いサイズ）を保有。
- **計算結果**: `200 * 1step * (0.01 / 1.0) = 2 JPY/step`

**考察**:
1分間でビットコイン価格（2000万円想定）が0.01%動くだけで **2,000円** 変動します。
これに対し、ペナルティが **2円** では、ノイズに埋もれて全く「痛み」として認識されません。
エージェントは「大きなポジションを持つと痛い（ペナルティ大）が、小さなポジションなら無視できる」と学習し、**「微小ポジションでの居座り」** という新たな局所解に到達しました。

### B. 環境設定の不整合 (Training vs Backtest)
- **Training**: `max_position = 1.0` (Config由来)
- **Backtest**: `max_position = 0.1` (スクリプト固定値)
- Trainingで学習した「0.1 (10%)」の出力強度が、Backtestではさらに小さい「0.01 BTC」として解釈され、よりペナルティが軽視される結果となりました。

### C. 報酬スケーリングの副作用
- 今回の修正で `reward / 100,000` としました。
- ペナルティ（2円）は正規化後 `0.00002` となり、ニューラルネットの重み更新においてほぼゼロ（勾配消失）として扱われています。
- JPYベースでの「実感」を持たせるには、ペナルティの絶対額をもっと引き上げるか、**ポジションサイズによるスケーリングを廃止**する必要があります。

## 3. 改善に向けた提言

### 対策1: Position-Scalable Penaltyの廃止
「ポジションが小さいからペナルティも小さい」というロジックは、在庫リスク管理としては正しいですが、Freeze対策としては逆効果でした。
**「ポジションを持っている事実」そのもの** に対してペナルティを課すべきです。

```python
# 修正案
scaling = 1.0  # サイズ依存なし
if abs(position) > 0:
    penalty = hold_ramp * extra_steps * scaling
```
これにより、0.01 BTCの保有でも 200円/step (1時間で1.2万円) のコストが発生し、明確な撤退圧力が生まれます。

### 対策2: ペナルティ単価の増額
現在の `hold_ramp = 200` は、BTCのボラティリティに対して安すぎます。
最低でもスプレッド（約1,000円〜2,000円）と同等以上の圧力をかける必要があります。
推奨: **`hold_ramp = 1000` (1000円/step)**

### 対策3: Reward Clippingの見直し
`[-1.0, 1.0]` のクリップ幅に対し、現在の報酬（数百円〜数千円）は `0.01` 程度に収まっています。
`reward_scale` を上げるか、除数を `100,000` から `10,000` に下げて、信号強度を上げるべきです。

## 4. 結論
「Anti-Freezeロジック」は導入されましたが、**定量的強度が不足** していました。
「微小ポジションによるペナルティ回避」という抜け穴を塞ぐため、**ペナルティの固定額化（非スケーリング化）** と **増額** を次回の修正で行います。
