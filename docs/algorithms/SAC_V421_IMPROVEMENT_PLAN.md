# SAC v421 Balanced Trading - 改善計画ドキュメント

## 概要
SAC v420 Hold RelaxedのBUYバイアス問題を修正したv421モデルのさらなる改善計画。
目標：安定して儲かるスキャルピングトレードモデルを実現。

## 1. 特徴量強化

### 現在の状況
- **トレンド指標**: 60個の特徴量を選択済み
- **選定理由**: 価格トレンドの多角的把握（移動平均、Ichimoku、Supertrendなど）
- **特徴量数**: 約80個（価格・出来高・テクニカル指標）

### 改善提案
- **追加検討指標**:
  - モメンタム指標: Williams %R, Ultimate Oscillator
  - ボラティリティ指標: Chaikin Volatility, Normalized ATR
  - 市場構造指標: Order Flow, Market Profile
  - 時間帯指標: 月次/四半期サイクル、市場セッション
  - 外部データ: ニュースセンチメント、Googleトレンド、経済指標

- **特徴量削減**: 相関の高い指標を統合（例: 複数のRSIバリエーション）
- **動的特徴量**: 市場ボラティリティに応じた重み付け

## 2. データ品質向上

### 改善計画
- **データ拡張**: より長い期間の過去データ（1年以上）を追加
- **複数時間軸**: 1分/5分/15分/1時間の特徴量統合 ✅ **実装完了**
- **リアルタイム適応**: 市場変動へのオンライン学習データ生成
- **異常値処理**: 極端な価格変動のフィルタリングと補正
- **データバリデーション**: 欠損値・異常値の自動検知システム

### 複数時間軸実装状況
- **実装日**: 2025-10-17
- **実装内容**:
  - RSI, ATR, ADX, EMA Cross, Heikin-Ashiの多時間軸対応
  - 6時間軸 (M1/M5/M15/H1/H4/D1) 対応
  - 特徴量数: 156個 (多時間軸追加により46個増加)
- **効果**: SACアルゴリズムの複数時間軸分析能力向上

## 3. 報酬関数最適化

### 現在の問題
- **長時間学習時の問題**: 報酬が1.000または-1.000に張り付く
- **原因**: 極端な報酬設計による勾配消失/爆発

### 改善計画
- **スキャルピング志向**: 短期取引（数分〜数十分）を奨励
- **報酬クリッピング緩和**: 過度な上下限を緩和
- **リスク調整リターン**: Sharpe ratioベースの報酬要素追加
- **取引頻度最適化**: 過度な取引/過少な取引のバランス
- **ダイナミック報酬**: 市場ボラティリティに応じた報酬スケーリング

### 具体的な修正
```json
{
  "reward_clip_min": -50.0,
  "reward_clip_max": 50.0,
  "short_term_bonus": 0.1,
  "scalping_penalty": -0.01
}
```

#### **詳細実装計画**

##### **1. コンセプトドリフト検知 (Concept Drift Detection)**
- **統計的手法**:
  - Kolmogorov-Smirnov検定: 分布の変化を検知
  - CUSUM (Cumulative Sum) 検定: 平均値の変化を監視
  - Page-Hinkley検定: 逐次変化点検知
- **MLベース手法**:
  - ADWIN (Adaptive Windowing): 動的ウィンドウによる変化検知
  - DDM (Drift Detection Method): 誤分類率ベースの検知
  - EDDM (Early Drift Detection Method): 誤分類率分布の変化検知
- **時系列特化手法**:
  - Time Series Change Point Detection
  - Seasonal-Trend decomposition
  - Fourier変換ベースの周期性変化検知
- **実装アプローチ**: River/MLflow統合によるリアルタイム検知パイプライン

##### **2. 自動再学習トリガー (Automatic Retraining Triggers)**
- **パフォーマンス低下検知**:
  - 予測精度の閾値監視（例: 精度90%以下でトリガー）
  - 損失関数のトレンド分析
  - 取引成功率の継続的監視
- **データ分布変化検知**:
  - 特徴量分布の統計的変化検知
  - 相関関係の変化分析
  - アウトライアー増加率監視
- **定期スケジューリング**:
  - 時間ベース（毎日/毎週）
  - データ量ベース（新規データ1000件ごと）
  - パフォーマンスベース（精度低下5%ごと）
- **実装アプローチ**: イベント駆動型トリガーシステム

##### **3. A/Bテストフレームワーク (A/B Testing Framework)**
- **トラフィック分割**:
  - 確率的分割（例: 新モデル30%、旧モデル70%）
  - 時間ベース分割（平日新モデル、週末旧モデル）
  - ユーザーベース分割（特定条件でのみ新モデル）
- **統計的有意性検定**:
  - t検定、Mann-Whitney U検定
  - 信頼区間推定
  - 効果量（Cohen's d）計算
- **自動ロールバック**:
  - パフォーマンス低下時の自動切り戻し
  - 統計的有意な悪化検知
  - 安全マージン設定（例: 精度95%信頼区間）
- **実装アプローチ**: Multi-armed banditアルゴリズム統合

##### **4. オンライン学習パイプライン (Online Learning Pipeline)**
- **インクリメンタル学習**:
  - オンライン勾配降下法
  - ミニバッチオンライン学習
  - 適応型学習率調整

# ⚡ 計算時間短縮のための改善策

## 概要

## 1. データ処理の最適化

### 特徴量計算の効率化
- **問題点**: 156個の多時間軸特徴量計算に時間がかかる
- **改善策**:
  - インクリメンタル特徴量計算（差分更新のみ）
  - 特徴量計算の並列化（マルチプロセス/マルチスレッド）
  - 計算結果のキャッシュ化（Redis/Memory cache）
  - 不要特徴量の動的スキップ
- **期待効果**: 特徴量計算時間を50-70%削減

### データローディングの改善
- **問題点**: 大規模時系列データのI/Oボトルネック
- **改善策**:
  - メモリマップドファイルの活用
  - データプリフェッチングの実装
  - 非同期データローディング
  - データ圧縮（gzip/lz4）の検討
- **期待効果**: データ読み込み時間を30-50%削減

### キャッシュ戦略の強化
- **改善策**:

2025-10-17制定の量子化・軽量化実装計画。SAC v421のモデルサイズ削減と推論速度向上を目的とした包括的な最適化戦略。モバイル/エッジデプロイメント対応と計算リソース効率化を実現。

## 1. 動的量子化 (Dynamic Quantization)

### 実装内容
- **精度 vs 速度のトレードオフ分析**:
  - FP32→FP16/INT8変換の精度影響評価
  - レイヤー単位での量子化適用判断
  - 動的量子化範囲の自動調整
- **PyTorch Quantization統合**:
  - `torch.quantization.quantize_dynamic`の活用
  - LSTM/Linear層の優先量子化
  - 量子化対応レイヤーの自動検知
- **量子化アウェアトレーニング**:
  - Quantization Aware Training (QAT) の検討
  - 量子化ノイズを考慮したトレーニング
  - ファインチューニングによる精度回復

### 技術的詳細
- **対象レイヤー**: LSTM, Linear, Embedding層
- **量子化方式**: 動的量子化（重みのみ） + 静的量子化（活性化含む）
- **精度維持**: 許容精度低下を1%以内に抑制
- **実装ファイル**: `ztb/training/quantization/quantizer.py`

### 期待効果
- **モデルサイズ**: 60-75%削減
- **推論速度**: 2-4倍高速化
- **メモリ使用量**: 50-70%削減

## 2. 知識蒸留 (Knowledge Distillation)

### 実装内容
- **教師-生徒モデル構成**:
  - 教師モデル: 既存のSAC v421フルモデル
  - 生徒モデル: 軽量版ネットワーク（パラメータ数50%削減）
  - 中間層蒸留: 特徴マップの知識転移
- **蒸留損失設計**:
  - ハードラベル損失（クロスエントロピー）
  - ソフトラベル損失（KLダイバージェンス）
  - 中間層特徴マップのL2距離最小化
- **段階的蒸留プロセス**:
  - Phase 1: 出力層のみの蒸留
  - Phase 2: 中間層を含む蒸留
  - Phase 3: アテンション重みの蒸留

### 技術的詳細
- **温度パラメータ**: ソフトマックスの温度調整（T=2.0-5.0）
- **蒸留強度**: αパラメータによるハード/ソフト損失のバランス
- **実装ファイル**: `ztb/training/distillation/distiller.py`

### 期待効果
- **モデルサイズ**: 40-60%削減
- **推論速度**: 1.5-2.5倍高速化
- **精度維持**: 教師モデル比95%以上の精度保持

## 3. モデル圧縮統合 (Integrated Model Compression)

### 実装内容
- **プルーニング (Pruning)**:
  - 構造的プルーニング: チャネル/フィルタ単位の除去
  - 動的プルーニング: 重要度ベースの重み除去
  - L1/L2正則化によるスパース化促進
- **低ランク近似 (Low-rank Approximation)**:
  - SVD分解による行列近似
  - Tucker分解によるテンソル近似
  - 自動ランク選択アルゴリズム
- **コンポジット圧縮パイプライン**:
  - プルーニング → 量子化 → 蒸留の順次適用
  - 各ステップでの精度検証
  - 自動圧縮率最適化

### 技術的詳細
- **プルーニング率**: 20-50%（重要度ベース）
- **ランク選択**: スペクトルノルムベースの自動決定
- **実装ファイル**: `ztb/training/compression/compressor.py`

### 期待効果
- **モデルサイズ**: 70-85%削減
- **推論速度**: 3-6倍高速化
- **メモリ効率**: GPU/CPUメモリ使用量60-80%削減

# 🛡️ 高度リスク管理実装計画

## 概要
2025-10-17制定の高度リスク管理実装計画。AIベースの動的リスク管理システムにより、SAC v421のリスク調整リターンを最大化。CVaR最適化とポートフォリオ最適化を統合した革新的なリスク管理アプローチ。

## 1. CVaR最適化 (Conditional Value at Risk Optimization)

### 実装内容
- **CVaR計算モジュール**:
  - ヒストリカルシミュレーションによるCVaR推定
  - モンテカルロシミュレーション統合
  - 信頼区間付きCVaR計算
- **リスク制約付きSAC (Risk-aware SAC)**:
  - CVaRを考慮した報酬関数設計
  - リスク調整リターンの最適化
  - 動的リスク許容度の調整
- **CVaRベースの意思決定**:
  - ポートフォリオレベルでのリスク評価
  - 取引サイズのCVaR制約下最適化
  - リアルタイムリスク監視

### 技術的詳細
- **CVaR計算式**: CVaR_α = E[L|L ≥ VaR_α]
- **信頼水準**: α = 95% (5%テールリスク)
- **最適化手法**: 勾配ベースCVaR最適化
- **実装ファイル**: `ztb/risk/cvar_optimizer.py`

### 期待効果
- **リスク削減**: テールリスクを30-50%低減
- **安定性向上**: 極端な損失シナリオの回避
- **リターン最適化**: リスク調整リターンの向上

## 2. ポートフォリオ最適化統合 (Portfolio Optimization Integration)

### 実装内容
- **Markowitzの平均分散モデル拡張**:
  - 現代ポートフォリオ理論の統合
  - 効率的フロンティアの計算
  - リスク・リターンの最適バランス
- **ブラック-リッターマンモデル**:
  - 市場均衡からのベイジアン更新
  - 投資家ビューの統合
  - 動的資産配分
- **リスクパリティ戦略**:
  - 等リスク寄与ポートフォリオ
  - 分散投資による安定化
  - 相関リスクの低減

### 技術的詳細
- **最適化ソルバー**: SciPy/SciPy.optimize統合
- **制約条件**: 完全投資制約、リスク上限設定
- **再バランス頻度**: 日次/週次/月次の柔軟設定
- **実装ファイル**: `ztb/risk/portfolio_optimizer.py`

### 期待効果
