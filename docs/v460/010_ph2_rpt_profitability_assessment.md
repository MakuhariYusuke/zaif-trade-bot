## §1 問題設定: 何円儲かるか

v460 "Microstructure Edge" の戦略構造:

```
方向予測 → maker 指値エントリー → 保有(1-15分) → maker 指値イグジット → 損益計上
```

この戦略の期待損益は 3 要素で決まる:

| 要素 | 変数 | 現在の状態 |
|------|------|-----------|
| **方向予測能力** | IC (Information Coefficient) | ≈ 0 (G1 FAIL) |
| **執行品質** | fill rate, adverse selection | 未測定 (G1.1 未実施) |
| **市場条件** | spread, σ, 流動性 | 実測済 (§2) |

**方向予測能力 IC ≈ 0 の時点で、他の 2 要素がいかに良好でも利益は出ない。**

## §3 収益試算モデル

### 3.1 単一ラウンドトリップの期待損益

方向予測 maker 戦略のラウンドトリップ PnL:

$$E[\text{PnL}] = (\alpha + s - 2 \cdot \text{AS}) \times V$$

**※ 簡略化モデル**: 上式は両レグ maker 約定を前提としている。実際には fill rate 90% でも両レグ約定確率は 0.9² = 81%。イグジットが taker となる場合 0.1% = 10 bps の追加コストが発生し、BE IC は 0.04 → 0.13 に悪化する (012# §2-A 参照)。

| 変数 | 意味 | 単位 |
|------|------|------|
| α | 方向アルファ = IC × σ_return | bps |
| s | maker-maker スプレッド獲得 | bps |
| AS | adverse selection (約定時の逆選択コスト、片道) | bps |
| V | ポジション価値 = Q × P | JPY |

### 3.2 パラメータ推定

| パラメータ | 推定値 | 根拠 |
|-----------|--------|------|
| s (スプレッド獲得) | 1.08 bps | 実測 (§2.1) |
| AS (片道逆選択) | 1.0-2.0 bps | 暗号資産 maker の文献値。BTC/JPY 国内は HFT 少なく下限寄り |
| σ_1min | 23.0 bps | 実測 (§2.2) |
| σ_5min | 48.3 bps | 実測 (§2.2) |
| σ_15min | 82.3 bps | 実測 (§2.2) |

### 3.3 スプレッド獲得の条件

maker-maker ラウンドトリップでスプレッドを獲得するには、**エントリーとイグジットの両方が best bid/ask で約定**する必要がある。

- エントリー: best bid（買い）/ best ask（売り）に発注 → 約定待ち
- イグジット: 反対側の best に発注 → 約定待ち

**重要**: 両方が想定どおり約定する確率は 100% ではない。特に:
- 保有期間中に価格が動き、イグジットの best 位置が変わる
- イグジット注文が約定しない場合、キャンセル→再発注→時間経過→損失拡大
- **急いで taker でイグジットする場合: taker 手数料 0.1% = 10 bps が即発生し、アルファを完全に消す**

## §5 損益分岐分析

### 5.1 ブレークイーブン IC

$$\text{PnL} = 0 \iff \alpha + s = 2 \cdot \text{AS}$$
$$\text{IC}_{\text{BE}} = \frac{2 \cdot \text{AS} - s}{\sigma}$$

| AS (bps) | spread (bps) | σ_1min (bps) | IC_BE | 判定 |
|----------|-------------|-------------|-------|------|
| 1.0 | 1.08 | 23.0 | **0.040** | G1 では fold 4 込みでやっと到達する水準 |
| 1.5 | 1.08 | 23.0 | **0.083** | OHLCV プロキシで到達不可能 |
| 2.0 | 1.08 | 23.0 | **0.127** | 極めて高い予測能力が必要 |

### 5.2 解釈

- AS = 1.0 bps（最楽観）でも IC_BE = 0.04 が必要
- G1 レポートの fold 0-3 の direction IC は -0.002 〜 +0.022 → **ブレークイーブンに未到達**
- fold 4 込みの平均 IC ≈ 0.03-0.04 は fold 4 の異常値に依存（005# §4.1）
- **OHLCV 由来の特徴量でブレークイーブン IC を安定的に達成する見込みはない**

### 5.3 スケーリングの罠

「ポジションを大きくすれば収益も大きくなる」は半分正しく半分誤り:

1. PnL は V に比例するが、**マーケットインパクトは非線形に増大**
2. Coincheck の top-10 bid 深度は 0.166 BTC → 0.05 BTC 以上の注文は板を動かす
3. 0.1 BTC の注文は流動性の 60% を占め、**自己の注文がスプレッドを拡大**させる
4. 結果、AS が増大しブレークイーブン IC がさらに上昇 → スケールするほど不利になる

## §8 構造的課題の直視

### 8.1 OHLCV → Real Data: 何が変わるのか

005# は OHLCV プロキシが方向予測に無力であることを証明した。Real data で変わる可能性があるもの:

| 特徴量 | OHLCV プロキシ | Real Data | 追加情報 |
|--------|--------------|-----------|---------|
| bid-ask spread | (H-L)/mid ≈ HL 比 | 実際の best bid/ask 差 | 板状態の直接観測 |
| depth imbalance | CLV (近似) | bid/ask 各価格帯の注文量 | 需給バランスの直接観測 |
| trade flow | 符号付き出来高 | 個別約定の方向 (buyer/seller initiated) | 情報トレーダーの検出 |
| order flow toxicity | VPIN proxy | 実際のフロー毒性 | マーケットメイカーのリスク指標 |
| queue position | なし | 自注文の板内位置 | 約定優先度の推定 |

**批判**: real data は確かに情報リッチだが、BTC/JPY 国内取引所の特殊性がある:
- 参加者の多くは個人投資家（情報トレーダーの比率が低い可能性）
- HFT が少ないため板の情報効率が低い可能性（逆に言えばエッジの余地）
- 取引所ごとに板の特性が異なり、汎化しにくい

### 8.2 v459 との「同じ轍」リスク

v459 は以下のパターンで失敗した:

1. RSI×7 で OHLCV 方向予測 → 失敗
2. SAC を大量チューニング → 学習は安定するが予測がない
3. 119 文書を生産 → 結論は「特徴量に情報がない」

v460 のこれまでの経緯:

1. OHLCV proxy×10 で方向予測 → G1 FAIL (v459 と同じ)
2. G1.1 実装に工数投下 → 方向信号がないまま執行品質を測る
3. 10 文書を生産 → 現在ここ

**共通パターン**: 問題の根本（方向予測能力の欠如）に取り組む前に、周辺インフラを整備する傾向。

### 8.3 Coincheck BTC/JPY の市場特性の考察

§2 のデータからの所見:

1. **スプレッドは狭い (1.08 bps)**: maker 戦略にとっては好条件。ただし AS が spread を上回れば意味がない。
2. **板は薄い (top-10 bid = 0.166 BTC)**: 大きなポジションは取れない。スケーリングに限界。
3. **出来高は適度 (830 BTC/24h)**: 0.01 BTC の取引は問題なく可能。
4. **ボラティリティは高い (年率 167%)**: 方向を当てられれば大きなリターン。当てられなければ大きな損失。

## Appendix A: 計算根拠

### A.1 期待損益の導出

方向予測型 maker 戦略の 1 ラウンドトリップ:

- **Entry**: maker 指値 (best bid/ask) → 手数料 0%
- **Exit**: maker 指値 (反対側 best) → 手数料 0%
- **保有期間**: H 分

PnL (long の場合):

$$\text{PnL} = P_{\text{ask}}(t+H) - P_{\text{bid}}(t)$$
$$= [P_{\text{mid}}(t+H) + s/2] - [P_{\text{mid}}(t) - s/2]$$
$$= \Delta P + s$$
$$= (\alpha - 2\text{AS} + s) \times V / P$$

ここで、両レグの maker 約定時に AS が片道ずつ発生すると仮定。

### A.2 Adverse Selection の推定

AS は maker 注文に固有のコスト: 「約定した瞬間、価格が不利な方向に動く傾向」。

- 暗号資産の AS: 文献上 0.5-5 bps (市場・取引所による)
- Coincheck BTC/JPY: HFT 比率低 → AS は比較的小さいと推定 (1-2 bps)
- ただし板が薄い → 大口注文時は AS 増大

### A.3 市場データ取得スクリプト

`temp/market_check.py` で Coincheck API + 過去 Parquet データから算出。

### A.4 IC と Grinold の基本法則

$$E[\alpha] = \text{IC} \times \sigma_{\text{return}}$$

これは Grinold の Active Management の基本法則の簡略化。IC は予測とリターンの Spearman 相関。
