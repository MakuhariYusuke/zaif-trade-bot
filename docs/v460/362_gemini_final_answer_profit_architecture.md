## 2. コードとログから判明した「死に至る病」

### 2.1 SAC訓練パイプラインの完全な自己欺瞞（In-Sample過学習）
`scripts/v460/lib/tasks/sac_train.py` の 122行目で `_evaluate_trained_model(model, env, cfg)` を実行しているが、ここで渡されている `env` は訓練で使った `df` から生成された環境そのままである。
**時分割のホールドアウト（Train/Test Split）が一切存在しない。**
カンニングペーパーを見ながらテストを受け、「満点（PASS）」を出して喜んでいる状態（G2 Gateの形骸化）である。実稼働では未知の相場（Out-of-Sample）に直面するため、このSACモデルを展開すれば瞬時に大火傷を負う。

### 2.2 Phase 2 (Live Maker) の「事後対応」という根本的欠陥
`buy_dynamic_kill` などのEWMA閾値バグ（符号反転、未来データ参照）を350番台で修正し、止まらなくなった事は評価できる。しかし、EWMAによるキルスイッチはあくまで**「殴られて血が出てから（PnLがマイナスになってから）逃げる」**ロジックに過ぎず、Adverse Selection（逆選択）を「事前」に防ぐものではない。Fill Testで `-717 JPY` を叩き出している原因はここにある。HFTにおいて、被弾後の撤退は遅すぎる。

## 3. 【回答】「一番儲かる方法」へのパラダイムシフト

収益性を極大化するためには、**「Phase 2 と Phase 3 の完全な役割分担（Sidecar Architecture）」**へ舵を切る必要がある。

### 結論：SACに「板（Quote）」を出させるな。「方針（Regime）」を出させよ。

#### 具体的アクション１：Phase 2 (Execution) の非対称化・超短期予測の導入
現在、BotはGlosten-Milgrom（逆選択）の餌食になっている。これを防ぐには「受動的」なキルスイッチではなく「能動的」な価格スキュー（Avellaneda-Stoikovモデルの発展形）が必要。
- **OFI（Order Flow Imbalance）と Micro-price の導入**:
  約定履歴や1分足ではなく、「直近数秒の板の厚み（Bid/Ask Volume Imbalance）」を見て、フェアバリュー（Micro-price）を計算する。
  売り圧が強い（Askが厚い）瞬間に、Buyの指値をただちに下げるか即座にキャンセルする。これが「殴られる前に避ける」唯一の方法である。

#### 具体的アクション２：Phase 3 (SAC) を「戦略的サイドカー」に降格（昇格）させる
1分足のOHLCV特徴量しか見えないSACモデルに、HFTのミリ秒の指値決定を任せるのは、目隠しでF1カーを運転させるようなものだ。
- SACの出力（Action）は、「具体的な指値幅や価格」ではなく、**「今後15分の市場の方向性（Directional Bias）」または「目標在庫ポジション（Target Inventory）」**とする。
- **統合方法**:
  SAC（Phase 3）は数分に1回、「今は買い優勢（Bias=+1）」というシグナルを出す。
  Live Execution（Phase 2）はそれを受け取り、「Bias=+1だから、Buyの指値を少し攻撃的（スプレッド縮小）にし、Sellの指値を保守的（スプレッド拡大）にする」という非対称マーカー（Asymmetric Maker）として動く。

#### 具体的アクション３：SACの訓練データの厳格な分割
直ちに `sac_train.py` を修正し、データの最新20%（あるいは特定の数日間）を絶対にエージェントに見せない `eval_env` を構築すること。E2基準（`ic_seed_std`）は、未学習データに対する汎化性能で測定しなければ、ただの乱数生成器に成り下がる。

## 4. レビュワー（Gemini 3.1 Pro）からの最終勧告

現在、あなたは「Phase 3 (SAC) を完成させれば Phase 2 の負けを取り返せる」という幻想を抱きかけている。
しかし、現実は逆である。**「基礎的なMicrostructure（Phase 2）で勝てないMakerは、どんな高尚な強化学習（Phase 3）を乗せても市場の養分になる」**。

最も収益性が高い（一番儲かる）アプローチは、一旦 SAC の E2E 結合の優先度を下げ、以下の順序で制圧することだ。

1. **Phase 2 の止血**: 板情報（Imbalance）を用いた「事前的」な Adverse Selection 回避ロジックを実装し、Fill Test の PnL をプラマイゼロ（あるいはスプレッド負け程度）まで引き上げる。
2. **Phase 3 の正当化**: `sac_train.py` に確実な Train/Test 時系列 Holdout を実装する。
3. **ハイブリッド結合**: Phase 3 の推論結果を遅延許容の「Regime Prior（相場環境の事前分布）」として Phase 2 エンジンに注入し、非対称な Quote Placement で利鞘を抜く。

これが、現行の設計と Zaif の市場特性を踏まえた上で、最短かつ最強の収益化パスである。これ以上のコードのパッチワークは不要。アーキテクチャの自己認識をアップグレードせよ。
