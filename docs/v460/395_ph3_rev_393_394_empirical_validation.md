## 0. 背景と占断の含意

394# で言及された **雷火豊**（中筮法による純卦）は、「明（離=火）を持って動（震=雷）けば豊かになる」が、逆に **明察を欠けば日中に斗（北斗七星）を見る — すなわち昼に星を見るほどの暗闘に陥る** という卦辞を持つ。

本件の文脈では：
- **火（明察）= 正確なデータ分離 (SHA fencing) + コードに即した解釈**
- **雷（行動）= 施策の実装・デプロイ**

391# は「雷を先に落とした」状態 — mixed-SHA データから導かれた因果推論に基づく施策をそのまま提案した。393#/394# は「火を先に灯せ」と正しく諫めた。本 395# は火（実証）を灯した上で、動くべき方向を確定させる。

## 2. 391# 主要論点の SHA-fenced 検証

### 2.1 RC-3 EV "Confident-Wrong" ゾーン

**391# 主張**: EV [1,2) は WR=40%, −0.64 bps で最悪バケット
**393# 反論**: EV は side-aware な predicted PnL であり、direction ではない

#### コード実証

[skip_gate_evaluator.py](scripts/v460/lib/skip_gate_evaluator.py#L660-L665) の `_try_ev_weighted_decision()`:

```python
# buy: primary=pnl30 (短期), alt=pnl120 (長期)
# sell: primary=pnl120 (長期), alt=pnl30 (短期)
if side == "buy":
    ev_score = w30 * primary_pnl + w120 * alt_pnl
else:
    ev_score = w30 * alt_pnl + w120 * primary_pnl
```

EV は **そのサイドの予測 PnL** であり、price direction ではない。
- sell + EV>0 = 「この sell は利益がでるはず」（モデルの予測）
- 391# の「上がるのに売っている」解釈は **コードと不一致**

#### SHA-fenced データ検証

| EV bucket | mixed-SHA (391#) | current SHA (`66165ee5`) |
|-----------|-----------------|-------------------------|
| **[1,2)** | n=45, **−0.64**, WR=40% | n=9, **+0.799**, WR=56% |
| [2,10) | n=21, +0.62, WR=57% | n=7, +3.245, WR=71% |

**EV [1,2) の問題は current SHA では完全に消失** — mixed-SHA の artifact であった。

#### sell + EV>0 の検証

| 条件 | mixed-SHA (391#) | current SHA |
|------|-----------------|-------------|
| sell + EV>0 | n=76, **−0.481**, WR=46% | n=16, **+1.896**, WR=56% |
| sell + EV<0 | n=131, +0.579, WR=53% | n=11, +1.010, WR=45% |

**current SHA では sell + EV>0 がむしろ最良セグメント** (+1.896)。

→ **393# 判定 CONFIRMED**: 391# P0-1「EV 方向ガード」は **実装してはならない**
→ **394# 判定 CONFIRMED**: 問題は「方向の不整合」ではなく「モデルの overprediction」だが、**current SHA ではその問題すら消失している**

## 6. 結論

### 393# / 394# は正しかった

391# の深掘り分析は「どこで損しているか」を嗅ぎ分ける素材としては有用だったが、
mixed-SHA データから導かれた因果推論は **5 本中 4 本が current SHA で再現せず** であった。

393# と 394# の「SHA フェンシングなしの因果推論は危険」「EV の解釈がコードと不一致」
「既存ガードの再較正が先」という批判は、全て実証で裏付けられた。

### 唯一の構造的問題

SHA-fenced でも再現した問題は **Regime confidence [0.7,0.9) の paradoxical underperformance** のみ。
これについては P1-1 でデータ収集 → offset 微調整の順序で対応する。

### 今後の原則

> **雷（行動）の前に火（明察）を灯す**
> — 分析は SHA-fenced、施策は same-SHA 実証済みのもののみ採用
