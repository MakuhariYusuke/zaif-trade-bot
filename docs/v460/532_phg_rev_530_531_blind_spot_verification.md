## §0 総評

530# と 531# はそれぞれ質の高いレビューを行っている。特に 531# の「母集団不一致」「ceiling 飽和」「CV cap_hit」の指摘は鋭い。
しかし、両者に共通して **以下の主要論点が欠落**している。

1. **時間帯クラスタリング** — 損失の 171% が 12h+15h の 2 時間に集中
2. **05:17→08:25 の隠れたデッドロック** — 16:22+ より長い 3 時間8分間の veto 連鎖
3. **veto の機会費用** — veto 解除後の first-fill は 5/6 が黒字 (avg +1.36bps)
4. **sell_dynamic_kill のタイミング問題** — 損失発生後に反応的に発動、予防にならず
5. **Buy アクセス率の構造的低さ** — buy 176 サイクル中 fill=59 (33.5%)

## §2 05:17→08:25 の隠れたデッドロック — 529# の 16:22+ より深刻

本日の veto シーケンス全体:

| # | 開始 | 終了 | 持続 | veto回数 | 直後fill PnL |
|---|------|------|------|---------|-------------|
| 1 | 03:15 | 03:15 | 瞬間 | 1 | +1.63 |
| 2 | 03:19 | 03:33 | 14m | 4 | +2.45 |
| 3 | 03:41 | 03:44 | 3m | 2 | +0.19 |
| 4 | 04:09 | 04:15 | 6m | 2 | -0.06 |
| **5** | **05:17** | **08:25** | **3h 8m** | **37** | **-0.78** |
| **6** | **16:22** | **17:27+** | **65m+** | **19** | **+4.75** |

529# が報告した 16:22+ デッドロックは 65 分 / 19 回 veto だが、**05:17→08:25 は 3 時間 8 分 / 37 回 veto** で遥かに長い。
06h-07h の fills = 0 はこのデッドロックの結果。530#/531# はどちらもこの期間に言及していない。

**構造的意味**: veto デッドロックは 16:22+ の一過性の問題ではなく、BTC=0 + veto 条件が揃えば日中いつでも発生する再帰的パターン。

## §3 Veto の機会費用 — 定量的評価

6 つの veto シーケンス終了後の first-fill PnL:

| 値 | 結果 |
|----|------|
| +1.63, +2.45, +0.19, -0.06, -0.78, +4.75 | 5/6 が正 |
| 合計 | +8.18bps |
| 平均 | +1.36bps |

**veto が解除されて最初の取引が成立する時点では、ほぼ常に買いが有利**。
これは市場の自己修正メカニズム（BF-CC spread の mean reversion）を示唆する。

veto は「現在の瞬間のリスク」を正しく捉えているが、**リスクがどのくらい持続するか**を考慮していない。3 時間連続で veto し続けるのは明らかに過剰防衛である。

**示唆**: veto には time-decay（531# の提案と一致）または max_consecutive_veto_count の上限が必要。

## §4 sell_dynamic_kill のタイミング問題

### 第 1 回発動: 12:30

| イベント | 時刻 | 内容 |
|---------|------|------|
| C14902 fill | 12:29 | **-20.79bps** (sell) |
| C14903 fill | 12:31 | -5.34bps (buy) |
| kill 発動 | 12:30 | rolling30 mean=-1.378 < threshold -0.814 |
| kill 継続 | 12:32-13:00 | sell blocked, buy のみ |
| kill 自動解除 | 13:04 | TIME LIMIT expired (2031s, limit=1800s) |

**kill は C14902 の損失発生 1 分後に発動**。予防ではなく事後対応。
C14902 (-20.79) が rolling mean を押し下げたことで threshold を超えた。つまり損失した結果として kill が発動する構造であり、損失を防ぐ機構ではない。

### 第 2 回発動: 15h 帯

| イベント | 時刻 | 内容 |
|---------|------|------|
| C14948 fill | 15:11 | -6.37bps (sell) |
| C14951 fill | 15:21 | -10.13bps (sell) |
| kill 自動解除 | 15:55 | TIME LIMIT |

ここでも sell 損失が先に発生し、kill がその後に反応。

**530#/531# への補正**: 530# は「toxic sell の条件分離」、531# は「sell AS 条件分離」を提案しているが、**既存の sell_dynamic_kill が事後的にしか機能しない**点を見落としている。条件分離は事前判定に基づく必要があるが、現行メカニズムはそうなっていない。

## §7 530# / 531# の主張に対する検証結果

### 530# Finding #3 (favorable tighten 13fills/+9.94bps) — 検証困難

531# が正しく指摘した通り、JSONL の `cross_venue_lead_lag_applied` フラグからは 530# の数値を再現できない。
ログの favorable tighten 判定と JSONL のフラグは異なる母集団を捕捉している。**join key 不在のため検証不能**。

### 531# §2.1 (pipeline stage の加算的積み上げ) — 部分的に不正確

531# は "各 stage が独立に offset を押し上げるため" と述べ、加算的蓄積を示唆している。

JSONL の `offset_stages` 実データ:

**buy 例**:
```
base=0.05 → as_shift=0.30 → regime=0.54 → spread_adapt=0.30 → kyle~vol_guard=0.30 → final=0.30
```
- as_shift: 0.05→0.30 (加算的, +0.25)
- regime: 0.30→0.54 (乗算的, ×1.8)
- spread_adapt: 0.54→0.30 (乗算的, ×0.556 — **正規化**)
- vol_guard: 0.30→0.30 (identity)

**sell 例**:
```
base=0.14 → as_shift=0.12 → regime=0.10 → spread_adapt=0.26 → vol_guard=0.30 → final=0.30
```
- as_shift: 0.14→0.12 (**減少**, -0.02)
- regime: 0.12→0.10 (乗算的, ×0.833 — 減少)
- spread_adapt: 0.10→0.26 (乗算的, ×2.56 — **大幅増**)
- vol_guard: 0.26→0.30 (乗算的, ×1.15)

pipeline は加算と乗算の混合であり、かつ正規化段階を含む。
531# の「stage 間相関の検証と冗長 stage 削減」提案は方向性として正しいが、多くの中間段が identity (×1.0) であるため、実質的に**活性段は 3-4 段**。活性段の値はサイドによって増減方向が異なる。

### 531# P0-new (ceiling 0.25→0.30) — fill rate リスクの定量が欠落

531# は ceiling 引き上げを P0-new として提案するが、fill rate への影響を「段階的に検証すべき」と述べるのみで定量的な見積もりがない。

現在のデータ:
- pipeline 出力の中央値 ≈ 0.30 (pre-clamp)
- 0.30 の offset = mid price から 0.30% 離れた注文 = BTC/JPY 11M で約 33,000 JPY
- 現行 0.25 = 約 27,500 JPY

offset 増加は fill rate 低下に直結する。0.25→0.30 で mid からの距離が **20% 拡大**。
fill rate が現在の 33% から更に低下するリスクは無視できない。

**提案**: ceiling 引き上げ前に、pipeline 上流の正規化段 (spread_adapt) の効果を確認し、上流で 0.25 以内に収まるキャリブレーションを先行すべき。
