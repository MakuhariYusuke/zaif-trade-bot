## 実装内容

### 1. FillRecord 型統合 (F1 関連)

- `ztb/risk/pnl_monte_carlo.py` のローカル `FillRecord` を **削除**
- `ztb/metrics/fill_quality.py` の正規定義を import に統一
- `load_fill_records()` / `load_fill_records_glob()` も fill_quality へ委譲
- `re-export` で後方互換を維持 (`from pnl_monte_carlo import FillRecord` は引き続き可能)

### 2. MC シグネチャ修正 (F5 CRITICAL)

- `run_gate_check.py`: `PnLMonteCarloSimulator(MonteCarloConfig())` → `PnLMonteCarloSimulator(records, MonteCarloConfig())`
- `MCFillRecord` フィールド変換ブロック (15行) を **削除** (型統合により不要)
- `MonteCarloResult.to_dict()` を新設 — `PnLMonteCarloSimulator.to_dict(self, result)` から独立
- `run_pnl_monte_carlo.py`: `sim.to_dict(result)` → `result.to_dict()` に更新

### 3. Unknown Fill 対策 (F6 HIGH)

- **問題**: `get_order_status() == None` → `filled=True` は不正確
  - adapter は open orders → transactions を順に確認済み
  - `None` = 両方に不在 → API 障害 or 期限切れ の可能性大
  - fill_rate の過大評価リスク
- **修正**: `None` 検出時に 2 秒後リトライ
  - リトライで `filled` 確認 → 正常 filled 処理
  - リトライ後も `None` → `cancelled=True, cancel_reason="status_unknown"` (保守的)
- `cancel_reason_poll` 変数で poll ループ中の理由を保持、最終 FillRecord に反映
