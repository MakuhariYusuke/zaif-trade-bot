## §2 妥当な点 (維持推奨)

1. `AdaptiveSACCore` の本質的欠陥（DUMMY 検知器、外部バッチ未注入）をクリティカルに捉えた点は妥当。  
根拠: `ztb/training/adaptive_sac_core.py:24`, `ztb/training/adaptive_sac_core.py:538`, `ztb/training/adaptive_sac_core.py:579`, `ztb/training/adaptive_sac_core.py:586`

2. `ActionPrediction` の 5 次元固定が重大問題という認識は妥当。  
根拠: `ztb/trading/live_trader/action_prediction.py:31`, `ztb/trading/live_trader/action_prediction.py:33`

3. 「SAC 系の整理が必要」という方向性そのものは妥当。ただし手順を段階化すべき。

## §3 ph2 継続中に先行可能な最小タスク

ph2 を止めずに進められるものだけに限定する。

| 優先 | タスク | 目的 | 工数目安 |
|------|--------|------|---------|
| P0 | `ActionPrediction` の `features[:5]` 依存を除去（モデル observation_space / schema に完全追従） | 訓練-推論ギャップの即時是正 | 0.5-1d |
| P0 | `scripts/v460/run_experiment.py` に `sac_train` タスクの枠実装 | 001# P3-1 の前倒し | 0.5-1d |
| P1 | `FeatureSchemaManager` を v460 用に拡張（metadata 必須チェック） | ModelRegistry 重複回避 | 0.5d |
| P1 | SAC 実装依存グラフを自動出力（import 参照列挙） | 安全な deprecate 計画の土台 | 0.5d |

## §4 015 への修正提案（差分方針）

1. §8.2 の前提条件を Gate 準拠で修正（G1 PASS + G1.1 PASS 90%）。
2. §6.1 は「統一 SACTrainer を採用、環境は当面 HeavyTradingEnv 維持」に変更し、FastIntraday 移行は別フェーズへ分離。
3. §6.2 の deprecate は「即削除」から「4段階移行計画」へ変更。
4. §6.3 は新規 ModelRegistry ではなく既存 schema 基盤拡張を第一案に変更。
5. §7 は ph3 本文から分離し、`ph5_online_learning_pre_design` 相当の別文書へ移す。
6. 文書管理欄の日付・参照節番号を修正。

## §5 結論

015 は問題発見力は高いが、**Gate 整合性と実装移行順序に高リスクのズレ**がある。  
ph2 を維持しながら前倒しすべきは「推論次元ミスマッチ修正」と「v460 ランナーへの `sac_train` 実装準備」であり、オンライン学習本体は ph5 へ切り分けるのが最も安全。
