# Document 381: Critical Review of 380_fill_test_trading_improvement_analysis

## 0. レビュー方針 (Codex Surrogate Review)
本ドキュメントは、提出された `380_fill_test_trading_improvement_analysis.md` (3/4～3/11の7日間fill test分析) に対し、本来Codexが実施するはずであった厳格なコードベースおよびログ実証を伴う批判的レビュー(Critical Review)を代行するものです。

結論から申し上げますと、**380ドキュメントの市場分析は非常に鋭く有用であるものの、分析の前提条件に致命的な「Ghost Metric Paradox (存在しない指標の分析)」が含まれており、データ期間の分断による分析の歪みが発生しています。**

## 1. 致命的指摘: 存在しない指標 (`forced_buy_delay`) の分析

### 1.1 事象と乖離
380ドキュメントにおいて、`forced_buy_delay` に起因するキャンセルが389件 (全体の13.6%) を占め、これが主要な問題点として挙げられ、P1にてサイクルの削減等の対策が提案されています。

### 1.2 コードおよびGit履歴による実証
しかし、これは**存在しない指標（Ghost Metric）**です。
コードベースおよびGit履歴を確認した結果、以下の事実が判明しています。

* **Commit**: `5639943aa` (Doc 348#) 
* **日付**: 2026-03-09 (分析期間3/4～3/11の中間)
* **内容**: `balance_forced` メカニズムの全面撤廃。
  * `scripts/v460/lib/cancel_reasons.py` において、`forced_buy_delay` 関連の属性は削除済み。
  * `fill_config_parser.py` 等からも該当ロジックは完全にパージされています。

### 1.3 結論
分析期間（7日間）の前半は `balance_forced` が存在した旧アーキテクチャのログであり、後半（3/9以降）は存在しない新アーキテクチャのログです。この2つの異なるEpoch（環境）のデータセットを単純結合して集計したことで、現行システムには存在しない課題への対策を講じようとする「分析の幻覚」が発生しています。
したがって、**`forced_buy_delay` に関する対策提案はすべて棄却（対応不要）**となります。

## 2. 各提案の技術的検証と評価

Ghost Metric の問題を除けば、その他のパラメータチューニングの提案（YAML変更）はアーキテクチャの現状に即しており、非常に実用的です。

### 2.1 `sell_hour_offset_boost` の拡張 (P0指定: 承認)
* **分析の妥当性**: 時間帯（Time-of-day）によるAdverse Selectionの偏りに着目し、09h, 11h, 12h, 21h, 22h にペナルティを付与する提案は、市場理論として妥当です。
* **コードとの整合性**: `scripts/v460/lib/maker_risk_guards.py` における `sell_hour_offset_boost` のパース・適用機構を確認しました。YAMLへのキー追加のみでシームレスに動作し、副作用なく意図したロジックが発火します。

### 2.2 `offset_ceiling_ratio_buy` の厳格化 (P1指定: 承認)
* **分析の妥当性**: 現状より設定値（0.15など）を下げてスプレッド急拡時の高値掴み（Buy側の過剰追従）を防ぐ提案は、現在のボラティリティ環境に合致しています。
* **コードとの整合性**: `configs/v460/fill_test.yaml` 経由での設定変更のみで安全に適用可能です。

### 2.3 `stale_adverse_drift` 閾値の動作確認
* 380で触れられている「ドリフト時のみキャンセル」という挙動について、`scripts/v460/lib/order_monitor.py` の実装を検証しました。
* 現在の設定は `drift_bps_buy: 4.0`, `drift_bps_sell: 5.0` であり、正確に悪化方向の時のみ `CR.STALE_ADVERSE_DRIFT` によるキャンセルが発火する設計（`drift_bps >= _stale_drift and is_adverse_drift`）が担保されています。現状の設定値および機能は正常に稼働しています。
