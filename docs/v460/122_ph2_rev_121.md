- **E14: 強化学習 (SAC) の「Hold 学習」リスク (Critical)**
  ベースの期待値がマイナスの状態で SAC を導入すると、エージェントは損失を最小化するために「一切取引しない (Hold)」という局所最適解に陥る可能性が極めて高い。
- **E15: サンプルサイズとモデル複雑度の不一致 (High)**
  759 件のデータに対して、LightGBM などの複雑なモデルや多すぎる特徴量 (16+) を適用すると、次元の呪いにより OOS (Out-of-Sample) 性能が崩壊する。
- **E16: API Rate Limit の「隠れバースト」リスク (Medium)**
  OB データの取得 (Track D) と、注文・キャンセル・残高照会が同一サイクル内で重なった場合、瞬間的なバーストで 4 req/s を超過し、致命的な機会損失を生む可能性がある。

### 4. 優先度付きアクションアイテム

1. **P0 (戦略修正)**: ph3 (SAC) への移行条件を「Oracle テストでの明確なプラス収益の証明」および「Track A/B 適用後の PnL30s (または PnL120s) の黒字化」に厳格化する。
2. **P0 (実験統制)**: Track A, B, D の同時デプロイを禁止する。1週間に1 Track (または独立した1施策) のみをデプロイし、因果関係を特定できる A/B テスト環境を維持する。
3. **P1 (ML方針)**: Track B の SkipGate 再訓練において、使用するモデルを線形モデル (Ridge/Logistic Regression) に限定し、特徴量選択 (SelectKBest) の k 値を厳しめに設定する (過学習防止)。
4. **P1 (評価基準)**: Gate 判定の主軸を PnL30s から PnL120s にシフトする（120s でエッジがあることが確認されているため）。

### 5. 質問リスト

1. PnL がマイナスの状態で SAC を訓練した場合、エージェントが「Hold」以外の有意義な戦略を学習できるという理論的根拠（または勝算）はどこにありますか？
2. わずか 759 件（分割後 380 件）のデータで SkipGate を再訓練する際、過学習を防ぐための具体的な交差検証（Cross-Validation）戦略と正則化手法は何ですか？
3. Track A, B, D を同時に進めた場合、最終的な PnL の変化がどの施策によるものか、どのようにして統計的に分離・証明するつもりですか？
