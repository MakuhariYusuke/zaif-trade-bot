## §1 先に結論

ph2 再fill testに入れるモデルは、現時点では次の優先順位が妥当です。

| 優先 | モデル | 判定 | 理由 |
|---|---|---|---|
| 1 | `AS-LR SkipGate` (`mode=as`, 060/061/062系) | **採用** | walk-forward で `+0.230 bps`、TSCVで `+0.382 bps` の改善実績あり |
| 2 | 064の XGBoost direction (h5/h15) | **シャドー運用のみ** | G1公式判定ロジック未満、3fold・不安定、Baseline優位区間あり |
| 3 | 058の PnL Ridge gate | **不採用** | その後の検証で不安定/劣後。実運用優先度が低い |

## §2 064の重要論点（批判的レビュー）

### 2.1 G1判定ロジックが 000# と不整合

`scripts/v460/run_064_g1_info_verify.py:219` で判定が `abs(avg_direction_ic) > 0.02` のみになっています。  
しかし 000# §3.2 / `configs/v460/gate_thresholds.yaml` では最低でも以下が必要です。

1. IC 閾値
2. Accuracy 閾値
3. 有意 fold 数
4. 多重比較補正（Holm）
5. 効果量条件（Cliff's Delta）

064の PASS は「簡易基準PASS」であり、**公式G1 PASSとは別物**です。

### 2.2 3fold・3日データは暫定評価としては有用だが、Go判定には弱い

- `scripts/v460/run_064_g1_info_verify.py:42` で `N_FOLDS=3`
- direction系は `0/3, 1/3, 1/3` の有意foldで、安定性が不足
- h1方向は XGB が baseline を下回る（064本文表）

よって、**モデル採用根拠としては弱い**です。

### 2.3 指標の解釈に注意が必要

`scripts/v460/lib/evaluator.py` では回帰ターゲットの `accuracy` を符号一致で計算しています。  
`magnitude/volatility` は非負値主体のため、accuracy が 1.0 に寄りやすく、比較指標としては弱いです。  
064の regression `acc=1.0` は性能優位の証明にはなりません。

### 2.4 互換性のない出力形式

064 JSON は `xgb_results` / `baseline_results` 形式で、`run_gate_check.py` が期待する構造と異なります。  
実際に `run_gate_check.py --gate G1 --results-path docs/v460/064_ph1_g1_info_verify.json` では **FAIL** になります（`fold_results`/`g1_judgment_cache` なし）。

## §3 ph2 再fill test向けの実務提案

### 3.1 本投入モデル（推奨）

**AS-LR SkipGate (060/061系)**

- `mode: as`
- 初期値: `as_threshold=0.60`, `max_skip_rate=0.30`
- ただし初回は保守運用で `as_threshold=0.65` から入って良い

理由:

1. ph2課題（AS削減）に目的整合
2. walk-forward で改善確認済み
3. 062で `run_fill_test.py` への統合済み

### 3.2 064モデルの扱い

**shadow only**（ログ記録だけ、注文判定に使わない）

- 064の h5/h15 direction score を別ログ保存
- 200サイクル以上で AS-LR と同じ母集団で比較
- 優位性が確認されるまで Gate判定に使わない

### 3.3 直近でやるべき設定

1. `models/v460/skip_gate_as.pkl` を学習・保存（現状は `skip_gate.pkl` のみ確認）
2. `configs/v460/fill_test.yaml` の `skip_gate.enabled` を段階的にON
3. 他施策を固定し、SkipGate の効果だけを分離評価

## §4 判定基準（再fill testでの採用/中止ルール）

以下を 200 サイクル単位で判定するのが現実的です。

| 指標 | 継続条件 | 中止条件 |
|---|---|---|
| post_fill_30s_pnl mean | baseline比で改善 | baseline以下 |
| AS ratio | baseline比で低下 | 増加 |
| fill rate | 劣化が軽微 | 大幅悪化 |
| skip rate | 設定範囲内 | 上限張り付き |

補足: 000# のG1.1最終閾値（7日）判定とは別に、短期は「劣化しないこと」を先に確認する運用が安全です。

## §5 064から活かすべき点（捨てない）

ただし「特徴量として有望」と「今すぐ運用モデルに採用」は分離すべきです。
