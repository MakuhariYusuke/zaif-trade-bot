## 1. 結論（先に要点）

1. **現段階で 1D 維持は正しい**。  
   000# の Gate 順序（G1-info → G2-train → G3-pnl）と整合し、v451 成功パターン（簡素化）にも一致する。
2. **不足は「実装に落ちる運用層」**。  
   034 は方向性が正しい一方、`run_fill_test` の方策A/Bにレジーム文脈を接続する設計が未定義。
3. **次の打ち手は「拡張」ではなく「条件付き適応」**。  
   Action 次元を増やす前に、既存の offset/lot 適応をレジーム条件で分岐し、収益差を統計で確定させるべき。

## 3. エージェント委任パラメータの統治モデル（提案）

### 3.1 委任レイヤー

| レイヤー | 対象パラメータ | 委任可否 | 理由 |
|---|---|---|---|
| L0: Human Hard Guard | `loss_cap_jpy`, `min_lot`, `max_lot`, 緊急停止条件 | **委任禁止** | 安全境界は最終防衛線。学習主体に渡すと破局リスク |
| L1: Rule Agent (現フェーズ) | `spread_offset_ratio`, `order_quantity`, `cycle_interval_sec`, `order_timeout_sec` | **委任可（制約付き）** | 既に方策A/Bで運用可能。Gate順序を崩さず改善可能 |
| L2: RL Agent (将来) | `offset`（先行）、`lot`（後行）、`timing`（離散） | **G3通過後のみ** | v444/v456の失敗を回避するため、証拠が出るまで拡張禁止 |

### 3.2 今すぐ実装すべき委任仕様

1. `run_fill_test` の方策A/Bを**レジーム条件付き**に拡張。  
2. レジームごとに `min_samples` を持たせ、少数サンプルでの過適応を禁止。  
3. 変更ログに `regime`, `confidence`, `stability` を必須保存。  

実装起点:
- `scripts/v460/run_fill_test.py`
- `scripts/v460/lib/param_adapter.py`
- `scripts/v460/lib/lot_sizer.py`

## 4. レジーム判定の再利用設計（拡張ではなく運用強化）

### 4.1 再利用候補

| 用途 | 既存資産 | 使い方 |
|---|---|---|
| 軽量ライブ判定 | `ztb/trading/strategies/action_signal_guide/components/market_regime.py` | ph2 の fill test ループで regime タグ付け |
| オフライン基準線 | `ztb/metrics/metrics.py::classify_market_regime` | 実験後分析の共通ベースライン |
| 安定性検証 | `ztb/analysis/market_analysis/statistical_analyzer.py` | regime 変化頻度・安定性の統計検定 |
| 高粒度判定 | `ztb/analysis/regime/advanced_regime_detector.py` | ph3以降の比較対象（現時点は主系にしない） |

### 4.2 設計原則

1. **4状態から開始**（`trending / ranging / high_vol / unknown`）。  
2. **ヒステリシス導入**（連続 N サイクル一致で状態確定）。  
3. **信頼度ゲート**（confidence 低時は `unknown` 扱いで適応停止）。  
4. **レジーム別評価を必須化**（全体平均だけで判断しない）。

## 6. 範囲外も含む高収益寄与の提案

| 分野 | 提案 | 期待効果 | 実装負荷 |
|---|---|---|---|
| 執行 | 約定後 30秒ASだけでなく、約定前の「毒性フロー」フィルタ追加 | 逆選択回避の先回り | 中 |
| 執行 | サイド別オフセット学習（buy/sell 別） | 現在の buy/sell fill 差の是正 | 低 |
| データ | レジーム×サイド×スプレッド帯の三次元集計を標準化 | 何が効いているかの可視化 | 低 |
| モデル | regime を入力する前に regime を「実験タグ」として使う | 過学習回避、因果誤認抑制 | 低 |
| 運用 | Champion/Challenger（現行設定vs提案設定）常設 | 迷走防止、意思決定速度向上 | 低 |

## 7. 直近2週間の実行計画（ph2並行）

### Week 1: 計測強化

1. fill record に `regime`, `regime_confidence`, `regime_stability` を追記。  
2. 日次集計に `regime×side×offset_bin` を追加。  
3. `unknown` 比率が高い場合のフォールバック（適応停止）を追加。  

### Week 2: 条件付き適応の実証

1. 方策A/Bを regime 別閾値で A/B 実験。  
2. 判定は p-mean + Holm で統一。  
3. 以下を満たした場合のみ継続:
   - regime 別 `n_filled >= 80`
   - 主要 regime で AS_ratio 改善
   - 累積 PnL が safety cap の 70% 警戒域未満

## 9. 最終判断

`034` の主張は方向として正しい。  
次に勝ち筋へ近づく鍵は、**行動空間の拡張ではなく、既存の方策A/Bをレジーム条件付きで高解像度化すること**。
