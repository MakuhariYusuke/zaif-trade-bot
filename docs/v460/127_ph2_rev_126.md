## §0 結論（先に要点）

126# の方向性（再学習の自動化 + 無停止反映）は正しいです。  
ただし現状は、**設定と実装の接続不整合により、意図した hot-reload が実運用で成立しない構成**になっています。

最優先で直すべきは以下です。

1. **CRITICAL**: 再学習先モデルと実運用モデルのパス/モードが不一致（実質未反映）
2. **HIGH**: 再学習データが AS ラベル依存で絞られ、PnL 回帰学習にサンプル選別バイアス
3. **HIGH**: run 混在学習（run_id 未分離）による因果崩壊

## §1 重大指摘

### C1 (CRITICAL): hot-reload 経路が実運用モデルにつながっていない

**根拠**

- 実運用 SkipGate: `configs/v460/fill_test.yaml:196-199`
  - `skip_gate.mode: as`
  - `skip_gate.model_path: models/v460/skip_gate_rb30.pkl`
- 再学習書き込み先: `configs/v460/fill_test.yaml:272-275`
  - `retrain.model_path: models/v460/skip_gate_lgbm_pnl120.pkl`
  - `retrain.target: pnl120`
- 再学習モデル生成: `scripts/v460/ml/retrain_scheduler.py:370-376`
  - `SkipGateConfig(mode="pnl", use_ob_features=...)`
- 評価時 override: `scripts/v460/lib/skip_gate_evaluator.py:80-92`
  - モデル内設定を YAML `skip_gate.*` で上書き

**問題**

- `SkipGateEvaluator` が監視するモデルファイルは `skip_gate.model_path` 側であり、`retrain.model_path` 側ではない。
- そのため、現設定では再学習が回っても実運用の判定モデルは更新されない。
- さらに、パスだけ合わせて `skip_gate.mode=as` のままだと、`LGBMRegressor` に対して `predict_proba` を呼ぶ経路に入り、評価失敗で実質スルー判定化するリスクがある。

**推奨対応**

1. `skip_gate.*` と `retrain.*` の **model_path / mode / use_ob_features を同一契約で統一**。
2. 起動時に fail-fast バリデーションを追加。
   - 例: `skip_gate.mode != retrain_target_mode` なら起動停止。
3. 126# の「使い方」節に、`mode` 切替条件を明記。

---

### H1 (HIGH): PnL 再学習が AS ラベル存在行に依存しておりサンプルを不当に捨てる

**根拠**

- `scripts/v460/ml/retrain_scheduler.py:261`
  - `build_preorder_as_features(enriched)` を使用して `X_base` を作成
- `scripts/v460/ml/feature_enricher.py:497-499`
  - `build_preorder_as_features` は `filled & adverse_selected_raw.notna()` で抽出
- その後の target は PnL: `scripts/v460/ml/retrain_scheduler.py:267-278`

**問題**

- `pnl120` 回帰なのに、AS ラベル欠損行を先に落としており、学習サンプルを縮小・偏らせる。
- v460 の現状（データ不足が主課題）と逆方向。

**推奨対応**

1. `retrain_scheduler` 用に「PnL 回帰向け preorder feature builder」を分離し、  
   抽出条件を `filled & target_pnl.notna()` にする。
2. `result` に `dropped_by_as_label` を記録し、捨てた件数を可視化。

---

### H2 (HIGH): run 混在学習（run_id 未分離）で因果が崩れる

**根拠**

- `scripts/v460/ml/retrain_scheduler.py:255`
  - `load_fill_records(results_dir)` を run_id フィルタなしで読み込み
- `scripts/v460/ml/data_loader.py:43-45, 71-78`
  - run_id フィルタ機能自体は実装済み
- 118#/122# 系で既に「run 混在による交絡」を課題化済み

**問題**

- 設定やモデル世代が異なる run を混ぜると、再学習結果の意味が薄れる。
- 品質ゲートの score も run-mix の影響で不安定化。

**推奨対応**

1. `retrain` 設定に `run_id_filter` と `exclude_missing_run_id` を追加。
2. デフォルトを「最新 run_id のみ」にする。
3. `retrain_history.jsonl` に `run_id_set` を記録。

---

### H3 (HIGH): スケジューラ異常終了が観測しにくい

**根拠**

- 子プロセス起動: `scripts/v460/run_fill_test.py:1552-1556`
  - `stdout/stderr` を `DEVNULL`
- 起動後の生存監視なし（PID ログのみ）

**問題**

- 起動成功ログ後に即死しても気づきにくい。
- `retrain_scheduler.py` 側は import 時に `FileHandler("logs/retrain_scheduler.log")` を作るため、環境によっては初期化で落ちうる。

**推奨対応**

1. 起動 10-30 秒後に `poll()` でヘルスチェックし、死亡時は WARNING ではなく ERROR。
2. stderr を `results_dir/logs/retrain_scheduler.stderr.log` にリダイレクト。
3. `retrain_scheduler.py` は logging 初期化前に `logs/` を `mkdir`。

---

### H4 (HIGH): OB 特徴量契約が train/runtime で不一致

**根拠**

- 再学習側: `retrain.use_ob_features: true` (`configs/v460/fill_test.yaml:275`)
- 実運用側: `skip_gate.use_ob_features: false` (`configs/v460/fill_test.yaml:203`)
- runtime は config override を優先: `scripts/v460/lib/skip_gate_evaluator.py:91`

**問題**

- 再学習時に OB ありで学習しても、実行時に OB 無効で評価する可能性が高い。
- 期待した edge が runtime で消える。

**推奨対応**

1. `skip_gate.use_ob_features` と `retrain.use_ob_features` を単一 source に統一。
2. hot-reload 時に feature contract 差分をログ出力（`model_n_features` vs `runtime_feature_mode`）。

## §2 中程度の指摘

### M1: quality gate の比較基準が弱い

- `prev_score` が取れない場合 0.0 比較になる（`scripts/v460/ml/retrain_scheduler.py:328-335`）。
- 初回や旧モデル移行時に「悪化モデル通過」の余地がある。

**推奨**: `prev_score` 不在時は `absolute_min_score` を別閾値で要求。

### M2: `target: as30` の命名が実装とずれる

- 実装は `pnl120` 以外を `post_fill_30s_pnl` 回帰として扱う（`scripts/v460/ml/retrain_scheduler.py:267-270`）。
- `as30` は分類を想起しやすく誤運用リスク。

**推奨**: `target` 値を `pnl30` / `pnl120` に限定。

### M3: テストは防御系中心で、成功系統合の担保が不足

- `tests/unit/v460/test_retrain_hot_reload.py` は skip/fallback ケースが中心。
- 「実際に再学習→配置→hot-reload→評価成功」の E2E がない。

**推奨**: 最低 1 本、統合成功テストを追加。
