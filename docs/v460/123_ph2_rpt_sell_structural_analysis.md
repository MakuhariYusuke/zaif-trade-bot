## §3 Sell 損失の構造分解

### 3.1 Regime 別

sell は全レジームで赤字。特に **trending で -0.688 bps** と最悪。buy は trending で最善 (+0.334)。
→ trending レジームは buy にとって追い風、sell にとって逆風 (トレンドフォロー構造)。

### 3.2 Wait Time 帯別

| Wait 帯 | BUY avg | SELL avg | 解釈 |
|---|---|---|---|
| 5-10s | **+0.275** | -0.436 | buy fast fill は有利、sell は不利 |
| 10-15s | -0.341 | -0.147 | buy の中間帯が悪い |
| 15-30s | -0.516 | -0.433 | 両方悪い |
| 30-60s | -0.033 | -0.205 | 中立帯 |
| >60s | **+0.671** | **-0.723** | buy は reversion edge、sell は stale |

**buy 5-10s**: market が buy 方向に動いた直後に maker fill → reversion で利益。
**sell >60s**: 長時間放置 → informed trader に pick off される構造。

## §5 改善提案

### 優先度マトリクス

| # | 施策 | 予想効果 (bps/168h) | リスク | 過去根拠 |
|---|---|---|---|---|
| **S1** | sell time_filter: UTC 04, 15 追加 | **+65** | fill -35件 (4%) | 107# 段階廃止との整合要検討 |
| **S2** | sell offset: 0.18→0.22 | **+40** | sell fill_rate -5~8% | 121# 積極案、105# 同根拠 |
| **S3** | SG sell target_skip_rate: 0.20→0.25 | **+20** | skip 過多の機会損失 | 124.2# rb30 逆選別なし確認済 |
| **S4** | VG sell: boost 2.0→skip (VG 発動時 sell skip) | **+15** | sell 機会減少 | §3.5 VG 逆効果データ |
| **S5** | buy→buy 連続防止: sell→buy フォールバック強化 | **+25** | 実装複雑度 | §3.3 buy→buy -0.928 |

### S1: sell time_filter 拡張

```yaml
# Before
skip_utc_hours_sell: [8, 14, 16]     # 3h 遮断

# After
skip_utc_hours_sell: [4, 8, 14, 15, 16]  # 5h 遮断
```

**根拠**: UTC 04 (JST 13) avg=-2.842 n=11, UTC 15 (JST 00) avg=-1.403 n=24。
**107# との整合**: 107# は段階的「緩和」を提案したが、実データで悪化時間帯が判明したため**追加ではなく修正**。121# A1 で既に 7h→3h に緩和済であり、ここからの 3h→5h は「データに基づく再締め」。

### S2: sell offset 引上げ

```yaml
# Before
side_offset:
  sell: 0.18

# After
side_offset:
  sell: 0.22
```

**根拠**: 0.18 でも全レジーム赤字。offset 推移 0.12→0.14→0.18 の各段階で改善を確認 (-0.85→-0.632→-0.470)。0.04 追加で -0.25 程度を期待。
**リスク**: fill_rate 低下。現在 sell fill rate は高め (431/~550 = 78%) でマージンあり。

### S3: SkipGate sell skip_rate 引上げ

```yaml
# Before
target_skip_rate_sell: 0.20

# After
target_skip_rate_sell: 0.25
```

**根拠**: 124.2# で rb30 の sell 逆選別解消を確認。skip を増やして悪トレードをより積極的に排除。
**118# 経緯**: 旧 LR モデルでは sell SG が逆選別 → 118# で sell_enabled=false → 124.2# rb30 で再有効化。rb30 での skip 効果は warm-start 後のデータ蓄積を待って再評価。

### S4: VG sell skip 化

```yaml
# Before (offset boost のみ)
volatility_guard:
  offset_boost_factor: 2.0

# After (sell 側は skip 化)
volatility_guard:
  offset_boost_factor: 2.0
  sell_skip_on_guard: true    # 新パラメータ
```

**根拠**: §3.5 で VG 発動時の sell PnL が -0.728 (非発動 -0.412 より悪化)。boost では不十分 → skip が合理的。
**実装**: `skip_gate_evaluator.py` に VG 状態参照を追加。YAML に `sell_skip_on_guard` フラグ。

### S5: buy→buy 連続防止

**問題**: BTC 残高不足 → sell 不能 → buy 連続 → 同方向 inventory 蓄積 → -0.928 bps。
**対策案**: `max_consecutive_same_side` パラメータ (例: 3) 超過で SKIP → inventory rebalance 待ち。
**過去**: `smart_side` (054# S2) が類似目的だが `max_consecutive_same: 2` で `enabled: false`。再有効化を検討。

### S6/S7: 追加保守化

S1-S5 の効果確認後に検討。現時点では 168h 測定の純度を優先し、変更数を最小化すべき。

## §6 実装優先度と順序の提案

### Phase A: 即時適用 (YAML 変更のみ、コード変更なし)

- **48h 確認**: S1+S2 適用後 48h のデータで sell PnL avg > -0.25 を確認してから Phase B へ。

## §8 レビュー依頼事項

以下の観点でのレビューを求める:

1. **S1 time_filter 拡張の妥当性**: UTC 04/15 追加は 107# の「段階的緩和」哲学と矛盾しないか。データ量 (n=11, n=24) は統計的に十分か。
2. **S2 sell offset 0.22 の根拠**: 0.18→0.22 の +0.04 は収益改善に見合うか。fill_rate 低下の予測精度。
3. **S4 VG sell skip**: VG が逆効果というデータは、VG 自体の問題か市場環境の問題か (生存バイアス: VG が防いだ「さらに悪い取引」が見えない)。
4. **S5 buy→buy 防止**: 054# smart_side 再有効化 vs 新規実装のどちらが適切か。
5. **Phase A のみ先行** vs **Phase A+B 一括適用** のどちらが 168h 測定に適切か。
6. **全体**: 本分析で見落としている重要なパターンや、過去ドキュメントで既に解決済みの問題を重複提案していないか。
