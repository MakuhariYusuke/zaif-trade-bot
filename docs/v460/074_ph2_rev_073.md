## §3 073 を前進させる改訂実行順（提案）

### Step 1: 評価基盤の修復（最優先）

1. `run_single_cycle(side_override=...)` 方式に変更し、`run_continuous()` で決めた side を強制適用。  
2. 073分析スクリプトの入力を clean/quarantine 分離し、両方の結果を併記。  
3. S12 の `sim_pnl` 参照バグを修正。S6 は「戦略」表から外すか実際の test 反映ロジックを追加。

### Step 2: 判定ルールの整合

1. 30s KPIを Gate 判定の主軸に固定、60s/120s は補助指標として別枠管理。  
2. 戦略採否は平均値だけでなく Holm + Cliff + p-mean の AND 条件に変更。  
3. pass_rate 下限（例: 70%）と最低サンプル下限（例: foldごと n>=30）を追加。

### Step 3: 実運用に繋がる検証へ転換

1. queue_wait 依存の事後戦略は「示唆」扱いに下げ、事前利用可能特徴量のみで再設計。  
2. side 別 filter は時間帯固定ではなく、週次更新の rolling 推定へ移行。  
3. manifest + JSON artifact を残し、再計算可能なレビュー体制に統一。

## §5 最終提言

`073` は方向性として有望ですが、現状のままでは「評価基盤の歪み」が大きく、結論の採用は早計です。  
**まず基盤修復（side 適用整合・clean分離・統計検定）を完了し、その後に戦略比較を再実行**するのが最短です。  
この順序なら、v459〜v460で積み上げた資産をほぼ無駄なく統合できます。
