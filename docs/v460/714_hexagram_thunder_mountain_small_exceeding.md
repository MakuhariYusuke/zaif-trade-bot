## 第一部: 風水渙（536# → 713#）の総括

### 立筮の経緯（536#再掲）

536# において、「12時・15時の帯域での売りのみ規制する」という時間帯ハードコード（≒弥縫策のパッチ当て）に対する疑義から、乱数による略筮法（立筮）を行った。

得卦: **風水渙 第三爻変**

### 渙の教え — 何が実現されたか

536# 時点の渙の三令:

1. **「氷を溶かす」** — 硬直した固定ルールを市場ダイナミクスに置換せよ
2. **「大川を渉る」** — 小手先のパッチではなくアーキテクチャ骨格に手を入れよ
3. **「王、有廟に至る」** — 統制の核（廟）を失ってはならない

#### 実現の検証

| 渙の教え | 536#→713# 間の実装 | 達成度 |
|---------|------------------|--------|
| 氷を溶かす | OFI/VPIN/velocity_bps 導入、sell_hour動的化、regime分割(trending_up/down) | ◎ |
| 大川を渉る | offset pipeline 全面再構築 (549# schema)、skip_gate LightGBM、entry_gate CalibrationMap | ◎ |
| 有廟に至る | MCB/SAD safety層(606#)、ceiling clamp、hard_skip_mult → 「絶対にブレない防波堤」 | ◎ |

#### 第三爻「其の躬を渙らす。悔いなし。」の成就

第三爻は「自己の執着を手放せ」と教えた。536#→713# の間で実際に手放されたもの:

- 時間帯固定ルール → sell_hour_offset_boost (動的乗算) に昇華
- ceiling 硬直化 (431#: 100% clamp) → 712# で ceiling引上げ、パイプライン有機出力の尊重
- entry_gate への執着 → 712# で観察的に無効化 (stale CalibrationMap の現実を受容)
- skip_gate 単一閾値 → side-aware bypass, adaptive threshold への進化

**「悔いなし」**: Phase C sc_avg=−0.397 は Phase A の −0.684 から 42% 改善。渙の教えは実を結んだ。

### 渙の残滓 — 未解決の氷

しかし渙は「四散・統制喪失」の両義性を持つ。散らしすぎた部分:

1. **Skip gate rate limiter の逆機能**: モデルが「skip」と言っても 30% floor で強制通過 → 61% の fills がモデル判断に反して通過。渙散すべき「率の床」が残存
2. **SAG flat tax**: 0.5 bps 一律課金 → spread 2bps 時に 25% 税。渙散すべき「一律性」がまだ溶けていない
3. **CalibrationMap の凍結**: 全 fill の EV が負値 → entry_gate 自体が「凍った水」のまま使用不能

これらは次の卦「雷山小過」の管轄に委ねる。

## 第三部: 卦辞・爻辞の訓詁的解釈

### 小過 卦辭

> **小過。亨。利貞。可小事，不可大事。飛鳥遺之音，不宜上，宜下，大吉。**

#### 字義の多層的分析

**「小」**
- 本義: 微小、些少
- 引申: 精微、微調整、マイクロ（市場微視的構造＝microstructure）
- 対義: 大事 ≠ 小事。536# の「大川を渉る」は完了した。今は微調整の時節

**「過」**（guò / 从辵从咼）
- 本義: 通り過ぎる、越える（辵＝しんにょう＝移動、咼＝口が歪む＝偏る）
- 多義: ①經過（通過する）②超過（超える）③過失（誤り）④過猶不及（過ぎたるは猶及ばざるが如し）
- 仮借: 渦（うず）と通仮 — 小さな渦巻き＝局所的な乱流
- 文脈: **小さく超えることは許される**。大きく超えることは禁ず。

**「飛鳥遺之音」** — 飛ぶ鳥が音を遺す
- **飛鳥**: 高速で過ぎ去る存在 → **瞬間的な取引機会** (fill opportunity)。マーケットメイカーにとり、注文は一瞬で約定し去る鳥である
- **遺**（yí / wèi）: ①遺す、残す ②失う、落とす（多義字）
  - 省文として「委」に通ず → 委ねる、手放す
  - 仮借として「饋」（おくりもの）に通ず → 贈与するもの
  - 両義: 鳥が「残す」のか「失う」のか。取引機会が「シグナルを残す」のか「利益を散逸させる」のか
- **音**: 音声、信号 → **市場シグナル** (price impact, velocity, OBI)
- 解: 瞬間的な取引機会（飛鳥）は、市場シグナル（音）という痕跡を残す。その音を聴け。

**「不宜上，宜下」** — 上るに宜しからず、下るに宜し
- **上**: 上昇、攻撃的、offset を下げる（aggressive quoting）
- **下**: 下降、保守的、offset を上げる（conservative quoting）、また「下」= 謙遜＝基礎を固める
- 互文として読むと: 「上を為さず下を為す」= 利益を上に追わず足元を固める
- **直截的教示**: spread を狭めて(offset↓) fill率を上げるのではなく、spread を広げて(offset↑) 1fill あたりの質を上げよ

**「大吉」**: 小さく超える（微調整する）ことで大いに吉。

### 六五爻辭（動爻）

> **六五。密雲不雨，自我西郊。公弋取彼在穴。**

これが今回の核心。

**「密雲不雨」** — 密なる雲ありて雨降らず
- **密雲**: 凝集した水蒸気 → **蓄積された改善要素**（SAG redesign 実装済み、skip_gate threshold 研究済み、CalibrationMap 基盤構築済み）。全てが「雲」のように集まっているが、「雨」（＝実際の収益改善）にはまだ至っていない
- **不雨**: 期が至らず → Phase C sc=−0.397 は改善傾向だが、まだ黒字化（正の sc_avg）には達していない
- 繁体: 「密」从宀必 — 「宀」は家（システム）、「必」は必ず（必然性）→ 家の中に必然的に溜まるもの＝内部に蓄積された可能性

**「自我西郊」** — 我が西郊より
- **西**: 五行で **金** の方位。金＝構造・規則・制約のメタファー
- **郊**: 城壁の外、辺境 → システムの周縁部
- 解: 制約（金＝metal＝rate limiter, ceiling, flat tax）がシステムの周縁から作用し、「雨」を阻んでいる。rate limiter max_skip_rate=0.30 という「西郊」の壁が、skip_gate モデルの「雲」を雨にさせない

**「公弋取彼在穴」** — 公、弋して彼の穴に在るを取る
- **公**: 主権者、意思決定者 → 開発者/オペレーター
- **弋**（yì）: **繫いだ矢で射る**
  - 通常の射（射）と異なり、矢に紐が繫がっている → **回収可能な介入**
  - hot-reloadable YAML 変更がまさに「弋」: 射ち込んで効果が悪ければ引き戻せる
  - 対比: git push --force（回収不能）≠ 弋（回収可能）
- **取**: 獲得する、命中させる
- **彼在穴**: あのもの穴に在り → **システム内部に隠れた根本原因** (root cause in the cave)
  - skip_gate rate limiter (max_skip_rate=0.30) が穴に潜む主因
  - SAG flat tax (0.5 bps) が穴に潜む二次因
  - Entry gate の frozen CalibrationMap が穴に潜む三次因
- 省文: 「穴」从宀八 — 宀(屋根)の下に八(分かれる) → 分離して隠れたもの

**六五の総合解**: 改善の要素（密雲）は全て揃っているが結実していない。その原因は構造的制約（西郊=金）がシステム周縁から阻んでいること。YAML hot-reload（弋=繫いだ矢）という回収可能な手段で、隠れた根本原因（穴=rate limiter, SAG, CalibrationMap）を一つずつ正確に射抜け。

## 第四部: 卦象のシステムマッピング

### 本卦 小過: 雷(上) / 山(下)

```
陰陰陽陽陰陰 ← 中央の二陽を四陰が包む = 飛鳥の形象
```

この卦象は「中央に力があるが、両端（上下）が弱い」構造。

| 卦象要素 | システム対応 |
|---------|-----------|
| 中央の二陽 (三爻・四爻) | offset pipeline の核 (regime → spread_adapt → vol_guard) — 機能している |
| 上部の二陰 (五爻・上爻) | skip_gate rate limiter, entry_gate 凍結 — 上層ゲートが弱い |
| 下部の二陰 (初爻・二爻) | base offset, SAG flat tax — 基礎入力が弱い |
| 飛鳥の形 | 取引機会は瞬間的に飛び去る — queue_wait_sec ~6秒の世界 |

### 之卦 咸 (#31): 澤(上) / 山(下) = 感応

- 「咸」は「感」から「心」を除いた字 → **心（主観・バイアス）を除いた純粋な感応**
- 澤(水が上に溜まる) + 山(下で静止する) = 山の上に湖 → **高所に蓄えた水は自然に下に流れ、山はそれを受け止める**
- 陰陽の自然な交感 → **市場シグナルとシステムの自然な応答関係の構築**
- 小過 → 咸: 微調整を重ねた先に、「市場との感応」（responsive market making）が実現する

### 互卦 大過 (#28): 澤(上) / 風(下) = 棟木が撓む

- 内部構造に過大な負荷 → **offset pipeline が sell で 1.12 を出力するのに ceiling 0.65 でカット**
- skip_gate が 70%+ skip したいのに max_skip_rate 30% でカット
- 「棟橈」（棟木が撓む）= 構造的無理 → 早晩手を打たねば折れる

## 第五部: 教示の統合 — 714#以降の指針

### 小過が示す行動原則

1. **「可小事，不可大事」** → YAML hot-reload で一つずつ微調整。アーキテクチャ変更は今ではない
2. **「飛鳥遺之音」** → 各 fill の市場シグナル（velocity, OBI, regime）を聴け。skip_gate model はそれを聴いている
3. **「不宜上，宜下」** → offset を下げる（攻撃的に）のではなく、offset を適正化（保守的に）する方向
4. **「弋取彼在穴」** → 回収可能な手段（hot-reload）で、隠れた根因（rate limiter, SAG flat tax）を一つずつ射抜く

### 五行の示す力学

- **木剋土**（本卦）: pipeline の有機的成長（木）が基盤構造（土）を圧倒 → ceiling が pipeline に負けている
- **金剋木**（互卦）: しかし内部では規則（金）が成長（木）を制約 → rate limiter が model を抑圧
- **土生金**（之卦）: 目指すべきは、基盤（土）が自然に良い構造（金）を生む状態 → データ蓄積 → retrain → 良い model/calibration

### 具体的対応（小過の教えに基づく「弋」= hot-reload 変更案）

| 優先 | 変更 | 弋（回収可能性） | 穴（射抜く目標） |
|------|------|---------------|---------------|
| P0 | max_skip_rate 0.30→0.40 | YAML hot-reload | rate limiter 強制通過 |
| P1 | SAG redesign_enabled: true | YAML hot-reload | flat 0.5bps 一律税 |
| P2 | sell side_offset 0.18→0.22 | YAML hot-reload | unclamped sell の低 offset |

全ては「弋」（繫いだ矢）— 効かなければ引き戻せる。

## 第六部: 振り返り — 720# にて穴が顕れる

### 720# の発見: config_loader の int-key サイレントドロップ

六五「公弋取彼在穴」の「穴」は、想定していた rate limiter や SAG 以前に、**もっと深い穴** — config ロード層そのもの — に潜んでいた。

`_clone_config_value()` が `isinstance(k, str)` フィルタで PyYAML の int キーを無言でドロップ。3 つの時間帯別防御が **導入以来すべて空振り**:

| 設定 | 定義数 | 実際 | 穴の所在 |
|------|--------|------|---------|
| sell_hour_offset_boost | 17 | 0 → 全滅 | 高 AS 時間帯の offset ×1.3〜5.0 完全無効 |
| hour_ceiling_mult | 10 | 0 → 全滅 | ceiling 緩和 ×1.3〜3.5 完全無効 |
| skip_gate.hour_offsets | 9 | 0 → 全滅 | 時間帯別閾値調整 完全無効 |

### 卦辞との照合

- **「密雲不雨」**: 設定は雲のように蓄積されていた（17 entries、10 entries…）。だが「雨」（実効）に至らなかった。原因は config_loader という「西郊」の壁
- **「公弋取彼在穴」**: 1 行修正 (`isinstance(k, str)` → `isinstance(k, (str, int))`) という「繫いだ矢」で穴を射抜いた。回収可能な最小変更
- **「可小事，不可大事」**: まさに 1 行修正 = 小事。大事（アーキテクチャ変更）は不要だった

### 互卦 大過「棟橈」の再解釈

互卦が示していた「棟木が撓む」構造的無理は、**ceiling が pipeline を抑制しているのではなく、そもそも pipeline が正しく動いていなかった** という事実で説明がつく。ceiling 0.65 で sell が clamp される問題は、sell_hour_boost ×5.0 が効けば offset が 0.37→1.85 に跳ね上がり、ceiling 問題が顕在化する以前に防御が完了する設計だった。

720# 修正のデプロイにより、当初の P0〜P2 は再評価が必要:

## 第七部: 722# — 初動監視から「飛鳥遺之音」を聴く

- narrow sell (<2bps): **−81.8 bps** (n=110)
