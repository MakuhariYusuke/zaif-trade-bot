## §3 見落とし事項（重要）

### O1. サンプル要件未達のまま強結論を出している

`000#` §3.3 では、暫定判定でも `n>=200` かつ 3暦日カバーが条件です。  
現状は n=95・1日であり、方針転換や閾値改訂の根拠には不足です。

### O2. E4判定が仕様とズレている

`ztb/metrics/fill_quality.py` の E4 は、`mean<0` でも p値が有意でなければPASSです。  
019のE4 FAIL表記は、`009#` §2.4 / `000#` §3.3 注記と不整合です。

### O3. cancel理由の証拠トレース不足

019は post_only reject を主因としていますが、既存 JSONL には `cancel_reason` が記録されていません。  
「推定」ではなく「証拠」で進めるには、cancel分類の恒久ログ化が必要です。

### O4. データバージョン管理不足（再現性リスク）

n=85とn=95が混在しており、同一実験セットの境界が曖昧です。  
`run_id` / `config_hash` / `git_sha` をFillRecord側に持たせ、比較単位を固定すべきです。

### O5. 指標定義変更（AS deadzone）のガバナンス不足

AS定義を deadzone 付きに変更するなら、**E5(raw)** と **E5(deadzone)** を分離しないと比較不能になります。  
単一E5を差し替えると、Gate履歴比較でバイアスが入ります。

## §4 方策（優先順位つき）

### P0（即時実施）

1. `019` のE4表記を「要再判定」に修正し、判定ロジック準拠へ統一。  
2. FillRecordへ `run_id`, `config_hash`, `git_sha`, `cancel_reason` を必須保存。  
3. `run_fill_test.py`で `status in (cancelled, rejected)` の場合も cancel_reason を確定記録。  
4. 判定レポートに「n<200または3暦日未満は暫定」の明示を強制。

### P1（次バッチ）

1. offset比率グリッド実験（例: 0.05/0.1/0.2/0.3）で、`fill_rate` と `spread_edge` のパレートを取得。  
2. side非対称制御（上昇相場時のsell条件強化、またはsell側offset拡大）。  
3. E5は `raw` と `deadzone` の2軸で並行監視し、閾値改訂は n>=500 後に判断。

### P2（方針）

- 019の選択肢では、**C案（レジーム判定導入）+ D案（現閾値維持で再計測）** を推奨。  
- **B案（AS閾値を50%へ緩和）** は、現時点では時期尚早（Gateの意味を失いやすい）。
