## 1. 概要 (Overview)

「SACに全てを任せる (End-to-End)」から「Sidecarによる方向予測 ＋ ルールベースの執行・安全装置」へとアーキテクチャが分離されたことで、**「特定のエッジパターンの検知」を独立したモジュール（弱学習器やルール）としてプラグインできる**ようになりました。

本ドキュメントでは、既存のコードベース（BitFlyer回線、板情報の取得、Ensemble機構など）を流用しながら、Maker戦略特有の死地を回避・利用する4つの高度なストラテジーについて、具体的な実装の方向性をまとめます。

## 2. Toxicity（毒）の予測と回避（★ 最優先バックログ）

**概念**: 「価格の上下」ではなく、「これから飛んでくるTaker注文が有毒か（情報を持っているか）」を推測し、Adverse Selection（逆選択）を避けます。

**既存実装とのリンク**:
現在の特徴量生成パイプラインには `trade_flow`（歩み値の偏り）や、短期の `volatility` が含まれており、さらに `scripts/v460/ml/as_classifier.py` には教師あり分類の足場が既に存在します。G1-info で用いている XGBoost などを使い、ターゲット変数を「次1分間のリターン」ではなく、**「次の1分間に自分のMaker指値が貫通されて、かつ30秒後に含み損になる確率 (`prob_toxic`)」**として二値分類モデルを学習させます。

**実装イメージ**:
- **学習**: `fill_records` の `post_fill_30s_pnl < 0` かつ `filled == True` のデータを正例（毒）として教師あり学習。
- **作動**: Sidecarの出力に `prob_toxic` を追加。
- **執行側 (`fill_cycle_executor.py`)**: `prob_toxic > 0.8` の場合、Alpha（買い・売り）のシグナルがどうであれ、**Hard Skip（参加見送り）または スプレッドの極端な拡大（Deep Quote）**を強制発動させます。

## 3. タイムマシン・アービトラージ (BitFlyer データの活用)

**概念**: 大規模・高流動性な市場（現在接続済みのBitFlyer等）の価格変動をカンニングし、遅延して追従する市場（Coincheck等）での1分足の意思決定に先行指標として使います。

**既存実装とのリンク**:
当プロジェクトには既に取引所の抽象化レイヤーがあり、BitFlyerのAPIクライアント（Public APIからの板・価格取得）が配線済みです。このデータをCoincheck等の約定判定の「直前」に特徴量として非同期ブレンドすることが十分に可能です。

**実装イメージ**:
- **特徴量追加**: `bf_cc_spread_bps` (BFとCCの価格乖離) や `bf_price_velocity_1s` (BFの直近1秒の価格加速度)。
- **作動**: BFで急激な買い（Taker Buy）の連続が発生し、CCがまだ動いていない瞬間を検知します。
- **執行側**: この「タイムマシン・フラグ」が立った場合、直ちにCCでの売り指値をキャンセル（または後退）させ、買い指値を最前線に配置します。Sidecar の `aggressiveness_hint` を跳ね上げる形になります。

## 4. キュー・マネジメント (Queue Position Estimation と 板情報のハック)

**概念**: 自分が板のどの位置（先頭か、最後尾か）にいるかを推定し、「最後尾の時に巨大な成行が来て食われる＝大底での最悪な約定」を回避します。

**既存実装とのリンク**:
CoincheckのOrderbook（L2板情報）をミリ秒〜秒単位で取得する機能と、自分の `make_order` を投げる `executor` が存在します。

**実装イメージ**:
完全なミリ秒単位のPublic Tape引き算は難しくとも、「疑似キュー管理」は今の板情報から実現できます。
1. `make_order` 実行時: 投入対象価格の現在の板の厚さ（Volume）を記録 (`snapshot_front_volume`)。
2. **監視 (`orchestrator_mid_cycle.py`)**:
   - 定期的に板情報を再取得し、対象価格のVolumeが `snapshot_front_volume` を大きく下回った（自分の前にある板が食われた、あるいはキャンセルで逃げた）かどうかを監視。
   - もし「自分の前の盾（他人の指値）が急激に消えた」ら、自分の注文が「最前列（丸裸）」になったサインです。
3. **安全装置**: 流動性が薄い状態で最前列に取り残された場合、即座に注文を取り消し、状況を再評価します。

## 5. 愚者の合議制 (Ensemble of Weak Learners)

**概念**: 単一の複雑なSACモデルがレジームチェンジに弱いのに対し、複数のシンプルで独立した判断基準（ルール＋軽量ML）の多数決で注文の安全性を担保します。

**既存実装とのリンク**:
既に `ztb/models/ensemble/` などアンサンブル周りの実装や、`walk_forward_as.py` のような複数モデル評価機構が存在しています。これをSACだけでなく「異種混合アンサンブル」に拡張します。

**実装イメージ**:
`Sidecar` を単一モデルではなく **「Committee（委員会）」クラス**に改修します。
- **委員A (Toxicity XGBoost)**: 「今は毒がないか？」 -> 安全(1) / 危険(0)
- **委員B (BitFlyer タイムマシン)**: 「グローバルの逆風はないか？」 -> 順風(1) / 逆風(0)
- **委員C (Orderbook 形状ルール)**: 「直近の板の厚さは十分か？」 -> 十分(1) / 枯渇(0)
- **委員D (SAC Alpha)**: 「方向性はどっちか？」 -> 買い(1) / 売り(-1)

**執行側 (Aggregator)**:
例えば「委員A, B, C 全てが 1 (安全) を返した時のみ」、委員D(SAC)の方向に従ってアグレッシブに指値を出します。一人でも危険を知らせた場合、即座に保守的オフセット（The Final Clampによる制限）を適用または `Hard Skip` します。
