## 1. 実施済みの Git 最適化報告

直前のセッションにて、肥大化した Git インデックスの軽量化と、不要なバイナリ/一時ファイルの整理を実施した。

### 1.1 物理的な軽量化 (git gc)
- **結果**: 12万件を超える Git オブジェクトの再圧縮とアグレッシブなクリーンアップ (`git gc --aggressive`) を実施。リポジトリ操作のレスポンス向上を意図。
- **背景**: 過去のファイル消失・再追加の過程で不要なオブジェクトがインデックスに滞留していた可能性を解消。

### 1.2 追跡対象の整理 (Untracked / Unstaged)
- **実験結果の除外**: `optimization_results/` および `experiments/` 以下の計 130+ ファイルを Git 追跡から解除。これらは `.gitignore` に追加され、今後はローカル成果物として扱う。
- **不要バイナリの削除**: `tests/benchmark/` 以下の冗長な比較用画像 (.png) を削除。
- **ルート直下の整理**: `test_results.json` 等のテスト関連ファイルを `temp/` へ移動し、ルートの視認性を確保。

## 2. 構造的負債とアーキテクチャ上の「気づき」

Git 整理の過程で、今後の開発（特に Codex/Copilot による自動開発）を阻害する可能性のある構造的課題を特定した。

### 2.1 モジュール定義の二重化 (CRITICAL)
- **現象**: `mypy` により `scripts/v460/lib/` と `ztb/` 以下のモジュールが、異なるパッケージ名で二重に認識されている。
- **リスク**: 型検査のバイパス、インポート時の予期せぬ挙動、同一ロジックの二重修正（ドリフト）の原因となる。
- **提案**: **106# R5 (lib → ztb 移行)** を優先し、`v460/lib` 以下のコアロジックを `ztb/` 配下の正規の階層へ一本化すべきである。

### 2.2 God Object の臨界点
- **対象**: `RewardCalculator` (2250行+), `UnifiedTrainer` (2800行+), `MakerPrice` (1600行+).
- **状況**: `MakerPrice` については 550# にて分割・整理が進んでいるが、依然として単一ファイル内の責務が多岐にわたる。
- **提案**: コードベースが 4,500 ファイルを超える規模となった今、単一ファイルの行数制限（例: 500-800行）を厳格に適用し、Mixin や Strategy パターンへの分解を加速させる必要がある。

### 2.3 設定 (YAML) と実装のドリフト
- **気づき**: `fill_config.py` 内のデフォルト値と `configs/v460/fill_test.yaml` の不整合（ドリフト）が、過去の修正履歴において散見される。
- **提案**: YAML を SSOT (Single Source of Truth) とし、ソースコード側でマジックナンバーやデフォルト値を保持せず、実行時に厳格なスキーマ検証（Pydantic 等の導入も検討）を行うべきである。

## 3. 今後の戦略案: 「アーカイブ化」と「身軽さの維持」

プロジェクトの規模が拡大し続ける中で、開発効率を維持するための戦略。

### 3.1 過去資産のコールドストレージ化 (Proposed)
- **概要**: 1,300 ファイルを超える `docs/` や、過去フェーズの `ztb/` 資産のうち、現在「生きていない」ものを `archived/` ディレクトリへ物理的に隔離し、Git 追跡から外す。
- **目的**: IDE のインデックス作成、`grep` 検索、AI のコンテキスト読み込みを「現在の関心事」に集中させる。

### 3.2 可観測性の質的向上
- **概要**: 単なるログ出力ではなく、意思決定パスの「因果」を `FillRecord` により濃密に記録する方向性（555# CalibrationMap 等）を支持。
- **補足**: `DecisionPath` フィールド等の拡充により、後日の事後分析を「推測」ではなく「事実」ベースで行えるようにする。

## 4. AI エージェントへのメッセージ (Codex / Copilot)

- **Git 運用**: `git add .` は引き続き禁止。整理された `.gitignore` を尊重し、成果物は適切なディレクトリへ。
- **リファクタリング**: 550# での `MakerPrice` 分割をモデルケースとし、他の God Object にも同様の外科的処置を検討されたし。
- **型安全**: `Any` 型の混入は、大規模リポジトリにおけるリファクタリングの最大の障壁となる。徹底した型定義を求める。
