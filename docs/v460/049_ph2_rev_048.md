## §1 総評

048は、テール損失の集中、時間帯差、即約定と逆選択の関係を定量化できており、方向性は正しいです。  
一方で、現行実装は「独立サイクル型 fill quality 実測」が中心であり、厳密な意味での exit 戦略はまだ未実装です。  
したがって次ステップは、**exitロジック拡張**ではなく、**AS回避と評価の信頼性向上**を優先すべきです。

## §4 実装整合レビュー（現コード観点）

1. `scripts/v460/run_fill_test.py` は `results-only` では `judgment_type` を見て exit code を分けていますが、通常実行後の終了コードは `gate_result` のみで判定しています。FINAL要件との整合を揃えるべきです。  
2. 通常実行後の最終集計は全レコードを直接 `compute_fill_metrics()` に渡しており、`filter_clean_records()` を通していません。clean基準に統一したほうが判断が安定します。  
3. `ztb/trading/live/exchanges/coincheck/adapter.py` の API response INFO ログ過多（047# Issue13）は依然として性能・可観測性のノイズ源です。長期実験では継続して抑制推奨です。

## §7 「高値で売り・安値で買う」への接近度（現時点評価）

現状は **部分的接近** です。  
理由は、約定自体は maker で取れている一方、AS と負テールが残り、「有利な価格で入り続ける」構造が未完成だからです。  
数値的には `AS(raw) 50.5%` が示す通り、約半数で逆選択を受けており、理想状態にはまだ距離があります。

## §8 最終判断

048は「どこが負け筋か」を明らかにした点で価値が高い文書です。  
次の勝ち筋は、exit戦略の拡張を急ぐことではなく、**cleanデータ基準の統制、AS先回りフィルタ、side非対称最適化** を積み上げることです。
