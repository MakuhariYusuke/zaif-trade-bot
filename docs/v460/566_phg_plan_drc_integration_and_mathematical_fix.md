## 0. レビューを受けた総括：単一因果論の超克

562#–564# のレビューを経て、本システムの不調は「Ceiling の値」という表面的な問題ではなく、**「オフセット算出パイプラインの数学的構造」と「在庫管理モデルの基本無視」** という二重の構造的欠陥に起因することが明らかになった。

本稿では、四者の議論を統合し、執行エンジンの生存圏を再定義する最終設計案を提示する。

## 1. 他エージェントの指摘に対する「データ探偵」の回答

### 1.1 「Buy 側主犯説」への反論 (vs 562#/563#)
レビューでは Buy 平均 PnL (-0.43bps) の低さを指摘されたが、これは「Zaif 固有の価格遅行（Basis Skew）に対し、海外市場（CV）の攻め（Tighten）を適用しすぎた」ことによる **「質の低い約定の量産」** である。対して、Sell 側の AS (36.4%) は **「物理的な逆選択（Toxic Flow）」** によるもの。
- **結論**: Buy 側は「CV Tighten の無効化（攻めるのをやめる）」で解決するが、Sell 側は「執行アルゴリズムの動的化」という外科的手術が必要。

### 1.2 「乗算連鎖の爆発」の受理 (vs 564#)
9段の乗算パイプライン（$1.2 \times 1.3 \times \dots$）が Ceiling 衝突の真因であるという 564# の指摘を全面的に支持する。
- **解決**: 指数的な増幅を抑制するため、**「加法的（Additive）リスクスコア」** への移行を設計に盛り込む。

## 2. 最終設計案：Exponential DRC (eDRC)

報酬による罰を完全に放棄し、執行エンジンの物理的な「回避能力」を極大化する。

### 2.1 指数的天井関数の導入
$$Ceiling_{dynamic} = Base\_Ceiling \cdot \exp\left( \alpha \cdot \frac{\sigma_{1min}}{\max(Spread_{bps}, \epsilon)} + \beta \cdot |OFI_{adverse}| \right)$$
- **$\exp$ の採用理由**: 天井を非線形に「青天井」方向へ逃がすため。これにより、高ボラ局面で Ceiling 衝突による「強制約定」が発生する確率を理論上ゼロに近づける。

### 2.2 在庫補正（inv_skew）の Regime 独立化
トレンド発生時に在庫補正を切るという現行コード（249#）の **「アンチ・金融工学的」** 実装を廃止する。
- **仕様**: トレンド時こそ在庫 $q$ に基づき、Reservation Price を非対称にシフトさせる。これにより `preflight_insufficient` の 12.8% を占める「在庫枯渇による不戦敗」を解消する。

## 4. 自己点検：この設計の「最後の死角」

- **約定率の激減**: 指数的天井により、荒天時にオフセットが 1.0 (100bps) を超える可能性がある。これは実質的な「取引停止」を意味するが、**「損をするなら止まったほうがマシ」** というユーザー様の理念（大義）に合致すると判断する。
- **パラメータ $\alpha, \beta$ の最適化**: この定数を間違えると、静かな相場でも過剰に逃げてしまう。初期値は 560# の clamped PnL から逆算して設定すべき。
