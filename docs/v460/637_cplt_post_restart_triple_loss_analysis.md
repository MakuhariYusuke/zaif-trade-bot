## 3. 三重構造損失の特定

### 3-1. 壊滅的逆選択フィル（最大原因: -43.81 JPY）

2 件の catastrophic loss が全損失の **126%** を占める:

#### Trade A: 09:31 buy/ranging, PnL = -28.02
| 属性 | 値 | 判定 |
|------|-----|------|
| spread_bps | 1.78 | **狭い → 利益余地なし** |
| fill_prob | **5.2e-06** | **実質 0% → 純粋な逆選択** |
| wait_sec | 27.8s | **長い → 約定前に相場が通過** |
| regime_confidence | 0.69 | 低い（ranging 確度弱い） |
| sidecar | **stale** | ML 不参加 |
| skip_gate_score | +1.16 | pass（検知失敗） |
| decision_path | primary_only | EV モデル未使用 |
| macro | weak_up | 弱い上昇トレンド中の buy |

**メカニズム**: 買い注文を出した後、市場が急落してオーダー価格まで到達 → fill_prob=5.2e-06 は「注文板の位置からは絶対に約定しない」ことを意味 → 市場がオーダーを**貫通**して約定。sidecar が stale で ML 保護なし。skip_gate は買い側のシグナルが弱く検知不能。

#### Trade B: 13:49 sell/ranging, PnL = -15.79
| 属性 | 値 | 判定 |
|------|-----|------|
| spread_bps | 2.71 | 中程度 |
| fill_prob | 1.0 | 通常（逆選択ではない） |
| wait_sec | 6.1s | 短い |
| skip_gate_score | **-1.26** | **スキップ判定 → レートリミッター強制通過** |
| ev_score | **-2.92** | **損失を予測していた** |
| gate_reason | **skip_rate_limit(35%>30%)** | 30% 上限到達で強制実行 |
| decision_path | ev_offset | EV 補正使用したが不十分 |

**メカニズム**: skip_gate は score=-1.26 でスキップを判断。EV モデルも -2.92 で損失を正確に予測。**しかし**、sell 側のスキップ率が 35% に達し、`max_skip_rate: 0.30` のリミッターが発動 → 保護判定を無効化して強制実行 → -15.79 の損失。

### 3-2. Skip Gate レートリミッターによる強制損失（二次原因: -9.56 JPY）

| 指標 | 値 |
|------|-----|
| レートリミッター発動トレード | 21 件 |
| レートリミッター発動 PnL | **-9.56 JPY** |
| 自然通過（pass）トレード | 49 件, PnL = -25.16 |
| 発動内 sell/ranging | 14 件, PnL = **-18.78** |

レートリミッター発動の 21 件中、**worst 3 の sell/ranging**（-15.79, -9.12, -5.67）だけで **-30.58** を占める。これらはすべて skip_gate が**正しくスキップを判断した**のに、30% 上限で強制実行された。

```
max_skip_rate: 0.30 (現行)
→ sell 側は実質的に 30% 以上スキップできない
→ skip_gate + EV モデルの防御力が 70% に制限される
```

### 3-3. JPY 残高制約による ranging buy priority 無効化（構造的原因）

| 指標 | 値 |
|------|-----|
| buy-freeze 回数 | 53 回 |
| sell-freeze 回数 | 2 回 |
| buy 凍結率 | ~41%（全 buy 試行の） |
| balance_freeze_cycles | 3（デフォルト） |
| 実際の buy/sell 比率（ranging） | 46%/54% |
| 期待 buy/sell 比率（635# 設計） | 75%+/25%- |

**635# の [ranging_buy_priority] は構造的に無効化されている。**

原因チェーン:
1. SideSelector → ranging buy priority → `next_side = "buy"` を返す ✓
2. `_resolve_balance_and_preflight()` → JPY 残高不足を検知
3. `freeze_side("buy", cycles=3)` → buy を **3 サイクル凍結**
4. 次の 3 サイクルは強制 sell → ranging でも sell 実行
5. sell 完了 → JPY にわずかな余裕 → 1 回だけ buy 実行
6. JPY 再枯渇 → 再び freeze_side("buy") → ループ

結果: buy/sell が交互に強制される（残高起因のピンポン）。ranging buy priority は dead letter。

## 5. 634# 見解との照合

634# は「問題は残高不足ではなく売損」と結論づけた（「JPY Margin >10M JPY 充分」）。

**修正見解**: アカウント残高全体は充分だが、**サイクル単位の可用 JPY** が慢性的に不足。原因は:
- 売り → JPY 回収 → 買い → JPY 消費 → 即座に枯渇 → freeze のサイクル
- `order_quantity: 0.001 BTC` (~11,500 JPY) は小さいが、BTC 在庫偏りで JPY が減少
- 634# の「残高不足ではない」は**総額**について正しいが、**流動性**について見落とし

## 7. 大川を渉れるポイント: 具体的施策

### 7-1. 【即効】max_skip_rate 引き上げ: 0.30 → 0.50

**根拠**: rate_limit 発動 21 件中、sell/ranging 14 件で -18.78。0.50 に引き上げることで多くの強制実行を回避。

```yaml
# configs/v460/fill_test.yaml
skip_gate:
  max_skip_rate: 0.50   # 0.30 → 0.50
```

**期待効果**: sell/ranging の rate_limit 損失 -18.78 の大部分を回避。推定 +10-15 JPY の改善。

**リスク**: スキップ過多による fill rate 低下。ただし現状でも sell/ranging は avg=-1.20 で**スキップした方が期待値が高い**。

### 7-2. 【即効】balance_freeze_cycles 短縮: 3 → 1

**根拠**: 3 サイクル凍結は過剰。JPY 不足 → 3 cycle 強制 sell → ranging buy priority 完全無効。1 に短縮すれば、次サイクルで buy を再試行可能。

```yaml
# configs/v460/fill_test.yaml
balance_freeze_cycles: 1   # デフォルト 3 → 1
```

**期待効果**: buy/sell 比率が 46%/54% → ~65%/35% に改善（設計値 75%+ には届かないが大幅改善）。buy/ranging の黒字復帰可能性。

### 7-3. 【中期】逆選択フィルター（fill_prob ガード）

fill_prob < 0.01 のトレード（13 件, -29.21）を防ぐメカニズム。

**選択肢 A**: 注文キャンセルの積極的タイムアウト
```
max_order_wait_sec: 25  # 25s 超えたら cancel
```
09:31 の -28.02 は wait=27.8s で発生。25s キャンセルで回避可能。

**選択肢 B**: fill_prob ベースの動的 offset 引き上げ
- fill_prob < 0.01 → offset を ceiling まで引き上げ（事実上のハードスキップ）
- 事前の queue position estimator と連携

### 7-4. 【中期】EV モデル精度改善

ev_offset パスが primary_only より悪い (avg -0.61 vs -0.38)。原因:
- sell/ranging で EV が損失を予測しているのに offset 補正が不十分
- ev_offset_sensitivity: 0.05 が保守的すぎる可能性
- sell 専用モデル (`skip_gate_lgbm_pnl120_sell.pkl`) の再学習が必要

### 7-5. 【長期】sidecar staleness 問題

-28.02 の壊滅的トレードで `sidecar=stale`。629# でキャッシュバグが修正されたが、依然として stale が発生。sidecar が正常に動作していれば、この逆選択を検知できた可能性がある。

## 11. 結論

**大川を渉れるポイントは「損失防止」にある。** システムは +44 JPY の利益を生んだが -79 JPY の損失で相殺された。

具体的には:
1. **2 件の壊滅的トレード**（-43.81）を防げれば**即座に黒字**
2. **レートリミッター**が skip_gate の保護判定を無効化（-9.56 の追加損失）
3. **残高制約**が 635# 施策を構造的に無効化

P0 施策（YAML 変更 2 点）を即座に hot-reload し、P1 施策（コード変更 2 点）を次回実装することで、現行の -34.71/8h を **+5~+15/8h** に転換できる見込み。
