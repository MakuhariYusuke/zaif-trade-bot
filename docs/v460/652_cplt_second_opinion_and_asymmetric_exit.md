## 2. 651# P0提案の検証と、市場微視的構造からの補強

### P0-1. Inventory Skewing の再調整 (`neutral_band: 0.05`, `tau: 3600`)
- **検証結果**: 推奨（支持）。現状、`preflight_insufficient` が極端に偏る（買い制約でのブロック 134件、JPY:BTC比率が0.9%:99.1%）という事実は、Inventory Skewが全く効いていないことを裏付けています。0.05（5%の偏り許容）という設定は、機会損失を防ぎつつ、スプレッドの過剰な狭まりを抑制する現実的な着地点です。
- **懸念と自己点検**: Skewが発動して内部要求スプレッドが歪められた際、`min_spread_bps` の下限と衝突した場合の挙動に注意が必要です。「在庫を戻したいからといって、マイナスの期待値を許容してまで逆サイドを取りに行く」のは避けるべきであり、現行の `min_spread_bps` フロアがSkew適用後も最終防衛線として機能しているか（順序の確認）が前提となります。

### P0-2. Toxic Low-Spread Sell Veto
- **検証結果**: 強く支持。`spread_bps < 2.3`（Q1バケット）でのマイナス期待値を防ぐための一手として最適です。
- **CPLT独自補強**: 651# の条件 `ob_imbalance > 0.25` は見せ板（Spoofing）に騙されるリスクが残ります。真のToxicity（毒性、Informed Flowの到来）を捉えるためには、VPIN (`vpin > 0.65`) に加えて、**`price_velocity_bps > 0`（微視的な上方への価格加速）** を条件に含めるべきです。「買い板が厚く、かつ実際に価格が上へ加速している最中の狭いスプレッド」こそが、Makerが轢かれる直前のサインです。

### P0-3. 長時間ホールドの Sell-entry 逃がし
- **検証結果**: 支持。14.27bpsの大損RT（Hold 69.7m）は典型的なテールリスクです。
- **CPLT独自補強（Regime-Drift Exit）**: 
  金融工学において、単なる「経過時間（Time-stop）」による逃げは往々にして底値・天井での損切りを誘発します。
  ホールド時間 > N分 だけで切るのではなく、**「ホールド時間 > N分 かつ、Regimeが `trending_up`（自ポジションにとって最悪の逆風）に遷移または継続している場合」** に限り、強制的にSoft Stop Loss（要求利益率・スプレッドを極小・マイナス許容にまで下げて即時撤退）を発動させるべきです。時間が経てば経つほど在庫は「腐敗（Decay）」しますが、それは「不利なRegimeドリフト」と組み合わさった時にのみ致命傷になります。

## 3. 追加の独自提案：The Edge（非対称なシステム設計）

### P1-X. 非対称なリターン要求（Asymmetric RT Exit Tolerance）
現物ベース（BTC/JPY）のMMにおいては、仮想通貨市場の構造的な「上方ドリフトバイアス」が存在します。
- `Buy-entry`（安く買って高く売る）：価格が全体的に上がりやすいため、持っていれば自然と有利なエグジット機会（Sell）が訪れやすい。
- `Sell-entry`（高く売って安く買い戻す）：決済待ちで持っている「JPYロング/BTCショート」ポジションは、相場が少しでも上昇トレンドに乗ると、永久に買い戻しの指値に到達しません。

**提案**: 
Buy-entry決済（Sell待ち）とSell-entry決済（Buy待ち）で、**要求するオフセットやクランプの許容度を非対称に（Asymmetric）** します。
つまり、`Sell-entry`の中の決済買い（Buy）は、「少しでも利益が出る（あるいは同値で逃げられる）なら、すぐに取引を完了してRTをクローズさせる」ようにゲインを妥協させ、逆に`Buy-entry`決済は強気に利益を引っ張るようにします。これにより、Sell-entryにおける「いつまでも買い戻せず、Regimeが変動して大爆発する」リスクを構造的に減らすことができます。

## 4. 自己点検 (Self-Audit)

本セカンドオピニオンの推敲にあたり、以下の点に留意・点検を行いました。

- **「Sell-entryが不利」と言い過ぎていないか？**
  【点検】直近の6W/7Lという狭いRTサンプルに引っ張られている可能性は否定できません。ダウントレンド環境下ではSell-entryが至高になります。そのため、前項の「非対称閾値」は固定値ではなく、「マクロトレンドがフラット〜上昇基調の時」という条件付きで適用されるべきです。
- **フィルター追加による稼働率（Fill Rate）の低下（Starvation）リスク**
  【点検】Toxic条件に `price_velocity` を付けるなどフィルターを精緻化することは、結果として「強制Pass」を増やし、`max_skip_rate` などのリミッターに当たる頻度を増やす副作用があります。よって、651#のP0-1（Inventory Skewの緩和）が適切に効き、Buy側での「健全なFill」頻度を上げて全体のSkipped率を正常化させることが**大前提**となります。
- **論証の薄い部分はないか**
  【点検】「MCB（サーキットブレーカー）の特例」がP2であるという651#の判定には完全に同意します。現在のデータ（During/Post-MCB fill: +0.55bps）を見る限り、MCB前後でのパニックに飛び込まない現状のガードはそれなりに機能しており、ここを急いで触ってバグを埋め込むリスクの方が高いと判断します。
