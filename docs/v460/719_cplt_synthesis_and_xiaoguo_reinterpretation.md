## §2 係争点と裁定

### 2.1 sell_hour_offset_boost: バグか設定か

| 主張 | 内容 |
|------|------|
| 715# (私) | 98.6% 不作動 → 構造的バグ |
| 716# | 症状は重いが根因断定は早い → telemetry 増設が先 |
| 718# | バグではない。「5つの特定 UTC 時間帯」以外は仕様上 no-op |

**718# の主張を事実検証した結果: 誤り**

- YAML には **17/24 時間帯** が定義されている（718# は「5つ」と記載 — 事実誤認）
- 定義済み時間帯のブースト値はすべて > 1.0 (1.3 ～ 5.0)

**追加検証** (本 719# で実施):

| 日付 | sell fills | sell_hour 有効 | no-op (ceiling) | no-op (未定義hour) | no-op (定義hour・非ceiling) |
|------|-----------|--------------|----------------|-------------------|----|
| 04/07 | 83 | **2** | 5 | 23 | **53** |
| 04/08 | 80 | **1** | 22 | 15 | **42** |

**53件 / 42件** が「ブースト定義済み時間帯・ceiling 未到達」なのに no-op。

例: UTC 2h (mult=5.0), vol_guard=0.3693 → sell_hour=0.3693。
正常なら 0.3693 × 5.0 = 1.847 → ceiling 0.65 にクランプ → sell_hour=0.65 になるべき。

**裁定**:
> **718# の「phantom bug」論は破綻**。定義済み 17 時間帯中 15 時間帯で no-op が確認された。
> ただし 716# の指摘通り、根因はコードバグか実行時コンフィグの齟齬か、まだ確定していない。
> 最有力仮説: **実行時の YAML (SHA 750cd71 / 90de90f 時点) と現行 YAML で sell_hour エントリ数が異なる**（git history 要確認）。あるいは `_current_utc_hour()` の返却値と fill timestamp の UTC hour の不一致。

### 2.2 モデルの扱い: 放棄か救済か

| 主張 | 内容 |
|------|------|
| 717# | モデル放棄。ルールベース (OBI / Inventory) のみで安定稼働 → シャドウ運用 |
| 718# | 放棄は早い。教師ラベルを p30/p120 に切替えて再学習すれば復活する |
| 716# | 一律 tuning ではなく side × regime × hour の governance 改修 |

**裁定**:
- 717# の「モデルにエッジがない」: **暫定支持**。n=8 organic pass では検証不能であり、現時点でモデルの予測力を信じる根拠がない
- 718# の「ラベル変更で復活」: **方向性は正しいが時期尚早**。retrain には十分な p30/p120 データの蓄積が前提。現時点で着手しても市場条件が変わるまでのデータでは不十分
- 716# の governance 改修: **最も実務的**。bypass を conditional にし、forced_pass の side × regime 分離を先に行う

**結論**: モデルは**即座に放棄もせず、即座に再学習もしない**。
1. bypass_mode を条件付き (regime-aware) に変更し、モデル判断の情報を一部活かす
2. p30/p120 のテレメトリ蓄積を並行で進め、データが十分になった時点で再学習を検討

### 2.3 SAG redesign (Inverse Penalty)

| 主張 | 内容 |
|------|------|
| 717# | OBI ベースの動的 pricing を新規実装 |
| 718# | 既存の `spread_as_guard_redesign` を先に有効化すべき |
| 715# | SAG redesign は低リスクだが narrow spread 時の penalty 増に注意 |

**裁定**: 718# の指摘は正当。OBI 新規実装の前に、**既に眠っている inverse penalty を起こすのが先**。

現行 (redesign=false): flat 0.5 bps penalty
Redesign (redesign=true): `0.5 × (2.0 / spread_bps)`, floor=0.25, cap=1.5

spread=2.0 bps 時: penalty=0.5 bps (同等)
spread=1.0 bps 時: penalty=1.0 bps (倍増 → narrow spread 保護↑)
spread=3.0 bps 時: penalty=0.33 bps (軽減 → 広 spread 機会↑)

**結論**: `redesign_enabled: true` への切替えは hot-reload 可能・回収可能。P1 で実行。

## §3 雷山小過の再解釈 — 716-718# を踏まえて

714# の解釈を三者の知見で更新する。

### 3.1 「飛鳥遺之音」

**714# 初期解釈**: 飛鳥 = 取引機会、音 = 市場シグナル (velocity, OBI)
**717# 拡張**: 飛鳥 = Taker、音 = Order Flow Toxicity の痕跡 (VPIN, OBI)

**716# を踏まえた再解釈**:
> 飛鳥が遺す「音」は **p30/p120** である。

spread_capture は飛鳥の「影」(appearance) に過ぎない。鳥が飛び去った後に残る「音」(sound = aftermath) こそが p30/p120 — 約定後に市場が実際に動いた結果。

713# 以前は影（sc_avg）を見て「鳥を捕らえた」と錯覚していた。716# がこの錯覚を破壊した。

**教示**: 影ではなく音を聴け。p30/p120 を判断の主軸とせよ。

### 3.2 「不宜上，宜下」

**714# 初期解釈**: offset を上げよ（保守的に）、下げるな（攻撃的になるな）
**717# 補強**: 無理に fill を取りに行くな、保守的にスプレッドを構えよ

**再解釈**: 「上」と「下」は offset の方向だけでなく、**メトリクスの階層** も指す。

- **上** = spread_capture (表層的・即時的) → 宜しからず
- **下** = p30/p120 (深層的・事後的) → 宜し

「上の指標を見て判断するな。下の指標（結果としての PnL）にこそ耳を傾けよ。」

### 3.3 「密雲不雨，自我西郊」（六五動爻）

**714# 初期解釈**: 改善要素（雲）は揃ったが結実（雨）していない。制約（西郊＝金）が阻む。

**再解釈**: 「密雲」は spread_capture の一時的改善 (Phase C sc_avg=−0.425 < Phase A sc_avg=−0.684)。しかし「不雨」— p30 は −1.013 と悪化している。

**「自我西郊」** — **我から出た西の郊**。rate limiter や ceiling だけが阻んでいるのではない。「自我」= **我々自身の指標設計** が雨を阻んでいた。sc_avg を最適化しても p30 が悪化するなら、「雨が降らない」のは当然。

> **制約（金）は外部にあるのではなく、我々の評価体系そのもの（自我西郊）である。**

### 3.4 「公弋取彼在穴」

**714# 初期解釈**: hot-reload（弋 = 繫いだ矢）で穴に潜む根因を射抜け。

**再解釈**: 穴に潜む真の標的は:

1. **spread_capture 信仰** — 穴の最深部。これを捨てない限り全ての施策が「影」を追う
2. **sell_hour の不作動** — 穴の中層。718# の「phantom bug」説が蓋をしていたが、719# 検証で蓋を剥がした
3. **governance (forced_pass/bypass)** — 穴の上層。モデルの上に governance が覆い被さり、モデルの判断を無力化

弋（繫いだ矢 = hot-reload）で射抜く順序: **①評価軸の転換 → ②sell_hour 真因特定 → ③governance 条件化 → ④SAG redesign**

### 3.5 互卦 大過 (#28) — 棟木が撓む

714# で指摘: pipeline が 1.12 を出力するのに ceiling 0.65 でカット → 構造的無理。

**再解釈**: pipe → sell_hour → ceiling の流れで、sell_hour が 98% 不作動であることが判明。**sell_hour が効いていれば pipeline 出力は vol_guard (e.g. 0.42) × boost (e.g. 5.0) = 2.10 → ceiling 0.65**。つまり sell_hour が正常動作すれば ceiling が頻繁に効く（保護的に機能する）。

sell_hour 不作動 → ceiling の出番が減る → 低い offset のまま fill → p30 で被弾。

**大過（棟木が撓む）の正体は sell_hour の不作動そのもの**。

### 3.6 之卦 咸 (#31) — 心なき感応

**714# 初期解釈**: 「心」を除いた純粋な感応 → 主観・バイアスを除いた市場との応答。

**再解釈**: 「心」= spread_capture_bps への執着（これが「心＝バイアス」）。これを除いた「咸」= p30/p120 による無心の感応 → Responsive Market Making。

sc_avg を手放し、p30/p120 で市場と対話する。これが小過 → 咸への遷移。
