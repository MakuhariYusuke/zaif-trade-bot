## 1. Task A: eDRC パラメータ初期値の戦略的導出

実測データの P99 (0.80) を「生存の限界線」と定義し、執行エンジンの退避性能を確定する。

### 1.1 パラメータ推定（再定義）

| パラメータ | 推奨値 | 戦略的意図 |
|-----------|--------|------------|
| **$\alpha$ (Vol感度)** | **0.020** | $\sigma=30$bps（極限ボラ）時に Ceiling を 1.8x (0.72) へ拡大。 |
| **$\beta$ (OFI感度)** | **0.40** | $OFI=0.8$（強い偏り）時に Ceiling を 1.38x (0.55) へ拡大。 |
| **$C_{base}$** | **0.40** | 既存の Buy/Sell 天井を包含し、平時の約定率を維持。 |

### 1.2 $C_{dynamic}$ 行動プロファイル（シミュレーション）

| $\sigma$ \ OFI | 0.2 (平穏) | 0.6 (警戒) | 1.0 (危機) | 期待される挙動 |
|---|---|---|---|---|
| **5.0** (平時) | **0.47** | **0.52** | **0.61** | 緩やかな退避。 |
| **15.0** (荒天) | **0.58** | **0.64** | **0.75** | **既存 Ceiling 0.30 では死んでいたゾーン。** |
| **30.0** (地獄) | **0.78** | **0.86** | **1.00** | **執行を事実上停止（Hard Retreat）。資産を守る。** |

## 2. Task B: RobustStats 統合設計（コードドラフト）

`maker_price.py` において、生信号を「執行用信号」へ変換する防波堤を構築する。

```python
# scripts/v460/lib/maker_price.py への統合案
def _get_robust_inputs(self, side: str) -> Tuple[float, float]:
    """高周波ノイズを除去し、リスク上昇に非対称な反応を示す入力を生成."""
    # 1. Volatility: リスク上昇(Up)に 4倍敏感な Asymmetric EMA
    self._robust_sigma = RS.asymmetric_ema(
        current_val=self._last_sigma,
        prev_ema=getattr(self, "_robust_sigma", self._last_sigma),
        alpha_up=0.20, alpha_down=0.05
    )
    
    # 2. Adverse OFI: 10サイクル中央値フィルタによるフラッシング耐性
    if len(self._ofi_history) >= 10:
        ofi_med = RS.median_filter_fast(np.array(self._ofi_history)[-10:])
    else:
        ofi_med = self.get_adverse_ofi(side) # fallback
        
    return self._robust_sigma, ofi_med
```

## 3. Task C: Balance-Forced Sell Tail Loss の解剖

### 3.1 「自殺的在庫清算」の構造
346# で判明した「Tail Loss の 100% が balance_forced」という事実は、現在の在庫管理ロジックが **「市場の毒性（AS）よりも、在庫の中立化を優先している」** ことを示している。
- **欠陥**: 在庫が偏る局面（Toxic Flow）で指値を Ceil (0.30) まで近づける（＝浅くする）行為は、情報強者に「安値でオプションを献上」する行為である。

### 3.2 処方箋：動的天井による「強制中立化の拒絶」
eDRC の $\beta$ (OFI) を 0.40 に設定することで、在庫を減らそうとする `inv_skew` の力が働いても、**「板が薄い（OFIが悪い）なら、そもそも天井が 0.60 以上に逃げている」** ため、物理的に浅い価格での約定が発生しなくなる。

## 4. 追加提言 (Task D): 「死の90秒窓」への外科的処置

565# で指摘された **「Sell 窓 = 90秒」** の問題に対し、以下の改善を提案する。

### 4.1 窓の非対称性の是正
Sell 側だけ 90秒待つのは、「損失が確定するまで目をつぶっている」に等しい。
- **提案**: 30s / 60s / 90s の各タイムホライズンにおける AS 発生率を独立監視し、**最短の 30s 窓で損失が一定値を超えた場合、即座に Sell Ceiling を指数的に引き上げる** フィードバックループの実装。

## 5. セルフレビュー (Self-Review)

### 5.1 数理的安定性
- **$\exp$ の爆発**: $\alpha, \beta$ が正である限り $C_{dynamic}$ は正の値を維持するが、引数が大きすぎると `inf` になる。`hard_cap: 1.0` による最終 Clamp は必須。
- **Chutter (バタつき)**: 中央値フィルタと EWMA の併用により、1秒単位の注文価格の激しい変動（ノイズ追従）は理論上抑制されている。

### 5.2 運用上の懸念
- **約定機会の消失**: 荒天時に天井が 0.80 まで逃げることは、実質的な「システム停止」を意味する。これは「損をしない」大義には適うが、月間の Total PnL 目標に対する機会損失を許容できるか、ユーザー様の最終判断を仰ぐべき点である。
