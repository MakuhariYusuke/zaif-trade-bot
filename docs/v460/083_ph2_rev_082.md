## §2 現在地（Gate と収益性）

### §2.1 Gate 現況

`results/v460/fill_test/monitor_snapshot_20260216_150613.json`:

- `total_orders=352`, `filled=290`, `judgment_type=INTERIM`
- `E1_fill_rate_p90=66.15%` (FAIL)
- `E4_post_fill_30s_pnl=-0.474bps`, `p=0.0437` (FAIL)
- `E5_adverse_selection=34.14%` (FAIL)

### §2.2 「改善兆候」と「採用可否」は別

`results/v460/verification_077/verification_077_20260216_150808.json`:

- time_filter の before/after は `+0.557bps` 改善
- ただし permutation `p=0.109`（非有意）
- Holm-Bonferroni は全戦略 FAIL
- 観測効果量で power `65.0%`（不足）

結論: **今は「勝っている」ではなく「勝てる可能性が上がっている」段階**。

### §2.3 高頻度化に対する現実

082の問題提起どおり、現状は高頻度には遠い。
`cycle_interval=120s` + `order_timeout=300s` + `time_filter` で、実効回転は低い。
粗い近似でも、現在の条件付き期待値は **約 +2 JPY/時（0.001 BTC）** 程度で、ロットを上げる前に構造改善が必要。

## §4 収益改善アクション（実装優先順位）

### §4.1 48時間で着手する施策（即効）

1. **run_id分離評価を必須化**
- `scripts/v460/ml/run_075_verification.py` に `--run-id` / `--git-sha` フィルタを追加。
- 082の全体集計を「最新 run 専用」と「履歴全体」で分離。

2. **SkipGate 可観測性修正（再学習の前）**
- score のままでは解釈がぶれるため、`P(AS)` をそのまま記録。
- `as_threshold_buy/sell` と比較した結果を artifact に保存。

3. **固定時間フィルタの縮退**
- 現在の wide/strict の固定時間帯を縮小し、最悪帯のみ hard skip。
- 残りは micro 条件（spread, recent flow, short-term velocity）で soft skip。

4. **timeout 短縮 + 再見積**
- `order_timeout_sec=300` を短縮し、一定秒で cancel→re-quote。
- 目標は「wait長すぎの stale fill」を削ること。

### §4.2 1週間で進める施策（中期）

1. **Sell 専用ポリシー化**
- buy/sell を同一ロジックにしない。
- sell は `offset`, `threshold`, `timeout` を別管理（既存 side 分離を強化）。

2. **イベント駆動型フィルタ**
- `hour` 中心から、`spread regime + trade-flow + volatility burst` 中心へ。
- 「高頻度を維持したまま危険局面だけ回避」に寄せる。

3. **G1.1 補助KPIの追加監視**
- 30s主KPIは維持しつつ、round-trip と net inventory を常時併記。
- `ztb/metrics/fill_quality.py` の round-trip 指標を意思決定側へ昇格。

## §5 082 質問への回答

### Q1 過学習リスク
- 時間帯最適化はサンプル不足で過学習リスクが高い。
- `Permutation + block bootstrap + run_id別WF` の3点セットで判定する。

### Q2 Edge予測
- 事前予測対象は `edge_at_fill` ではなく `P(AS)` に統一する。
- 現行 SkipGate の出力を確率として可視化し、閾値較正を先に行う。

### Q3 offset最適化
- 目的関数を `E[pnl_per_attempt] = fill_rate * mean_pnl_fill` に固定。
- ratio探索は固定gridではなく side別バンディット（探索率付き）で実施。

### Q4 Sell弱さ
- sell は独立戦略として扱う。
- sell-only の hard guard（spread上限、volatility上限、timeout短縮）を導入。

### Q5 SkipGate再設計
- いきなり廃棄しない。まず可観測性と閾値較正を修正。
- その上で `P(AS)` モデルの精度が低ければルールベース fallback を採用。

### Q6 理論上限
- 現状パラメータでは月次は小さく、ロット拡大だけでは危険。
- 上限を押し上げる鍵は「回転率改善」と「AS低減」の同時達成。

### Q7 Wait と AS の因果
- 交絡の可能性が高い。`hour/side/regime` 層化比較を先に実施。
- 次に小規模ランダム化（timeout/offset）で因果を確認する。

### Q8 ロット増加
- Gate未通過の段階でのロット増は不可。
- 段階増（1.0x -> 1.5x -> 2.0x）と同時に fill悪化・AS悪化の監視必須。
