## §0 Executive Summary

425# Decision Matrix の結論: **S1 FAIL × S1' FAIL → 「val_ratio=0.02は全般的に楽観」**。

しかしこの1行判定は事態の半分しか語っていない。S1（reward_clean × val_ratio=0.20）は pf_median=1.049 で閾値 1.05 を **0.001 差で逸脱** した marginal FAIL であり、S1'（reward_tuned × val_ratio=0.20）は pf_median=1.031, sharpe=0.45 の **構造的 FAIL** だった。この非対称性こそが、本実験で得られた最も重要な情報である。

根本結論: **問題は val_ratio 単独ではなく、「20K 学習が ~170 日間の市場レジーム変動に対して汎化しない」という時間スケール不適合である。** val_ratio=0.02（末尾17日OOS）はこの不適合を隠蔽していたにすぎず、reward_clean は reward_tuned より格段に頑健だが、いずれも中期レジーム遷移に脆弱。

## §3 根因分析

### §3.1 表層: val_ratio=0.02 の楽観バイアス — 確認されたが「主犯」ではない

val_ratio=0.02（末尾17日OOS）→ 0.20（末尾169日OOS）で G3 が PASS→FAIL に遷移したことは、422# の楽観仮説を支持する。しかし S1 の pf_median=1.049 は **閾値を 0.001 しか割っていない**。もし閾値が 1.04 なら PASS である。これは「偽陽性」というより「境界事例が厳密評価で判定反転した」と記述すべきであり、val_ratio=0.02 は「楽観」ではあるものの「虚偽」ほどではない。

真の問題は **なぜ 169 日間 OOS で pf が 1.05 を下回るのか** である。

### §3.2 構造因: mid 期崩壊 — 時間スケール不適合の証拠

Multi-slice に共通する mid 期崩壊パターンは、以下の仮説を支持する:

**20K step（~14分間の学習）で獲得した方策は、OOS 内で ~60 日目以降の市場レジーム変動に対応できない。**

- 1,192,591 行の学習データ ≈ 828 日分（1440step/日）
- 20K step で実際にデータに接触するのは学習データの ~2%
- 学習が見た分布と OOS mid 期（~60-120日目）のレジームが乖離すれば pf が崩壊するのは自然

S1 seed 42 は mid→late で改善する「例外的」パターンだが、これは seed 42 が偶然 mid-late のレジームに適合する初期重みを引いた可能性が高い。seed 456 は early=1.255（高い）→ mid=0.640（壊滅）で、**early で有効だった方策が mid の市場環境では逆効果** になった典型例。

### §3.3 reward 関数の影響: reward_clean の相対的頑健性

4 条件の pf_median を整理する:

| | val=0.02 | val=0.20 | Δ |
|---|---|---|---|
| reward_clean | 1.145 | 1.049 | -0.096 |
| reward_tuned | 1.006 | 1.031 | **+0.025** |

reward_clean は val_ratio を広げると劣化するが、reward_tuned は val_ratio に対してほぼ不変（かつ低水準）。これが意味するのは:

1. **reward_tuned は学習自体が不十分** — 補助ペナルティ（balance_penalty=0.1, consistency_penalty=0.01）が PnL 信号を薄め、20K step では有効な方策に収束しない。val_ratio を変えても差が出ないのは「そもそも学習してない」から
2. **reward_clean は学習はしているが OOS 後半で脆弱** — 純粋 PnL 信号で方策は獲得されるが、mid 期のレジーム変動に対して robustness がない

### §3.4 Corr Paradox の継続（425# §B2 参照）

S1' の reward_profit_corr_median = **0.924** は S1 の 0.866 より高い。しかし S1' の pf_median は S1 より低い。「報酬と利益の相関が高いモデルほど利益が少ない」という 425# で指摘した paradox が再現された。

この根因: reward_tuned の補助ペナルティは **OOS でたまたま利益が出る step と reward が相関する** ように方策を歪めるが、それは **利益を最大化する方策とは別物** である。ペナルティ項が「pnl と相関しやすい安全方策」（ほぼ何もしない）に誘導している可能性がある。これは S1' seed 789 の ROI=-4.32%（大損）かつ corr=0.929（高相関）というデータが如実に示す — 相関が高くても利益は出ない。

### §3.5 best_model vs final_model（422# A1 の検証）

422# で「G3 が final_model ではなく best_model を使うべき」と提案した。S1/S1' で両方を評価した結果:

| | final pf | best pf | best が優勢？ |
|---|---|---|---|
| **S1 seed 789** | 1.089 | **1.156** | ✅ (+0.067) |
| **S1' seed 789** | 0.923 | **1.020** | ✅ 赤→黒転換 |
| S1' seed 456 | 1.103 | 1.030 | ❌ final が上 |
| 他の seed | ≈同一 | ≈同一 | — |

best_model が有効な seed もあるが、**全 seed で一貫して優勢ではない**。422# A1（best_model 差替え）は部分的改善に留まり、根本解決にはならない。ただし seed 789 のように best_model で黒字帰還するケースは、F6 checkpoint 選別の改善で拾える余地がある。

### §3.6 431# fill data との接続 — 「学習環境と本番の断絶」

431# の fill data 分析で判明した事実を本結果に重ねると、より根本的な問題が浮かぶ:

- **buy ceiling clamp rate = 100%**: 本番では SAC 出力は ceiling でクリップされ、全注文が固定 offset になる
- **Sidecar 有効レコード = 0/1,617**: SAC→Sidecar→offset chain は完全に切断されている
- **EV Score × 30s PnL 相関 = 0.017**: 学習環境で SAC が最適化する EV は、本番 PnL にほぼ無関係

つまり、**S1/S1' で test しているOOS 評価は「学習環境内のシミュレーション」であり、本番の clamp + sidecar 停止状態とは根本的に異なる**。仮に G3 PASS したとしても、それが本番でのリターンに直結する保証はない。

これは 427#-430# の議論 — SAC を Driver から Sidecar に降格し、観測可能性を確立すべき — の実験的裏付けになっている。

## §4 425# Decision Matrix の適用と解釈

### §4.1 Letter の判定

| S1 | S1' | Matrix の指示 |
|---|---|---|
| **FAIL** | **FAIL** | val_ratio=0.02は全般的に楽観的 → 過去のG3 PASS全体の信頼性見直し |

### §4.2 判定の修正

Matrix の判定は正しいが、ニュアンスの追加が必要:

1. **「全般的に楽観」は正確だが「全面的に無効」ではない** — S1 は marginal FAIL（0.001差）であり、reward_clean 自体は val_ratio=0.20 でも nearly-PASS 水準。G3 PASS の信頼性見直しは必要だが、reward_clean の方向性まで棄却すべきではない
2. **reward_tuned は val_ratio に関係なく一貫 FAIL** — reward_tuned は「楽観の被害者」ではなく「そもそも弱い」。今後の実験候補からは除外すべき
3. **本当に見直すべきは G3 Gate の前提** — val_ratio=0.02 の OOS 17 日は「評価」として短すぎるが、val_ratio=0.20 の OOS 169 日は 20K step 学習に対して長すぎる。適正な val_ratio は 0.05〜0.10 の範囲に存在する可能性がある

## §5 根本原因の統合 — 三層構造

```
Layer 1: 学習容量 (20K step は ~2% のデータにしか接触しない)
  ↓
Layer 2: レジーム汎化不全 (mid 期崩壊 — 学習分布外の市場環境への脆弱性)
  ↓
Layer 3: 評価系の欺罔 (val_ratio=0.02 が Layer 2 を隠蔽)
  ↓
表出: reward_clean だけが val_ratio=0.02 で G3 PASS
```

- **Layer 1 は 100K 実験で既に検証され、増ステップが解にならないことは 422# で判明** 済み（100K G3 FAIL）。20K での学習飽和は step 数の問題ではなく、**方策空間の問題**（1次元 continuous_action [-1,1] での SAC はそもそも表現力が限定的）
- **Layer 2 が本セッションで新たに定量化された核心**。mid 期崩壊パターンは全 reward 関数・全 val_ratio で共通であり、SAC 単体の限界を示す
- **Layer 3 は 422#-425# で発見・本実験で確認された交絡**

### §5.1 なぜ mid 期が崩壊するのか — さらなる深掘り

multi-slice の 3 分割で「early-mid-late」に対応する OOS の期間を概算する:

- OOS 全体: 243,386 step ≈ 169 日
- early: ~0-56日, mid: ~57-113日, late: ~114-169日

学習データは OOS の直前で終わる。early 期は学習データの末尾に時間的に近いため、**分布シフトが最小**。mid 期は学習データから2-4ヶ月離れるため、**季節性・ボラティリティレジーム・流動性構造の変化** が蓄積する。late 期の挙動が seed によりまちまち（回復する seed もあれば壊滅する seed もある）なのは、late 期のレジームと学習データのレジームとの類似性がシードの初期重みに依存するからと考えられる。

これは 424#（Gemini）が指摘した「時間スケールのミスマッチ」の定量的証拠である。

## §6 427#-431# の知見との統合

### §6.1 Sidecar の必要性が実験から裏付けられた

430# で発見された `sac_retrain_scheduler.py`（完全実装済み・未起動）は、本実験が示す「レジーム変動への脆弱性」に対する **既存の解答** である。定期的な retrain が走れば:

- SAC は直近データで方策を更新し、mid 期崩壊を回避できる可能性がある
- Sidecar v2（比例変換）による gradual な bias 反映が、clamp に頼らない実行を可能にする

### §6.2 Clamp 100% 問題（431#）との接続

S1/S1' の OOS 評価は clamp なしのシミュレーション環境で行われている。しかし本番では buy 全件が ceiling clamp される。これは SAC が学習した方策の意味が**本番で完全に消失する**ことを意味する。

この矛盾は「SAC の学習環境と本番環境のギャップ」という、val_ratio よりもさらに根本的な問題を指し示す。G3 Gate は学習のシミュレーション内で pf を測っているが、本番では offset chain 全体が clamp に潰されている。

### §6.3 reward_clean の「偶然の妥当性」

reward_clean が reward_tuned より優れる理由を、427#-431# の文脈で再解釈する:

- reward_clean: `step_pnl × 100`、ペナルティ0、`ent_coef=0.01`（固定）
- reward_tuned: `step_pnl × 1` + 補助ペナルティ群、`ent_coef=auto`

reward_clean の「全ペナルティ無効化」は設計意図というより **消去法の産物** だが、結果として **ノイズの少ない勾配信号** を SAC に提供する。ent_coef=0.01 の固定はエントロピーボーナスを抑制し、方策が早期に exploitation に偏ることを許容する。これは 20K step という短い学習では合理的 — 探索余地がないなら exploitation に集中すべき。

一方 reward_tuned の ent_coef=auto は SB3 のデフォルト（初期値0.1, 自動調整）であり、20K step の短い学習で探索を促進しすぎる + 補助ペナルティが PnL 勾配を汚染する、という二重の不利が生じている。

## §7 結論と次のアクション

### §7.1 確定事項

| # | 結論 | 根拠 |
|---|---|---|
| C1 | val_ratio=0.02 は楽観バイアスを含む | S1 FAIL（但し marginal） |
| C2 | reward_tuned は val_ratio に関係なく弱い | Original FAIL + S1' FAIL（構造的） |

### §7.2 価値判断を含む推奨

| 優先度 | アクション | 理由 |
|---|---|---|
| **P0** | **val_ratio=0.05〜0.10 での追加実験** | 0.02 は楽観、0.20 は過酷。適正 OOS 長を同定する |
| **P1** | **retrain_scheduler 起動** (430# 発見の既存資産) | mid 期崩壊の根本対策。定期 retrain でレジーム追従 |
| **P2** | reward_tuned を終了し、**reward_clean 一本化** | C2 より。限られたリソースを分散させない |
| **P3** | **clamp 条件付き OOS 評価の導入** | OOS で clamp を模擬し、本番との乖離を測定する |
| **P4** | G3 Gate の val_ratio 標準化 | 比較可能性のため、G3 は固定 val_ratio（例: 0.10）で統一 |

### §7.3 422#-426# シリーズの完結

422# で始まった「100K G3 FAIL はなぜか」の探求は、以下の経路で解明された:

```
422#: 100K FAIL → val_ratio 交絡仮説
 ↓
423#/424#: val_ratio 単独犯ではない（時間スケール不適合）
 ↓
425#: reward × val_ratio 交互作用 → S1/S1' 実験設計
 ↓
426#（本文書）: S1/S1' 実行 → mid 期崩壊パターン発見
         → 根因 = 20K SAC のレジーム汎化限界
         → val_ratio=0.02 はこの限界を隠蔽していた
```

**100K FAIL の真因は「過学習」でも「val_ratio の artifactual PASS」でもなく、SAC の 1 次元連続行動空間 × 有限ステップ学習が本質的に持つレジーム汎化限界である。** 20K でも 100K でもこの限界は存在し、val_ratio=0.02 が PASS を出していたのは OOS が短すぎて限界が露呈しなかったからにすぎない。

この認識に立つと、次の施策は「SAC をもっと良く学習させる」ではなく、**「SAC の限界を前提として運用アーキテクチャ側で補完する」** — すなわち 430# で発見済みの retrain_scheduler 起動と Sidecar v2 有効化 — が論理的帰結となる。
