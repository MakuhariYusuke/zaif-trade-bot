## §0 エグゼクティブサマリ

1. `000` の大義（短期高収益）と `118` の方針（F4/F5 を最優先）に照らすと、`119` は方向性は正しい。  
2. 実データ再集計でも `EE 48件 = -7.20bps/件`、`No-EE 375件 = +1.03bps/件` で、Early Exit 問題は再現。  
3. ただし現時点の全体は `P30 mean=-0.267bps`、`AS=31.3%` で F5 (≤30%) は未達。  
4. 追加で重大なのは、`spread_adaptive` 閾値が実測分布と不整合で **常時 narrow 判定** になっている点。

## §3 追加で見つかった重要改善点

### A1. `spread_adaptive` が実質的に常時 narrow 発動 [CRITICAL]

- 実測 `spread_bps`: median `2.43`, max `5.03` (n=511)。  
- 現設定: `narrow_spread_bps=10`, `wide_spread_bps=25`。  
- 結果: **全件が narrow 判定 (<10)**、wide 判定は 0 件。  

提案:
1. 閾値を固定値ではなく分位点で設定（例: narrow=P35, wide=P85）。  
2. まずは暫定で `narrow=2.0`, `wide=4.0` の AB テスト。  

### A2. 分析が run 混在で、意思決定に Simpson 逆転リスク [HIGH]

- 全体平均だけ見ると方向がぶれる。  
- 例:  
  - `1771339803_3afba87b`: `+1.353bps`  
  - `1771380856_b7d09bbf`: `+0.241bps`  
  - `1771513512_f4e2c2a2`: `-0.753bps`  

提案:
1. Gate判定の補助指標として `active_run` と `trailing_200fills` を必須併記。  
2. 文書では `all-run` と `current-run` を明示分離。  

### A3. Buy 側 SkipGate 閾値の再調整余地 [HIGH]

- buy の `skip_gate_as_prob` では `[0.50,0.52)` 帯が `mean=-0.247bps`、AS 36.7%。  
- 現在 `as_threshold_buy=0.52`。  

提案:
1. `as_threshold_buy=0.51` を候補に短期 AB（過剰 skip を監視）。  
2. `target_skip_rate_buy` 固定より、PnL 目的関数を含むオンライン較正へ。  

### A4. Early Exit 判定が推定ベース（`actual_measurement_sec<28`） [MEDIUM]

- `FillRecord` に `early_exit_triggered` を保存しておらず、分析がヒューリスティック依存。  

提案:
1. `FillRecord` へ `early_exit_triggered: bool` を追加。  
2. `pnl_at_exit` と `pnl_at_30s_fixed` を併記して計測バイアスを分離。  

### A5. 在庫制約に対する side 選択が非効率 [MEDIUM]

- 現行は交互ベースで、残高不足 side を毎回試してから反転する。  
- 警告ログと API 呼び出しが増える。  

提案:
1. inventory-aware side selector（実行可能 side を先に選ぶ）を導入。  
2. 残高不足時は `side freeze`（一定回数は実行可能 side 固定）。

## §6 最終判断

`119` は、`000` の大義に対して「どこが収益を壊しているか」を特定できており、レビューとして有用。  
一方で、`118` の方針どおり Gate 通過可否で判断するなら、現状は **F5 未達リスクが残る**。  
したがって次の一手は「EE無効化」単体ではなく、**AS制御（特に buy閾値 + spread_adaptive再設計）** を同時に進めるべきである。
