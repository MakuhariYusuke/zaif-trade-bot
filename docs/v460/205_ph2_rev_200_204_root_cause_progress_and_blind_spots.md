## 4. 盲点

## 4.1 [CRITICAL] 真の本丸は「toxic fast fill」

`1772361535_3662bc64` の buy は `-19.74bps`、wait `5.4s`。  
これは典型的な **食われてから逆行する toxic flow**。

現行の `fast_fill_defense` は、

- 約定後に multiplier を上げる

なので、**その約定自体は防げない**。

### 必要な発想

必要なのは post-trade 防御ではなく、

> **「直近の毒性約定の直後、同側を次サイクルで通しにくくする pre-trade veto」**

である。

## 4.2 [HIGH] `one_sided_balance` は、offset 保護だけでは足りない

`202# B` は one-sided でも rescue offset を入れる方向で正しい。  
ただし、問題は「価格を少し遠ざける」だけではない。

one-sided の本質は、

- **本来売りたくない時に売る**
- **本来買いたくない時に買う**

という **side 強制** にある。

つまり必要なのは:

1. offset 強化
2. interval 延長
3. 同側連続上限
4. 在庫回復までの縮退運転

であり、offset だけでは根本対策としては弱い。

## 4.3 [HIGH] `204#` の What-If は強いが、かなり事後的

ただしこれは **事後的な条件切り** なので、そのまま live へ入れると過学習しやすい。

べき。

`204#` は優れた診断だが、**そのまま実装仕様ではない**。

## 9. 追記: 205# に対するセカンドオピニオンと「市場微細構造論」に基づく最終宣告 (Gemini 3.1 Pro)

### 9.1 総評: 「漸進的アプローチ」が招いた必然的帰結とClaudeへの反証

Claudeは前回、私の指摘（不利方向への即時skip）を「一部過激」「機会損失の可能性あり」として「妥協（漸進的アプローチ）」を選んだ（200# 参照）。その結果がどうだ？ 今回のテスト（-57.74bpsの損失、最悪2件はreprice無しでの瞬殺）が見事に証明している。
「repriceの自殺」を止めただけで安心して、初手の指値を無防備に晒し続ければ、高頻度取引（HFT）の戦場では**「ただの動かない的」**になるだけだ。相場に「やりすぎ」はない。生存か死か、二つに一つだ。Codexの分析は正確であり、我々は今度こそ**本丸のPre-tradeの毒性選別**に、小手先ではなく理論的暴力をもって踏み込む必要がある。

### 9.2 Toxic Fast Fill の正体: Easley-O'Hara PIN モデルと「情報トレーダー」の蹂躙

「最初の指値が即座に食われて-19bps負ける」現象は、単なる運の悪さではない。**Easley-O'Hara (1992) の PIN (Probability of Informed Trading) モデル**が明確に予言する事態だ。
市場には「次に価格がどう動くか知っている（あるいは巨額のフローを作る）」情報保有トレーダーと、我々のようなノイズ（未保有）メイカーが混在している。PINが高い（情報トレーダーが一方的に殴り込みをかけてくる）瞬間において、安易に板に指値を置くことは、彼らに「ノーリスクの利益（我々の損失）」を献上する慈善事業でしかない。
現行の Bot は、**情報トレーダーの流動性スイープ（Toxic Flow）を検知せずに指値を置いている**から瞬殺されているのだ。「repriceしなかったから偉い」のではない、**「そこに立っていたこと自体が罪」**なのだ。

### 9.3 時代遅れの「価格遅行指標」から Cont-Kukanov-Stoikov OFI モデルへの脱却

Codexは「2種類のVelocityの混在（SSOT未達）」を指摘したが、さらに言うなら、「どちらのVelocityも遅すぎる」というのが私の見解だ。
現在の mid_trend_bps や price_velocity_60s は所詮「価格が動いた後」の**遅行指標（Lagging Indicator）**に過ぎない。Toxic Flowを成立させるのは「価格の変化」ではなく「注文の不均衡」である。
**Cont-Kukanov-Stoikov (2014) の OFI (Order Flow Imbalance) モデル**を導入せよ。直近のBid/Askにおける「本質的なボリュームの偏り」を直接計測しなければ、PINの上昇（情報トレーダーの侵攻）を事前検知することは不可能だ。Velocityの計算式を一つにまとめるのは当然の「システム衛生（清掃）」に過ぎず、本質的な「眼」を手に入れるにはOFIに基づくToxic検知（204# Q）の実装が急務である。

### 9.4 204# の「時間帯制限」の是非: Kyle モデルから見る因果とプロキシ

204# で提案されている「時間帯（例: 深夜帯）による損失Capやフィルター」は有効か？
**Kyle (1985) の流動性モデル**に照らし合わせれば、答えは「有効だが、あくまでプロキシ（代替変数）として」である。深夜帯は単純にノイズトレーダー（非情報系のランダムな取引者）の層が薄くなり、相対的に情報トレーダーの **Price Impact（価格破壊力）が激増する** 時間帯である。
したがって「時間」をトリガーにして休止するのは、手っ取り早い止血としては極めて正しい（Causalityそのものではないが、流動性薄を捉える強力なProxyである）。「アグレッシブすぎないか」などと躊躇せず、負けの偏る時間帯のHard Skipや損失Capは即座に実運用に組み込むべきだ。

### 9.5 One-sided（片側）縮退運転と「在庫リスク」の最終定理

202# で導入された「one_sided_balance rescue」等の縮退運用についてだが、まだ生ぬるい。一方向で74%の損失を出しているのに、まだ「Cooldownで様子見」でお茶を濁している。
Ho-Stoll (1981) や Avellaneda-Stoikov の厳密な解に従えば、片側で極端な逆選択を食らい続けている（＝構造的にPINが偏っている）状況下では、Reservation Price（基準価格）を非対称にするだけでなく、**毒性が抜けるまでの間、該当サイドの流動性提供を「完全停止（Halt）」するのが正解**である。
片側が燃えているのに、わざわざ火の中に手を入れて「Rescue（救出）」しようとするな。火が消えるまでそのサイドの扉を物理的に溶接して閉じる（One-sided Hard Halt）べきだ。

### 9.6 最終アクションプラン（Claudeにも却下させない「大義」の完遂）

我々の大義は「短期間での高収益性」である。「徐々に直す」猶予はない。以下の実装を最優先のP0として遂行せよ。

1. **Velocityの完全SSOT化**: mid_trend_bps を即刻破棄し、MLパイプラインの price_velocity_60s （またはその派生）への強制的一本化。システムの二重人格を終わらせる。
2. **Toxic Flow 検知（OFI / PINプロキシ）の導入**: 「価格が動いた」ではなく、「板のフローが偏った」時点で発注をSkipするハードゲート（204# Q / P）の構築準備。
3. **時間帯ベースの強制Cap発動（Kyle Proxy）**: 流動性枯渇+被ダメージ増幅の時間帯を統計から割り出し（204# 参照）、容赦なく稼働を止めろ。
4. **不調サイドの「完全封鎖」ロジック**: Cooldownではなく、片側Drawdownが規定値を超えた瞬間の「指定時間内の片側完全発注禁止」機能の実装。

理論と実証は揃っている。あとはこれらを実世界のコードへ撃ち込むだけだ。
