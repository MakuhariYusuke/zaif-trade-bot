## §0 Executive Summary

**本分析の核心的発見: この取引システムの損失は「時間帯」が原因ではなく、3つの構造的欠陥に起因する。**

| 根本原因 | 影響度 | 解決方向性 |
|---|---|---|
| 1. Skip Gate の予測能力が零 (r=-0.010) | 致命的 | モデル再構築 or 廃止+代替 |
| 2. Offset ceilingがAS回避を妨害 | 高 | ceiling動的化 |
| 3. ranging+buy の Profit Factor 0.766 | 高 | regime別side戦略 |

時間帯フィルタは「特定時間帯で損する」事実を反映しているように見えるが、それは上記3因子が特定時間帯で重畳するだけであり、時間帯自体が原因ではない。

## §1 AS (Adverse Selection) の構造分析

### 1.1 基本事実

| 指標 | AS=True | AS=False | 差分 |
|---|---|---|---|
| 件数 | 960 (27.2%) | 2,575 (72.8%) | - |
| 30s PnL mean | **-6.479 bps** | **+2.173 bps** | 8.65 bps |
| 30s win% | **0%** | **66%** | - |

> AS flagが立った取引は **100%負け**。逆にASなしは66%勝ち。
> つまり**ASの事前回避がシステム全体の収益を支配している**。

### 1.2 ASが選ぶべきでない取引を選んでいる

AS発生時と非発生時の「注文時点の状態」を比較した結果、**差がほぼない**：

| 指標 | AS=True | AS=False | 差 |
|---|---|---|---|
| spread (bps) | 2.407 | 2.338 | +0.069 |
| offset | 0.261 | 0.244 | +0.017 |
| OB imbalance | 0.008 | 0.013 | -0.005 |
| price velocity | 0.140 | 0.327 | **-0.187** |
| ev_score | **-0.073** | **+0.180** | **-0.253** |
| VG triggered | 38.9% | 41.9% | -3.0% |
| queue_wait (sec) | 21.8 | 22.6 | -0.8 |

**気づき**:
- ev_score は AS=True で**負** → EV scoreはAS予測に使えるヒントを持っている
- price_velocity は AS=True で**低い** → 「静かな」市場でASが多い（逆に感じるが、velocityが低い=方向性が読めない=急変に脆弱）
- VGはAS時により発動率が**低い** → VGが発動しない時の方がAS危険

### 1.3 Offset Pipeline分析: ceilingがAS回避を阻害

AS発生時のoffset各ステージを非AS時と比較：

| stage | AS mean | noAS mean | 差分 | 判定 |
|---|---|---|---|---|
| base | 0.1253 | 0.1116 | +0.014 | |
| **as_shift** | 0.2081 | 0.1812 | **+0.027** | ★ |
| **spread_adapt** | 0.2469 | 0.2204 | **+0.027** | ★ |
| **kyle** | 0.2453 | 0.2187 | **+0.027** | ★ |
| final | 0.2849 | 0.2696 | +0.015 | |
| **ceiling** | 0.1776 | 0.1787 | **-0.001** | ← ここが問題 |

**致命的な構造**: AS危険時、pipelineは正しくoffsetを+0.027増やすが、最終的にceilingで**全てカット**される。ceiling値は AS/非ASで**ほぼ同じ(0.178)**。

→ pipelineはASリスクを検知している。しかしceilingが「全員同じ」ため、ASリスク検知が無効化されている。

Buy側: clamped 321件, ceiling超過 mean=0.080, max=0.300
→ 必要なoffsetが0.300超過なのに0.150で切られている

## §9 統合的根本原因診断

### 損失のメカニズムチェーン

```
1. SkipGateが取引品質を予測できない (r≈0)
   ↓
2. AS危険な取引も「通過」してしまう
   ↓
3. Offset pipelineはASリスクを検知してoffsetを上げようとする
   ↓
4. しかしceiling(0.150)で一律カットされる
   ↓
5. 不十分なoffsetでfillされる
   ↓
6. AS発生 → 100% 負け (PnL -6.5 bps)
   ↓
7. 特にranging+buy, trending_up+sell で悪化
```

### 時間帯との関係

「特定時間帯で損する」のは、以下が重畳する結果：
- 特定時間帯で regime 判定が不安定（unknownが増える）
- 特定時間帯で spread が広がる（AS損失が大きくなる）
- 特定時間帯で balance_forced が増える

時間帯フィルタは表面的に効くが、根本解決にならない。

## §10 改善提言（優先順位付き）

### P0: Ceiling 動的化 (最優先)

**現状**: buy ceiling = 0.150, sell ceiling = 0.150 で一律固定
**問題**: AS危険時でも同じceilingが適用され、pipelineの判断が無効化

**提案**: ceilingをAS確率の推定値に応じて動的に設定

```
ceiling = base_ceiling + as_prob_adjustment
例: base_ceiling=0.15, AS確率高→ceiling 0.25-0.30
```

根拠: 321件のbuy clampで平均0.08 (max 0.30) の超過 → ceiling を0.23程度にするだけで多数のAS回避が成立し得る

### P1: Skip Gate モデル再構築

**現状**: r = -0.010 → ランダムと同等
**問題**: パス/スキップの判断が完全にノイズ

**提案**:
- 短期的: SGスコア閾値を有効範囲に限定（score ∈ [-5.5, -5.0] のゾーンはn=384と多く PnL≈0、ここだけ通す場合のコスト検証）
- 中期的: adverseSelection flag自体を目的変数としたモデル再学習
- 長期的: skip gate → adverse selection gate に名前・目的変更

### P2: ranging+buy 戦略の再検討

**現状**: PF = 0.766 (取引量最大のカテゴリ)
**問題**: ranging市場ではbuy側の方が勝率が低い

**提案**:
- ranging時のbuy offsetを+0.03-0.05引き上げ（regime stage で対応可能）
- ranging + buy + ev_score < 0 の組合せを skip 可能にする
- buy→sell のbalance_forcedをranging時は抑制（AS率32.8%）

### P3: Reprice制限

**現状**: reprice毎にPnL悪化 (-0.221 → -0.728 → -2.213)
**問題**: 価格を追いかけてfillするほど逆選択される

**提案**:
- reprice上限を1回にハードリミット
- reprice_drift > 5.0 bps で即キャンセル（現在 mean 6.7 bps は多すぎ）

### P4: regime_confidence 過信フィルタ

**現状**: confidence=1.0 が最悪 (AS 37%, PnL -1.046)
**問題**: 「完全自信」はoverfitting

**提案**: regime_confidence > 0.95 の場合にoffset +0.02 追加ペナルティ

### P5: regime変化検出時のearly exit

**現状**: 注文→fill間でレジーム変化 = PnL -2.294 (通常の57倍悪い)
**問題**: 3%しかないが影響大

**提案**: fill後にregime_at_order ≠ regime を検出した場合、即時ポジション解消フラグ

## §12 まとめ

本分析により、「勿体ない取引」の根本原因は3つに集約された：

1. **Skip Gateの予測能力零** → 悪い取引を止められない
2. **Ceiling一律固定** → AS検知の成果がceilingで無効化される
3. **ranging+buy の構造的不利** → 最大取引量カテゴリがPF < 0.8

時間帯フィルタはこれらの上流因子が特定時間帯で重畳した「結果」を表面的に避けるだけであり、根本解決にはならない。上記P0-P5の構造改善が先決。

特にP0 (ceiling動的化) は**既にpipelineがASリスクを正しく検知している**にも関わらず、ceilingが一律でその判断を無効化しているという「勿体ない」状態を直接解消する、最も即効性の高い改善。
