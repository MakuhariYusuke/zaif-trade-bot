## 2. 023の良い点

- P0最優先という順序は妥当。  
- 並行タスクを明示して「待機時間を無駄にしない」思想は正しい。  
- G1.1 依存の有無を整理している点は運用しやすい。

---

## 3. 再設計案（実行順）

### Lane A: 計測信頼性（最優先）

1. P0を `024` 基準に更新して即実施。  
2. fill test の保存成否・行数増分・最新timestampを監視指標に統一。  
3. `unknown fill` 判定を導入し、E1/E5のバイアスを除去。  
4. G1.1判定は `run_id` 単位で算出（混在防止）。

### Lane B: 収益性分析（非破壊）

1. P1-B は既存 `run_pnl_monte_carlo.py` を使用。  
2. `run_gate_check --with-mc` の呼び出し不整合を先に修正してから統合運用する。  
3. Monte Carlo は「全期間」と「直近run_id」の2系統で出す。  
4. 感度分析（fill_rate / pnl_shift）を必須化して、閾値変更の根拠を作る。

### Lane C: 将来準備（限定）

1. P1-C は OHLCV再試験を縮小し、real特徴量準備に寄せる。  
2. P1-E は `scripts/v460/lib/tasks/sac_train.py` の監査中心にし、新規骨格実装は最小化。  
3. P1-A/P2 の破壊的変更は G1.1 判定後に着手。

---

## 4. 追加提案（範囲外を含む）

1. **Gate運用**: E1/E5 は点推定だけでなく Wilson 区間を併記し、早期判断の過信を防ぐ。  
2. **実験設計**: offset比率を固定値でなく小グリッドで同時運転し、最適化をオンライン化。  
3. **レジーム分解**: 上昇/下落/高ボラで指標を分解し、AS悪化の局所条件を特定。  
4. **監視自動化**: save失敗回数・unsaved_batch長・APIエラー率をアラート化。  
5. **再現性強化**: fill_recordsに `config_hash` も追加し、同一run比較を厳密化。

---

## 5. 結論

023は方向性は良いが、現状に対して前提が古い箇所と、優先順位が逆転している箇所があります。  
`P0計測信頼性` を先に固定し、`分析は既存実装再利用`、`破壊的リファクタは後段` へ並べ替えると、時間ロスと判定誤りを同時に減らせます。
