## §1 §3.1: fallback 品質判定

### 問題
`skip_gate.py` の fallback トリガーが `any(col in features for col in OB_CRITICAL_FEATURES)` — キーの存在チェック。
`build_features_from_market_state()` は常に `spread_bps_ob` / `depth_imbalance_ob` を生成する (0.0 含む) ため、**fallback が実質発火しない**。

### 修正
`_check_ob_quality()` メソッドを新設。以下3条件を全て満たす場合のみ OB 有効:

1. `spread_bps_ob` が有限かつ > 0 (bid=ask や mid=0 を弾く)
2. `depth_imbalance_ob` が有限 (NaN/Inf を弾く)
3. `ob_age_sec` が `ob_freshness_sec` (デフォルト 3 秒) 以内

### テスト追加
`Test068OBQualityCheck` — 8 テスト (valid/zero/nan/missing/stale/fresh/negative)

## §3 §3.3: side 別閾値

### SkipGateConfig 追加

```python
as_threshold_buy: Optional[float] = None   # None = 共通 as_threshold 使用
as_threshold_sell: Optional[float] = None
```

### evaluate() 変更

```python
def evaluate(self, features, *, side=None, ob_age_sec=None) -> SkipDecision:
```

`side="buy"` + `as_threshold_buy` 設定あり → buy 側閾値を優先使用。

### YAML 設定

```yaml
skip_gate:
  as_threshold: 0.65           # 共通
  as_threshold_buy: null       # buy は共通値
  as_threshold_sell: 0.60      # sell 厳格化
```

**sell を 0.60 に設定**: 067# §2 で sell PnL が buy の 3 倍悪い (-0.958 vs -0.301)。sell 側を先に厳格化。

### テスト追加
`Test068SkipGateSideThreshold` — 3 テスト (common/sell_stricter/buy_override)

## §4 §3.4: OB 不良時安全運転

### FillTestConfig 追加

| フィールド | デフォルト | 説明 |
|-----------|----------|------|
| `ob_fail_max_consecutive` | 5 | 連続 OB 不良で `ob_safety_stop` |
| `ob_fail_offset_boost` | 1.5 | OB 不良時の offset 倍率 |

### 動作

```
OB品質不良検出 (spread<=0 or NaN or stale)
  ├── _consecutive_ob_failures++ 
  ├── < max → offset × ob_fail_offset_boost で継続
  └── ≥ max → cancel_reason="ob_safety_stop" でサイクル停止
OB品質正常 → _consecutive_ob_failures = 0 (リセット)
```

068# §3.4 の「lotを最小固定」は、OB 不良時は既にフォールバック (ほぼ中立) に退化するため、lot 変更は入金後の fill test でデータ収集してから判断する。
