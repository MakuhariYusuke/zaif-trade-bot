## §0 結論（先に要点）

1. `067` の方向性は大筋妥当。ただし「板なしでもいけるモデル」の位置付けが楽観的すぎる。現状データでは **OBなし単独での収益改善根拠は弱い**。  
2. `066` の比較結果どおり、trade-only は ROC-AUC が高くても Skip20% 改善がほぼゼロ。ph2の目的（悪い約定の除外）に対しては **尾部リスク検出力不足**。  
3. 実装上の重要な不整合がある。`skip_gate.py` の fallback 判定は「NaN/欠損」ではなく「キー存在」で判定しており、説明文どおりには動きにくい。  
4. v459教訓に照らすと、今やるべきは「モデル追加」よりも「判定系の厳格化」と「撤退基準の前倒し固定」。

## §1 重大論点（批判的レビュー）

### 1.1 Two-Tier fallback の実動作が仕様説明とズレている

`067`/`066` では「OB特徴量が NaN のとき fallback」と説明されているが、実装は以下。

- `scripts/v460/ml/skip_gate.py` で `ob_available = any(col in features for col in OB_CRITICAL_FEATURES)`
- `scripts/v460/ml/skip_gate.py` の `build_features_from_market_state()` は `spread_bps_ob` / `depth_imbalance_ob` を常に生成（0.0含む）

この組み合わせだと、**OBが実質使えない場面でも primary に流れやすい**。  
板なしモデルを活かす前提の根幹なので、最優先で修正すべき。

### 1.2 「板なしで継続運転」の前提がランナー設計上弱い

`run_fill_test.py` は maker価格算出で `get_orderbook()` に依存し、失敗時は `orderbook_error` でサイクル終了する構造。  
つまり、skip gate の fallback が動いても、**発注前段で止まるため板なし継続は限定的**。

### 1.3 指標の目的不一致

`066` の結果は典型的に「分類指標と実運用価値の乖離」を示している。

- trade-only: ROC-AUC は高め
- だが Skip20% はゼロ近傍

ph2で重視すべきは ROC-AUC ではなく、以下。

1. Skip上位分位での `post_fill_30s_pnl` 改善
2. AS比率の低下
3. fill_rate の悪化最小化

### 1.4 サンプルサイズ問題は「絶対数」より「検定設計」が問題

166サンプル自体は即NGではないが、v459の失敗（単発成功の崩壊）を踏まえると、
「6fold 1セット」での採用判断は弱い。  
`v459/101` と `v459/116` の教訓どおり、window分割と対照群を固定した反証が必要。

## §2 板情報なしモデルの正しい位置付け

### 2.1 採用方針

- **Primary**: OBありモデル（現行 A(k=12)）
- **Fallback**: OBなしモデル（Curated k=5）
- **禁止**: 現時点で OBなしを primary 化すること

理由: `066` 時点で OBなしは「ほぼ中立」。収益エッジよりも可用性保険の役割が妥当。

### 2.2 ph2投入時の運用ルール（提案）

1. まず 300 サイクルは shadow で板なしモデルのスコアのみ記録（売買判定には使わない）
2. 次に「限定有効化」: 1日あたり最大20サイクルまで板なし判定を実売買に反映
3. 効果が閾値未達なら fallback専用に戻す

## §3 すぐ着手すべき実装修正（待ち時間なし）

### 3.1 fallback発火条件を「キー有無」から「品質判定」に変更

最低限、以下を満たす場合のみ `ob_available=True` とする。

- `spread_bps_ob` が有限かつ > 0
- `depth_imbalance_ob` が有限
- 板取得時刻の鮮度が閾値以内（例: 3秒以内）

### 3.2 OB品質フラグをログに保存

`FillRecord` に以下を追加して、後で分解検証可能にする。

- `ob_quality_ok`
- `ob_age_ms`
- `skip_gate_model_used`（primary/fallback）

### 3.3 side別閾値の導入

`067` の sell 劣後（PnL悪化）が大きいため、`as_threshold` を side別に持たせる。

- 例: `buy=0.65`, `sell=0.60`（sellを先に厳格化）

### 3.4 「板なし時の安全運転」を明文化

板情報不良時は以下を強制。

1. lotを最小固定
2. spread_offsetを保守側へ拡大
3. 一定回数連続で板不良なら自動停止

## §5 067のQ1-Q4への回答（簡潔版）

1. **Q1 妥当性**: 現状は「有望だが未確定」。採用可否は bootstrap/分割再検証を通して確定すべき。  
2. **Q2 G1 FAIL後の継続**: 許容可能。ただし「G1代替」ではなく「G1.1内の局所改善施策」と明記すること。  
3. **Q3 次に粘る方向**: OBありprimary維持 + OBなしfallback強化が最適。OBなしprimary化は時期尚早。  
4. **Q4 過去資産活用**: v459の統計・反実仮想・window分割評価を未だ活かし切れていない。

## §6 Go/No-Go ルール（板なしモデル限定）

板なしモデルを「fallback専用」から「限定実運用」に昇格する条件:

1. shadow 300サイクルで Skip上位20%の `post_fill_30s_pnl` が baseline 比 +0.15 bps 以上
2. 同期間で AS_ratio が baseline 比 3pt 以上低下
3. fill_rate 悪化が 2pt 以内
4. 日別で逆転（悪化日）が 1/3 以下

1つでも未達なら、板なしモデルは fallback専用のまま据え置く。
