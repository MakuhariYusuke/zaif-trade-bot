## 2. アーキテクチャと実行フロー

### コアファイル
- **`scripts/v460/run_fill_test.py`** (2,429 行): メイン実行ランナー
- **`configs/v460/fill_test.yaml`**: 設定ファイル
- **`ztb/metrics/fill_quality.py`**: 分析ライブラリ
- **`scripts/v460/ml/skip_gate.py`**: SkipGate ML フィルタ

### 1 サイクルの実行フロー

```
1. Ticker 取得 (best_bid, best_ask → spread 計算)
2. Time Filter 判定 (UTC hour × side で skip)
3. Regime Detection (trending/ranging 判定)
4. Offset 計算:
   - base = spread × spread_offset_ratio (0.05)
   - sell 側: × side_offset.sell (0.12)
   - trending: × trending_offset_boost (1.5)
   - spread_adaptive: narrow なら ×2.0, wide なら ×0.5
5. SkipGate ML 判定 (AS 確率推定 → skip 可否)
6. Maker limit order 発注
7. Fill 監視 (最大 timeout_sec 秒待機)
8. Fill 後: mid_at_fill 記録, 30s 後の mid 価格で PnL 計算
9. Early Exit: fill 直後に ±5.0 bps 以上で即キャンセル検討
10. 結果を JSONL に保存
```

### 主要コンポーネント

| コンポーネント | 状態 | 概要 |
|---------------|------|-----|
| **Spread Offset** | ✅ 稼働 | `spread × 0.05` で mid からオフセット |
| **Side Offset** | ✅ 稼働 | sell 側のみ `×0.12` (保守的) |
| **Time Filter** | ✅ 稼働 | UTC hour × side で skip |
| **Regime Detection** | ⚠️ 不十分 | 81% が "unknown" |
| **SkipGate ML** | ❌ 機能不全 | 501 サイクル中 0 skip |
| **Early Exit** | ❌ 未発火 | 0 回トリガー |
| **Adaptation** | ⚠️ 不明 | offset_ratio 記録なし |
| **Spread Adaptive** | ✅ 稼働 | narrow/wide スプレッド対応 |
| **Fast Fill Defense** | ⚠️ 未発火 | 0 回 |
| **Imbalance** | ⛔ 無効化 | 071# で無効化 |
| **Smart Side** | ⛔ 無効化 | 071# で無効化 |

## 10. 構造的問題の特定

### 問題 1: SkipGate ML が完全に機能不全 [CRITICAL]

**症状:**
- `skip_gate.enabled: true` にもかかわらず、501 サイクル中 **0 回もスキップされていない**
- SkipGate スコアが記録されたのは **10 レコードのみ** (501 中)
- スコア範囲: -5.31 ~ -4.75 (非常に狭い)、std=0.15

**推定原因:**
- モデルファイル `models/v460/skip_gate_as.pkl` は存在する
- しかしスコアが 10/501 でしか記録されていない → モデルが殆どのケースで例外を出している可能性
- スコア値が -5.0 付近に集中 → AS 確率として解釈不能 (0.0~1.0 のはずが log-odds 形式?)
- `as_threshold: 0.65` と比較すると、スコア -5.0 は常に `should_skip = False` になる

**影響:**
- 注文前フィルタリングが全く効いておらず、AS 率 39% そのまま

### 問題 2: Edge at Fill が一貫してマイナス [HIGH]

**症状:**
- 全体 Edge 平均: -0.357 bps
- Fill の 56.2% が -Edge (adverse selection)
- 時系列でも改善傾向なし

**推定原因:**
- `spread_offset_ratio: 0.05` が小さすぎる可能性
- spread 平均 2,272 JPY × 0.05 = 113.6 JPY のオフセット
- しかしこれは 0.001 bps 程度で、実質的に mid price 付近に配置
- AS にさらされやすい

**ジレンマ:**
- offset を上げると fill 率低下
- offset を下げると AS 増加
- 現在はこのトレードオフの悪い側にいる

### 問題 3: Sell 側の恒常的弱さ [HIGH]

**症状:**
- Buy: -0.318 bps vs Sell: -0.953 bps (差: 0.635 bps)
- Sell Edge: -0.426 vs Buy Edge: -0.290
- 時系列分析でも多くの窓で Sell が大幅マイナス

**推定原因:**
- `side_offset.sell: 0.12` で保守化しているが不十分
- BTC/JPY は長期的に上昇バイアスがあり、Sell 側の AS が本質的に高い
- まだ Sell 側のオフセットが足りない

### 問題 4: Regime Detection が 81% "unknown" [MEDIUM]

**症状:**
- 307/379 (81%) が "unknown" レジーム
- trending 検知は 19 件のみで、PnL も -1.209 と最悪

**推定原因:**
- `trend_threshold_pct: 0.5` が高すぎる (0.5% の変動を要求)
- `window: 20` が短期データに対して不適切
- BTC の短期では 0.5% のトレンドは稀

### 問題 5: Early Exit が一度も発火していない [MEDIUM]

**症状:**
- `early_exit.enabled: true`, `threshold_bps: 5.0` だが 0 回発火

**推定原因:**
- fill 後 30s の PnL が ±5 bps 超えるのは約 12% (両端合計) だが、Early Exit はリアルタイム監視
- `monitoring_interval_sec: 5.0` (5秒間隔チェック) では ±5 bps の瞬間を逃している可能性
- あるいは Early Exit のロジックが fill 後の反対注文 (利確/損切) を前提としているが、この fill_test ではそもそも反対注文を出さない

### 問題 6: Adaptation (offset 自動調整) の記録が無い [LOW]

**症状:**
- `adaptation.enabled: true` だが、`offset_ratio` が 0 レコードに記録
- effective_offset 等すべて未記録

**推定原因:**
- FillRecord に offset_ratio フィールドがあるが、記録コードが未実装or無効
- 適応が行われているかどうか検証不能

## 付録: 技術詳細

### A. FillRecord 主要フィールド

```python
@dataclass
class FillRecord:
    cycle_id: int
    timestamp: float           # UNIX timestamp
    side: str                  # "buy" or "sell"
    order_price: float         # 注文価格 (JPY)
    order_quantity: float      # 注文数量 (BTC)
    fill_price: float          # 約定価格 (JPY)
    filled: bool               # 約定したか
    cancelled: bool            # キャンセルされたか
    cancel_reason: str         # キャンセル理由
    queue_wait_sec: float      # 約定までの待機時間 (秒)
    mid_at_order: float        # 注文時の mid price
    mid_at_fill: float         # 約定時の mid price
    spread_at_order: float     # 注文時のスプレッド (JPY)
    post_fill_30s_pnl: float   # 約定30秒後のPnL (bps)
    adverse_selected: bool     # AS判定 (deadzone考慮)
    skip_gate_skipped: bool    # SkipGateでスキップされたか
    skip_gate_score: float     # SkipGateスコア
    regime: str                # "trending", "ranging", "unknown"
```

### B. 計算式

```
Edge at Fill (bps):
  buy:  (mid_at_fill - fill_price) / mid_at_fill × 10000
  sell: (fill_price - mid_at_fill) / mid_at_fill × 10000

PnL 30s (bps):
  buy:  (mid_30s - fill_price) / fill_price × 10000
  sell: (fill_price - mid_30s) / fill_price × 10000

Offset (JPY):
  base = spread × spread_offset_ratio
  sell: base × side_offset.sell
  trending: base × trending_offset_boost
```
