## 1. 実装した修正

### 1.1 R1: `_try_save_batch()` — 保存専用リトライ

```
_save_batch(batch)          ← 旧: try内で直接呼出、例外は大域catchに吸収
↓
_try_save_batch(batch)      ← 新: 独立try/except、3回リトライ(指数バックオフ)
  ├─ 成功 → True, batch クリア
  ├─ 失敗(連続3回未満) → False, batch 保持 → 次サイクルで再試行
  └─ 失敗(連続3回以上) → _emergency_dump() でフォールバック保存
```

### 1.2 R2: 例外分離

```python
# 旧: 全てを1つの try/except で処理
try:
    record = await self.run_single_cycle()
    ...
    self._save_batch(batch)  # ← 保存例外もここで捕捉
    batch = []
except Exception:
    continue  # ← 全例外を握り潰し

# 新: サイクル実行と保存を分離
try:
    record = await self.run_single_cycle()
except Exception:
    continue  # サイクルエラーは継続可能

# 保存は独立した _try_save_batch で処理 (リトライ付き)
if len(batch) >= batch_size:
    if self._try_save_batch(batch):
        batch = []
```

### 1.3 R4: record.timestamp ベースの日付ファイル分割

```python
# 旧: datetime.now(UTC) → プロセス時刻に依存
day_str = datetime.now(timezone.utc).strftime("%Y%m%d")

# 新: record.timestamp → レコード発生時刻に基づく (追跡性向上)
for record in batch:
    day_str = datetime.fromtimestamp(record.timestamp, tz=timezone.utc).strftime("%Y%m%d")
    by_date.setdefault(day_str, []).append(record)
```

## 4. R3 (WAL) 見送り理由

- `batch_size=10` (=約20分) で十分な頻度
- `_try_save_batch` のリトライ + `_emergency_dump` で N 回失敗時も救出可能
- `_cleanup_sync` (atexit) で未保存分を退避
- WAL 実装のオーバーヘッド vs 実益が見合わない（120秒/サイクルで I/O 頻度は低い）
