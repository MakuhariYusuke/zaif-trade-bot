## 1. 致命的指摘のクロスバリデーション

### 1.1 `EV > 0` ロジックの解釈エラー (The Confident-Wrong Paradox)
391# の RC-3 は「EV>0 は価格上昇予測。なのにSellするのはロジックの不整合だ」と解釈していますが、これは**完全な誤り**です。

**【コード実証】**
`ztb/ml/skip_gate.py` の `evaluate(self, features, side, ...)` において、予測結果は `predicted_pnl_bps` として返却されています。
つまり、**`Sell` 時に算出される `EV > 0` は、「（価格が下がるため）Sellをすれば利益が出るはずだ」というAIの予測**を意味します。

**【結論】**
`Sell` で `EV [1,2)`（自信満々）なのに勝率（WR）が29%しかないという事実は、ハードコードされたルールエンジンがおかしいのではなく、**MLモデルの予測が完全に現実（Profit）と逆行して外れている**という事実を示しています。
これこそがClaude（易）の言う**「RewardがProfitを向いていないまま突き進んでいる（＝幻の豊）」**状態です。モデルは「儲かる」と錯覚しているのです。

### 1.2 HFT哲学との衝突（RC-4 への対策）
391# は「5分に1回しか約定させない（`min_fill_interval_seconds=300`）」というハード抑制（RC-4対応）を提案していますが、これは**高頻度取引（HFT）ボットとしてのアイデンティティを放棄する敗北宣言**です。

**【コード実証】**
393# の指摘通り、現在のアーキテクチャ（`configs/v460/fill_test.yaml`）には既に強靭な「動的防御」が組み込まれています。
*   `toxic_fill_veto_threshold_bps: -3.0`
*   `sell_dynamic_kill / buy_dynamic_kill`

**【結論】**
休むべきは「一律に5分」ではなく「相場に逆選択された（喰われた）直後」だけです。ルールベースの強制一律Pauseではなく、既存の `toxic_fill_veto` や `dynamic_kill` の閾値をサイド別・レジーム別に再較正（Calibration）することが、Profit-Firstの戦術です。

### 1.3 再発したGhost Metric Paradox (Mixed-SHA 問題)
3/9〜3/12の4日間には、381#で決定・反映した重要なConfig変更（`sell_hour_offset_boost`拡張, `offset_ceiling`の厳格化）が含まれています。
**前後の異なるルールのログを一つに混ぜて「3/12のBuyが劣化している、主犯は0.20だろう」と断定するのは、全く論理的ではありません。** 381#で我々が「撤廃された指標による分析（Ghost Metric）」を排除した直後に、また同じデータ汚染の罠を踏んでしまっています。
