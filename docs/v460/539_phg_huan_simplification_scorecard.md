# 539# 風水渙 第三爻変の実践：状態棚卸しと削減スコアカードの策定

- **日付**: 2026-03-22
- **目的**: 538# のセカンドオピニオンを受け、単なる「断捨離」というスローガンを脱却する。正確なパラメータ状態の把握（棚卸し）と、簡素化の成否を測る定量的指標（スコアカード）を定義し、具体的な改修フェーズを示す。

## §1. 理念のエンジニアリング的再定義（風水渙 第三爻変）

第三爻変「渙其躬（そのみをかんす）。无悔（くいなし）」について、破音字のニュアンスを踏まえ、システム改修の3フェーズとして再定義する。

1. **【散らす】執着の破棄 (Pruning)**
   - **意味**: 過去の成功体験や場当たり的なパッチを物理的に削る。手放す恐怖を振り払う。
   - **対象**: `sell_dynamic_kill` のような遅行指標ベースのロジックや、12h/15h といった時間帯ハードコード（運用者のエゴ）。
2. **【渙める】氷の融解と連続化 (Liquefaction)**
   - **意味**: 0か1かで取引を遮断するガチガチのHard Gateを融解させ、滑らかな確率的スコアリングに緩和する。
   - **対象**: 9段の乗算チェーンによる Pipeline の 100% クリッピング（天井飽和・デッドロック）を、Sigmoid/Logitなどの正規化で滑らかに繋ぐ。
3. **【渙発する】普遍的力学の波及 (Propagation)**
   - **意味**: 断片化されたロジックを取り払った後、市場の根源的な力学を全体に行き渡らせる。
   - **対象**: 多くの散在する Soft Gate を、OFI (Order Flow Imbalance) や ATR といった根源的指標のHubに集約し、予測的防御を主軸とする。

## §2. 現行パラメータの状態棚卸し（Fact Check）

538# で指摘された通り、「これから導入すべき施策」と誤認されていた設定の**真の現在状態**を整理する。問題は機能不足ではなく、すでに入りすぎていて管理不能になっていることである。

| パラメータ / 構成 | 現行設定 (fill_test.yaml等) | 実態と今後の真の論点 |
| :--- | :--- | :--- |
| `min_spread_jpy` | `500` (535#で変更済) | 既に下げられている。論点は「これを固定値としている構造自体を剥がし、ボラティリティ（ATR）連動に置き換えるか」である。 |
| `composite_risk_enabled` | `true` (有効化済) | 既に有効。論点は「単なる判断軸の上乗せになっていないか。既存の個別Soft Gateをこれで**完全置換**できるか」である。 |
| Sidecar TTL | `7800s` (延長済) | 既に長い。論点は「TTLが長くても、市場環境が変われば推論値はStale（無価値・有害）化しているのではないか」の検証。 |
| `cross_venue` veto | `max_consecutive` 搭載済 | 既に緩和処理が入っている。論点は「そもそもこの複雑な例外分岐自体を刈り取れるか」。 |

## §3. 削減スコアカード（Simplification Metrics）

「簡素化に成功したか」を定量評価するためのメトリクス。現状（Before）から目標（After）へと数値を改善していくことで、単なる勘に頼らないリファクタリングを実施する。

| 計測項目 | 現在の推定値 | 目標値 | 測定方法 / 意義 |
| :--- | :--- | :--- | :--- |
| **制約系の総Gate数** | 9 (Hard 4 + Soft 5) | **3〜4に半減** | デッドロックの原因となる判断ブロックを減らし、見送りの理由を単一化する。 |
| **Pipeline Multiplier** | 9段の乗算チェーン | **3段以下の加重** | オフセット算出のブラックボックス化と異常な掛け算のインフレを防ぎ、解釈性を高める。 |
| **Clamp（飽和）率** | ほぼ 100% | **5% 未満** | Ceiling 0.25 への恒常的な頭打ち状態を解消し、パイプラインの微細な計算を実際の価格に反映させる。 |
| **1 Cycle 見送り理由** | 複数・重複 | **単一 (明確化)** | 取引見送り時のログ分析コストを下げ、不透明さを排除。 |

## §4. 具体行動計画（Action Plan）

スコアカードの目標を達成するため、以下の順序で実装へ入る。一気にすべてを変更することは避ける。

### Phase 1: 【散らす】Dead Logic の削除 (Safe Pruning)
- **行動**: `sell_dynamic_kill` の削除 / 無効化。時間帯ハードコード（12h/15h）などをHardブロックから外し、単なるフラグ情報へと格下げする。
- **狙い**: まず「遅行型の防衛線」を取り払い、Gate数を物理的に減らす。

### Phase 2: 【渙める】Pipeline 飽和の解消 (Normalization)
- **行動**: Ceiling limit に当てて切り捨てる乗算アルゴリズムを捨て、各 Stage の推論をもとに Sigmoid 等を用いた「加重平均・正規化」へリファクタリング。
- **狙い**: Clamp飽和率を大幅に低下させる（まずは pre-clamp distribution ログから実態を再確認する）。

### Phase 3: 【渙発する】OFI Hub への統合 (Prediction Hub)
- **行動**: 上手く機能していない Soft Gate 群を撤去。代わりに OFI (Order Flow Imbalance) による Toxic Flow（逆選択コスト）の予測を基盤とし、スプレッドにそのコストを加算する設計への一本化。
- **狙い**: 現時点で多次元化しすぎた判断基準を低次元化し、システム全体の透明性と予測精度を高める。
