# SELL-Lockバイアス調査: フェーズ1 & 2 サマリー

## 1. はじめに

本ドキュメントは、取引ボットで観測された「SELL-Lock」（売却注文に固執し、非効率な状態に陥る）バイアスの調査に関するフェーズ1およびフェーズ2の作業内容と結果をまとめたものです。

## 2. 問題定義

エージェントが特定の条件下で、微小な量の売却注文を繰り返し試行し、資産を有効に活用できない「SELL-Lock」状態に陥る問題が確認されました。本調査の目的は、この問題の根本原因を特定し、解決策を実装することです。

## 3. フェーズ1: アクションスペースと検証

### 3.1. 仮説

連続的なアクションスペース（特に取引量）において、モデルが非常に小さく効果のない値をを出力している可能性が、SELL-Lockの一因であると仮定しました。

### 3.2. 調査と発見

- **アクションの処理**: `ActionValidator`が取引注文を検証する主要なコンポーネントであることを特定しました。
- **無効なアクション**: モデルが出力した微小な取引量は、最小取引単位に満たないため、`ActionValidator`によって無効化または丸められていました。しかし、エージェントは同様のアクションを学習し続けていました。

### 3.3. 実装された変更

- `ActionValidator`のロジックを強化し、最小取引量を下回る注文をより厳密に処理するように改善しました。
- このフェーズでの対策は対症療法的であり、なぜモデルがそのような微小な値を出力するのかという根本原因の解決には至らないことが示唆されました。

## 4. フェーズ2: ネットワークの初期化と構造

### 4.1. 仮説

モデルのデフォルトのニューラルネットワークアーキテクチャ（`net_arch`）が、複雑な市場の状態を捉えるには単純すぎるか、または不適切である可能性があり、その結果として最適でないアクション（SELL-Lockにつながる微小な売り注文など）を出力していると仮定しました。

### 4.2. 調査と実装

1.  **設定ファイルの読込改善**:
    - `ztb/training/unified_trainer/main.py`を修正し、従来のJSON形式に加えて`.ini`形式の設定ファイルを読み込めるようにしました。これにより、柔軟な設定管理が可能になりました。

2.  **`net_arch`の動的設定**:
    - `ztb/training/core/config_manager.py`を修正し、`.ini`ファイルから`net_arch`パラメータを読み込む機能を追加しました。
    - `ztb/training/unified_trainer/algorithms/sac_trainer.py`を修正し、読み込んだ`net_arch`を`SAC`モデルの`policy_kwargs`に渡すようにしました。

3.  **検証**:
    - 上記の変更が正しく機能することを確認するため、一時的なテストファイル (`tests/unit/training/algorithms/test_sac_net_arch.py`) と設定ファイル (`tests/config/test_net_arch_config.ini`) を作成し、ユニットテストを実施しました。
    - テストは成功し、設定ファイルから`net_arch`がモデルに正しく適用されることが検証されました。

### 4.3. 結果と考察

- この改善により、ニューラルネットワークのアーキテクチャを外部設定ファイルから柔軟に変更できるようになりました。これにより、今後の実験でネットワーク構造がモデルのパフォーマンスやSELL-Lockバイアスに与える影響を体系的に分析する基盤が整いました。
- 調査の結果、`stable-baselines3`の`SAC` (`MlpPolicy`)における`net_arch`のデフォルト値は`[256, 256]`であることが確認されました。

## 5. 結論と次のステップ

フェーズ1と2を通じて、SELL-Lock問題に対する直接的な対策（アクション検証の強化）と、根本原因を探るための基盤（ネットワーク構造の柔軟な設定）を構築しました。

これにより、今後の調査と改善のための強固な土台ができました。次のステップとして、**フェーズ3: 報酬関数の分析と改善**に進みます。報酬の設計がエージェントの行動に与える影響を詳細に調査し、SELL-Lockバイアスを解消するためのより効果的な報酬体系を設計・実装します。
