# v454 Roadmap: シグナル品質の向上と「逆説的確信」の解消

## 1. 現状分析 (v453までの発見)

### 1.1. 閾値とパフォーマンスの奇妙な関係
v453における閾値緩和実験により、モデルの出力強度（Action値）と実際の収益性の間に、直感に反する関係があることが判明した。

| Multiplier | 実効閾値 (概算) | 結果 (Total Return) | 挙動 |
| :--- | :--- | :--- | :--- |
| **1.0x (Buggy/Legacy)** | > 0.010 | **+12%** | **高収益**。微細なシグナルを全て拾う。 |
| **1.5x (Relaxed)** | > 0.015 | **-38%** | **大損失**。中程度のシグナルのみ拾う。 |
| **3.0x (Relaxed)** | > 0.030 | **-38%** | **大損失**。1.5xと変わらず。 |
| **10.0x (Strict)** | > 0.100 | **+6%** | **低収益**。強いシグナルのみ拾う。 |

### 1.2. 「逆説的確信 (Inverse Confidence Paradox)」
この結果から導き出される事実は以下の通りである。

1.  **高確度シグナルは嘘をつく**: モデルが「強く売買すべき（Action > 0.015）」と判断したトレード群は、**-38%の損失を生み出すゴミ**である。
2.  **低確度シグナルこそが宝**: モデルが「迷っている/微細な反応（0.010 < Action < 0.015）」を示したトレード群が、**上記の大損失を埋め合わせた上で+12%の利益を叩き出す**ほどの超高収益性を持っている。

つまり、現在のモデルは**「自信満々の時は間違っており、自信がない時ほど正しい」**という逆説的な状態にある。

## 2. 課題の特定

### 2.1. なぜ強いシグナルは負けるのか？ (仮説)
- **過剰反応 (Overreaction)**: 急激な価格変動（ヒゲやノイズ）に対して、モデルが過剰に反応してAction値を大きく出力している。しかし、それは往々にして「天井掴み」や「底売り」となる。
- **遅行性**: 強いトレンドが発生した「後」にAction値が高まっている場合、エントリーが遅すぎて反転に巻き込まれている。

### 2.2. なぜ弱いシグナルは勝てるのか？ (仮説)
- **先行性**: トレンドの初動や、ボラティリティが上がる前の静かな予兆を捉えている。
- **平均回帰**: レンジ相場内での微細な逆張り（Mean Reversion）が機能している。

## 3. v454 開発ロードマップ

v454の目標は、**「強いシグナルの品質を向上させ、Action値と期待収益率を正の相関に戻す」**ことである。

### 3.1. 短期的な対応 (v453.x)
まず、現行モデルで利益を確保するために、設定を「正解」に戻す。
- **Action**: `ThresholdManager` のMultiplierを **1.0x** に戻す。
- **Rationale**: 現状のモデルは「微細スキャルピング」に特化した性能を持っているため、それを阻害しない設定にする。

### 3.2. 中長期的な改善 (v454)

#### A. 報酬関数の再設計 (Reward Shaping)
「自信満々の大損失」を罰する仕組みを導入する。
- **案**: Actionの絶対値が大きい時の損失に対して、ペナルティ係数を大きくする（例：Action > 0.1 で負けた場合、報酬を2倍減算する）。これにより、モデルは「確信を持ってエントリーするなら、絶対に勝て」と学習する。

#### B. 入力特徴量の見直し (Feature Engineering)
ノイズに過剰反応しないためのフィルタリング。
- **案**: 短期的なボラティリティ（1分足のヒゲなど）を平滑化した特徴量、あるいはより長期のトレンド乖離率を重視させる。
- **案**: `MarketRegime` 情報をより直接的にモデルに入力し、「今はレンジだから強く反応するな」と学習させる。

#### C. モデル構造の検討
- **案**: 現在のSAC（Soft Actor-Critic）のエントロピー正則化係数（alpha）を調整し、探索と活用のバランスを変える。
- **案**: ネットワークのキャパシティ（層数やユニット数）が不足しており、複雑な相場環境（ノイズとトレンドの区別）を表現しきれていない可能性の検証。

## 4. 結論
「閾値を緩和すれば勝てる」という単純な話ではなく、**「モデルが出力するシグナルの強度が、実際の勝率とリンクしていない」**ことが根本的な問題である。
v454では、単なるパラメータ調整ではなく、モデルが「正しい確信」を持てるような学習プロセスの改善が必要となる。

## 5. AIレビューで判明した追加の調査事項と即時対策
外部AIエージェントのコードレビューにより、現状の対策が十分でない、あるいは逆説を助長し得る「根本原因候補」が複数指摘されました。短期的に着手すべきタスクを以下に示します。

- **環境の離散化が原因の可能性**: `ztb/trading/environment/heavy_env/core.py` で連続Actionを閾値で離散化しているため、Actionの絶対値=確信が環境側で“段差”になり、強い確信が校正されにくい。根本案: 環境を真の連続（ポジション量に応じて約定・PnLを滑らかに変える）にする、または離散アルゴ（PPO）に寄せる。
- **Confidence Penalty の改良点**: 現実装（`ztb/trading/environment/components/reward_calculator.py`）は閾値が高く（デフォルト0.1）かつstep単位のpnlに依存しているためノイズを誤検出しやすい。改善案: ペナルティはトレード単位（クローズ時実現損失やMAE）に寄せる、またはヒンジ型で係数を小さくする。ATR欠損はフラグ化して安全に扱う。
- **表現ゆれとバグ修正の優先箇所**: SELLの表現（-1 vs 2）の不一致（`ztb/trading/constants.py` と `reward_calculator.py` 等）を全体で統一する。RiskManagerの調整が上書きされ無効化されている (`position_manager.py`)、最小取引単位で強制的に丸めてしまうロジックがある（現金不足の際の誤った約定を招く）。これらは逆説を増幅し得るため優先的に修正する。
- **データ・リークと特徴量投入の確認**: `SACv454FeatureEngineer`で追加した特徴量が学習データCSVに反映されているか確認する（`scripts/generate_v454_data.py` を実行済みでも、実際にトレーニングで使われている `data_path` に入っているかを検証）。スケーラーのfitが全データに対して行われていないか（train/testリーク）も確認必須。
