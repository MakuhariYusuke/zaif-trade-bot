## 1. 短期間収益性問題の根本原因分析

### 問題点
- 時間足ベース学習が短期間（分足/秒足）での収益安定性を損なう
- Phase 3の厳格リスク管理が取引機会を過度に制限
- 特徴量がテクニカル指標中心で市場ノイズ耐性が不足

### 根本原因
- **タイムフレームギャップ**: 学習データが1時間足中心で、短期間のボラティリティパターンを捉えきれていない
- **特徴量の静的設計**: 140程度の特徴量が基本指標に留まり、短期間向け適応が不十分
- **学習効率の限界**: メモリ使用量500MB超、ステップ/秒17.46とスケーラビリティ不足

### 影響
- 短期間バックテストで収益が不安定
- リアルタイム適応が遅延
- 高頻度取引での機会損失

### 改善計画
- マルチタイムフレーム統合学習の実装
- 短期間向け特徴量拡張（RV: Realized Volatility, 高頻度指標）
- 学習インフラの最適化（GPU活用、並列処理）

- **特徴量未活用**: ニュースAPI（newsapi-python）導入済みだが、感情スコアが十分活用されていない

## 4. 技術的課題と解決策（深掘り）

### 環境依存問題
- **NumPy互換性**: 明示的バージョン固定（numpy>=1.24.4,<2.0）。影響ファイル: pyproject.toml, requirements.txt
- **V4FeatureExtractor未定義**: ztb/features/ のインポートパス整理。依存関係グラフ作成
- **解決順序**: Phase 1開始前に完了。テスト: numpy_test.py 作成

### スケーラビリティ問題
- **メモリ使用量**: TTLCache導入（cachetools使用）、バッファサイズ動的調整。目標: 500MB → 300MB
- **学習時間**: CPUマルチコア活用（joblib/multiprocessing）。並列化率: 4-8コア想定
- **実装**: ztb/training/optimization/ にCPU最適化モジュール追加

### データ品質問題
- **短期間ノイズ**: 統計的フィルタリング（Z-score, IQR）、異常値除去。ライブラリ: scipy.stats
- **特徴量多重共線性**: PCA/特徴量選択（sklearn.feature_selection）。相関係数0.8以上除去
- **合成データ生成**: SMOTEやGANベース検討（CPU負荷考慮）

### 学習効率問題
- **ステップ/秒向上**: バッチサイズ最適化、データ前処理並列化
- **モデル収束**: 早期停止（EarlyStopping）、学習率スケジューリング
- **検証**: tensorboard統合、学習曲線監視
