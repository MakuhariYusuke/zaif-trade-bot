# 推奨リポジトリ構造

このドキュメントは、保守性・可観測性・CI 運用を改善するための推奨ディレクトリ構成と移行手順を示します。変更は段階的に行い、テストとレビューを必ず挟んでください。

## 推奨トップレベル構成

- `ztb/` - 実装本体（既存コード）
- `tests/` - 単体テスト、統合テスト
- `docs/` - ドキュメント（このファイル含む）
- `tools/` - スクリプト（リポジトリ補助ツール）
- `artifacts/` - 生成物（モデル、チェックポイント、tensorboard、レポート等）
- `data/` - 原データ（読み取り専用でコミットしないことを推奨）
- `notebooks/` - ノートブック実験
- `configs/` - YAML/設定ファイル
- `venv*` / `.venv` - 仮想環境（`.gitignore` で除外）

## artifacts 配下のサブ構成（提案）

- `artifacts/models/` - 最終モデル（LFS 推奨）
- `artifacts/checkpoints/` - 学習チェックポイント
- `artifacts/tensorboard/` - TensorBoard 出力
- `artifacts/logs/` - 実行ログ
- `artifacts/reports/` - 静的レポート/分析結果

## 移行手順（安全な順序）

1. `tools/restructure.py` を実行して候補を確認する（dry-run）。
2. `.gitignore` を更新（既に更新済み）
3. 小さなフォルダ単位で `git mv` を行い、動作に影響が無いことをテスト
4. 大きなバイナリやモデルは Git LFS に移行、履歴からの除去は BFG などを検討
5. CI のパスやスクリプトで参照先が固定されていれば適宜更新

## 注意点

- 既存の import パスを変更すると多数の修正が必要になるため、まずは `artifacts/` へ静的生成物のみを移動し、コード側は `Path('checkpoints')` など相対参照を保つ方法を検討してください。
- モデルやチェックポイントを取り扱うスクリプトは安全に再実行できること（再現性）を確認してください。

## 次のステップ

- `tools/restructure.py` を実行して一覧とグルーピングを確認→必要なら移動案を作成します。移動はユーザー承認後に実行します。
