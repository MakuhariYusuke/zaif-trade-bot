# v453 戦略改善計画 (Hybrid Strategy)

## 1. 現状のステータス (2025-12-14)
- **実装完了**: `PositionManager` および `HeavyTradingEnv` へのハイブリッドフィルター（時間帯・ボラティリティ）の実装。
- **検証完了**: バックテストにより、指定した除外時間帯（14時, 17時, 01時）および危険ボラティリティ帯（0.005-0.015）での新規エントリーがブロックされることを確認。
- **パフォーマンス**:
    - トレード数: 激減（約18,000ステップで48回）。
    - PnL: プラス維持（+2.23%）。
    - 挙動: 「乱射」から「狙い撃ち」へのシフトに成功。

## 2. 課題と次なる調整フェーズ
フィルターが機能することは確認できたが、トレード数が極端に少なくなったことは「機会損失」の可能性も示唆している。また、なぜ特定の時間帯が苦手なのか、その根本原因はまだ完全には解明されていない。

### 2.1. フィルターの最適化 (Optimization)
- **閾値の緩和**: 現在のボラティリティフィルター（0.005-0.015）は広すぎる可能性がある。この範囲を狭めるか、除外ではなく「ロット縮小」などのソフトな制限に切り替える検討。
- **時間帯の再考**: 14時、17時がなぜ悪いのかをデータレベルで再調査し、ピンポイントで除外するか、あるいは逆張り戦略への切り替えを検討。

### 2.2. 深堀り調査 (Deep Dive)
「意外な発見」を求めて、以下の観点で調査を行う。

1.  **データ異常の可能性**:
    - 14時、17時に特有のデータ異常（スプレッド拡大、出来高急減、あるいは急増）がないか？
    - 取引所（Zaif/Coincheck等）のメンテナンス時間や、特定の大口botの稼働時間との相関。

2.  **レジーム判定の精度**:
    - 苦手な時間帯において、`RegimeClassifier` が頻繁に判定を切り替えていないか？（フリッカー現象）
    - 「Consolidation（レンジ）」と判定されているのに実際は「Trend」であるなどのミスマッチがないか。

3.  **報酬関数の隠れたバイアス**:
    - 特定の条件下で、報酬関数が過剰なペナルティを与えており、モデルが「何もしないこと（HOLD）」を学習しすぎていないか。

## 3. アクションプラン
1.  **データ構造解析**: 14時/17時の市場データを統計的に分析するスクリプトを作成・実行。
2.  **レジーム遷移分析**: バックテストログを用いて、時間帯ごとのレジーム遷移頻度を可視化。
3.  **パラメータチューニング**: フィルター条件を緩和したバックテストを実施し、トレード数と勝率のバランスを探る。
