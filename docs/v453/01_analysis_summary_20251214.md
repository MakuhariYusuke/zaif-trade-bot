# v453 Hybrid Strategy 分析レポート (2025-12-14)

## 1. 概要
本ドキュメントは、v453 Hybrid Strategy (v3 Config) のバックテスト検証、不具合修正、およびその後の詳細分析によって判明した事実と課題をまとめたものである。

## 2. 経緯と発見

### Phase 1: フィルタ不具合の修正
当初、v3設定（レジームフィルタ有効化）を行っても v2b（ベースライン）と結果が変わらない現象が発生していた。
- **原因**: `HeavyTradingEnv` から `PositionManager` へレジーム情報を渡す際、Enumオブジェクトそのものを渡していたため、設定ファイル（JSON）の文字列比較が機能していなかった。
- **修正**: `.value` を用いて文字列として渡すように修正。
- **結果**: フィルタが正しく機能し、`force_exit`（強制決済）が作動することで、アクション数が増加し、パフォーマンスが変化した。

### Phase 2: "儲かるバグ" の発見
修正後のベースライン（v3 Fixed）は、**Total Return 12.43%** という良好な成績を記録した。
詳細分析の結果、この利益の大部分は `CONSOLIDATION`（保ち合い）および `LOW_VOLATILITY_RANGING` レジームで生み出されていることが判明した。

しかし、さらなる調査で以下の矛盾が浮き彫りになった：
1.  **ThresholdManagerの設定**: `CONSOLIDATION` 等のレンジ相場では、ノイズ削減のために閾値を **10倍** (`adjusted_threshold *= 10.0`) に引き上げる設定になっていた（v451での最適化）。
2.  **実際の挙動**: にもかかわらず、v3 Fixed では活発に取引が行われていた。

**結論**:
`HeavyTradingEnv.step()` メソッド内でのレジーム取得ロジックに不備（または仕様の不一致）があり、`ThresholdManager` に正しいレジーム（`CONSOLIDATION`）が渡されず、`None`（不明）として処理されていた。
その結果、**閾値の引き上げ（10倍）が適用されず、基本閾値（1倍）で取引が行われていた**。
皮肉にも、この「バグ」によってモデルはレンジ相場でスキャルピングを行い、利益を積み上げていたのである。

### Phase 3: "正しいコード" によるパフォーマンス悪化
この仮説を裏付けるため、`HeavyTradingEnv.step()` を修正し、正しくレジームを渡すようにしたところ、以下の現象が発生した：
- `CONSOLIDATION` が正しく認識されるようになった。
- `ThresholdManager` が閾値を10倍に引き上げた。
- 取引頻度が激減し、レンジ相場での利益（約+6,000円分）が消滅した。
- 結果、Total Return は **6%台** に半減した。

### Phase 4: 課題レジームへの対策
一方で、損失を出していた `BREAKDOWN_SETUP` や `MODERATE_BEAR_TREND` に対して、`ThresholdManager` で「売り有利（閾値0.5倍）」の設定を追加する実験を行った。
- **結果**: これらのレジームは黒字化に成功した（-600円 → +900円）。
- **副作用**: しかし、同時に行った「環境の修正（Phase 3）」の影響で、全体の利益は回復しなかった。

## 3. 結論と考察

### 「スッキリしない」現状
技術的に「正しい実装（レジームを正しく認識し、設定通りの閾値を適用）」を行うと、パフォーマンスが下がるというジレンマにある。
これは、**過去の最適化（v451でのレンジ相場閾値10倍化）が、現在のモデル（v452/v453）には不適切である**ことを示唆している。現在のモデルは、レンジ相場でも十分に利益を出せる能力を持っている。

### 今後の指針
「バグ（レジームを渡さない）」に依存して利益を出すのは、エンジニアリングとして不健全である。
正しいアプローチは以下の通りである：

1.  **コードは正しく修正する**: `HeavyTradingEnv` は正しくレジームを渡すべきである。
2.  **設定を現実に合わせる**: `ThresholdManager` の設定を見直し、`CONSOLIDATION` 等での閾値倍率を **10.0 から 1.0（またはそれに近い値）に戻す**。
    - これにより、「バグ」で起きていた「低閾値での活発な取引」を、**仕様として**再現する。
3.  **良いとこ取りをする**:
    - レンジ相場：閾値を下げて利益を確保（Baselineの強み）。
    - 下落相場：売り閾値を下げて利益化、または除外（Phase 4の成果）。

## 4. 推奨アクションプラン
1.  `ThresholdManager` の `CONSOLIDATION`, `RANGING` に対する倍率を `1.0` に変更する。
2.  `HeavyTradingEnv` のレジーム取得ロジックは「正しい状態（修正版）」を維持する。
3.  `BREAKDOWN` 等への「売り有利」設定は維持する。

これにより、コードの整合性を保ちつつ、最大のパフォーマンス（Total Return 13%超）を目指すことができる。
