# v451 最適化バックテスト分析レポート

## 1. 概要
過去の構成ファイル（`v444`）から発見された「市場レジーム適応型閾値（Advanced Market Regime Adaptation）」メカニズムを `v451` に適用し、バックテストを実施しました。
目的は、上昇相場（Bull Market）において売り（Sell）に偏る「Permabear」バイアスを修正することでした。

## 2. 実施内容
- **閾値マネージャーの改修**: `ThresholdManager` にレジームごとの動的閾値調整ロジックを追加。
    - `BUY_BREAKOUT`（上昇ブレイクアウト）時: 買い閾値を 0.5倍（緩和）、売り閾値を 2.0倍（厳格化）。
    - `RANGING`（レンジ相場）時: 全閾値を 1.5倍（厳格化）。
- **設定ファイルの作成**: `sac_v451_optimized.json` を作成し、上記機能を有効化。
- **バックテスト実行**: `backtest_v451_optimized.py` を使用して検証。

## 3. 結果分析

### 3.1 行動変容（Behavioral Change）
バイアスの修正という点では、**部分的な成功**が見られました。

| レジーム | 以前の挙動 (v451 Base) | 最適化後の挙動 (v451 Optimized) | 評価 |
| :--- | :--- | :--- | :--- |
| **BUY_BREAKOUT** | **売り支配的** (Sell > 50%) | **均衡** (Buy 11.3% / Sell 11.3%) | 改善 (売り一辺倒ではなくなった) |
| **BUY_VOLUME_SURGE** | データなし | **買い 100%** | 成功 (強い買いシグナルに反応) |
| **RANGING** | - | Hold 87% / Trade 13% | 取引頻度が高すぎる可能性 |

### 3.2 財務パフォーマンス（Financial Performance）
**結果: 破産 (Bankruptcy)**
- **最終資産**: 1,972 JPY (開始時 1,000,000 JPY)
- **主な要因**:
    1.  **過剰な取引頻度**: レンジ相場（全体の84%を占める）において、約13%の頻度で取引を行っています。
    2.  **手数料負け**: 11,000ステップで約1,600回以上の取引を行ったと推測され、手数料（0.05%）だけで資産の大半を失いました。
    3.  **アルファの欠如**: 「買いやすく」したものの、その買いシグナルが利益につながっていません。

## 4. 考察と次なる一手
「無理やり買わせる」ロジックは機能しましたが、収益性を犠牲にしました。
現在の `v451` モデル自体が、現在の市場環境に対して有効なエッジを持っていない可能性があります。

### 推奨される対策
1.  **閾値の全体的な引き上げ**:
    - ベースとなる閾値を引き上げ、取引回数を劇的に減らす（「待つ」ことを増やす）。
    - レンジ相場でのペナルティ係数を `1.5` から `3.0` 程度まで引き上げる。
2.  **再学習の検討**:
    - 既存モデルのパラメータ調整だけでは限界があるため、最新のデータセットでモデルを再学習（Fine-tuning）させる。
3.  **手数料を考慮した報酬設計**:
    - 学習時の報酬関数で、取引コストへのペナルティを強化する。

## 結論
「Permabear」問題は、ロジックによる強制介入で緩和可能であることが実証されました。しかし、単にバイアスを解くだけでは収益化できず、むしろ損失を加速させました。次は「無駄なエントリーを削る」方向でのチューニングが必要です。
