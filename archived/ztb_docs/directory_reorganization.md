# ZTBディレクトリ構成ドキュメント

## 概要

このドキュメントは、Zaif Trade Bot (ZTB) プロジェクトのディレクトリ構成と、ルート直下から適切な場所へのファイル再配置について説明します。

## ディレクトリ構成の理論的根拠

### 1. `ztb/analysis/sac/`
- **目的**: SACアルゴリズム関連の分析結果を一元管理
- **理論的根拠**:
  - 分析結果は実験の文脈を保つため、アルゴリズム別に分類
  - SAC固有の問題（SELLアクション学習失敗）を特定しやすくする
  - 時系列での改善状況を追跡可能

### 2. `ztb/tests/training/`
- **目的**: トレーニング関連コンポーネントのテストを統合
- **理論的根拠**:
  - テストはコンポーネント別に整理することで保守性向上
  - CI/CDでの自動テスト実行を容易にする
  - テストカバレッジの測定と管理を効率化

### 3. `ztb/experiments/sac/`
- **目的**: SACアルゴリズムの実験スクリプトを管理
- **理論的根拠**:
  - 実験コードは本番コードと分離することで安定性確保
  - アルゴリズム別の整理で比較・評価を容易にする
  - バージョン管理による実験の追跡を可能にする

### 4. `ztb/docs/`
- **目的**: プロジェクトドキュメントの一元管理
- **理論的根拠**:
  - ドキュメントは開発者体験の重要な要素
  - 一箇所に集約することで検索性と保守性を向上
  - CHANGELOGによる変更履歴の追跡

## SACアクション分析の深掘り

### SELLアクション学習失敗の根本原因

分析結果から以下の問題が特定されました：

1. **v435.7a**: BUYアクションのみ（SELL: 0%）
   - 報酬関数がBUYを過剰に奨励
   - SELLのペナルティが過大

2. **v435.7b/c**: SELLアクションのみ（SELL: 100%）
   - 報酬関数のバランス崩れ
   - BUY/SELLのインセンティブ逆転

3. **バックテスト結果**: 収益0%
   - アクション分布の偏りが利益を生まない
   - 適切なエントリー/エグジットが発生しない

### SAC v436での改善策

`train_sac_v436.py`では以下の改善を実装：

1. **シグナルガイド統合**:
   - RSI, MACD, Bollinger Bandsなどの古典的シグナル
   - シグナル強度に基づく報酬調整
   - SELLシグナル検知の強化

2. **連続アクションスペース**:
   - SACアルゴリズムの要求に適合
   - より細かいポジション制御が可能

3. **報酬関数の改善**:
   - シグナルベースのボーナス/ペナルティ
   - アクション分布のバランス化

## テストスクリプトの機能分析

### トレーナーテストの重要性

各テストスクリプトは以下を検証：

1. **PPOトレーナーテスト**:
   - 離散アクション対応の安定性
   - 設定ファイルの正しい読み込み
   - トレーニング最適化の初期化

2. **自己教師ありトレーナーテスト**:
   - 教師なし学習の設定妥当性
   - モデルアーキテクチャの正しさ
   - データ処理パイプラインの安定性

3. **統合トレーナーテスト**:
   - エラーハンドリングの堅牢性
   - ログ構造の適切さ
   - 例外処理の階層構造

## 構成管理のベストプラクティス

### ファイル配置の原則

1. **機能別分類**: 分析→analysis/, テスト→tests/, 実験→experiments/
2. **アルゴリズム別整理**: SAC関連ファイルはsac/サブディレクトリ
3. **ドキュメント一元化**: docs/ディレクトリでの集約
4. **設定ファイルの保持**: pyproject.toml, mypy.iniなどはルートに残す

### 保守性の向上

- **検索性の向上**: 関連ファイルがまとまって見つかる
- **変更影響の局所化**: 機能別の分離により影響範囲を限定
- **CI/CDの効率化**: テストと実験の自動実行を容易に
- **ドキュメントの充実**: 変更履歴と使用方法の明確化
